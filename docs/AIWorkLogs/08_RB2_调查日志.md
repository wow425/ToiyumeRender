## 3. 实测 vs 推断的边界（明确划线）

### 3.1 属于 [实测] 的（可直接复现验证）

1. **DrawScene 的 104 行 body 每一行**——逐行 awk 打印过，§3.1 步骤 5-14 全部可直接对照。

4. **ObjectRenderingVariant 的 8 个字段名、宽度、注释**——源码 `:348-363` 可见；但**位序（哪个字段在 bit 0-3）是 [推断]**。

### 3.2 属于 [推断] 的（本文明确标注，未闭合）

1. **位域的物理位序**（`ObjectRenderingVariant` 的 bit 0-3 是不是 renderpass）——C++ 标准不保证，MSVC 行为是「从低位起」，但本文未编译验证。→ §8 U1。
2. **`ShaderMeshInstance.flags` 高 8 位 stencil 的 shader 侧消费者**——只看到写入方，没读任何 PS 的读取点。→ §8 U3。
3. **`sort_bits` 的多材质累积是否真的会导致排序退化**——逻辑推理，未构造实验。
4. **`DrawWireframeOverlay` 嵌套调用 DrawScene 是否真的安全**（thread_local queue 被内层 init 清空的风险）——推导出「实际不嵌套」，但未穷举所有调用点。→ §8 U2。
5. **本项目 Scene 侧的资源归属**（§5.1 表部分行）——未读本项目 `05_Scene`，属 RB3 范围。
6. **`PREPASS_DEPTHONLY` 不绑颜色 RT** 这一点是 [实测]（`:2139-2143` 明确 `rt_count=0`），但「调用点是否真的没绑颜色 RT」未逐个核对 `wiRenderPath3D.cpp:1181-1247` → 保留半推断状态。

```bash
awk 'NR>=7179 && NR<=7282 {printf "%d: %s\n", NR, $0}' file.cpp
```
**代价**：每段读之前都要想清楚区间，不能「先看再定位」。**收益**：一次读到的内容可直接进报告，不用二次回源。

### 坑 2｜`grep -c "Barrier"` 是本文最值钱的一条命令
```
awk 'NR>=7179 && NR<=7282' wiRenderer.cpp | grep -c "Barrier"  →  0
```
「0」这个结果直接定性了 DrawScene 的边界（§1.3、§5.2）。**教训**：验证「某函数不做什么」时，`grep -c` 的 0 比读 100 行更有说服力，且成本极低。后续块（RB5 同步）应大量使用这个手法。

### 坑 3｜WE 的 `DrawScene` 只有 104 行，真正的工作在 `RenderMeshes` 里
如果只读 7179-7283（任务里给的「已知」区间），会得出「DrawScene 就是遍历+排序+调一个函数」的错误结论，**完全答不出「一条 draw 到 GPU 命令」**。必须向下追 `RenderMeshes`（353 行）+ `batch_flush` lambda（227 行）。
**这是本文与 01B 的最大差异点**（01B 只读了 7179-7283）。

### 坑 4｜`RENDERPASS` 的 106 处出现 ≠ 106 个分支
任务说「已知 67 处」，我 `grep -c` 得到 106。差异原因：`grep` 计数包含枚举定义、注释、函数参数传递。**不能拿出现次数当分支数**。实际需要判断语义的分支点约 20 处（已在 §3.1 步骤 16/22/23 与 §5.4 覆盖）。

### 坑 5｜`edit` 工具的 `old_string` 必须逐字符精确（含行尾）
批量给 9 个表格加标注时，用循环 `await tools.edit(...)` 一次失败就整个程序抛异常，已成功的编辑也难判断。改为：
```ts
for (const [tag, oldS, newS] of edits) {
  try { await tools.edit({...}); results.push(tag+": OK"); }
  catch (e) { results.push(tag+": FAIL "+e.message.slice(0,90)); }
}
```
**教训**：批量编辑必须 per-item try/catch + 汇总，否则一次失败会掩盖已成功项的状态。本次就有 1 项（§6 表头含 4 个空格差异）靠这个手法定位到并单独重试成功。

### 坑 6｜Windows 路径 + 中文目录：bash 里必须加引号且用正斜杠
```bash
WE="/d/CS-Self-Study/.../工程实现参考/WickedEngine-master/WickedEngine"   # 正确
```
用反斜杠或裸路径会失败。另外 `cd "$WE" &&` 比绝对路径调用更稳（避免 grep 输出里带完整路径导致行号列对不齐）。

### 坑 7｜报告的「标注率 100%」不能只靠正文句子标注
初稿正文句子都有 [实测]/[推断]，但 **9 个表格的单元格里没有**——形式上不满足 G2。补救方式：每个表格前加一个 `> **标注口径**：…` 引用块，声明该表哪些列是实测、哪些是推断。这样既满足 100% 覆盖，又不让每个单元格变得臃肿。**建议后续 RB 块都采用这个模式**。
