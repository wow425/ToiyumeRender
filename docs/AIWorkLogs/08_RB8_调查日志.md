## 6. 关键发现（Top 8，一句话一条）

1. **WE 的缓存是「弱引用表 + 强引用句柄」分工**：表里存 `weak_ptr`（`wiResourceManager.cpp:236`），调用方持有的 `Resource` 里是 `shared_ptr<void> internal_state`（`wiResourceManager.h:20-50`）→ 无人持有时条目过期并被 `UpdateStreamingResources` 顺手 `erase`（`wiResourceManager.cpp:1264-1288`）[实测]。
2. **WE 的失效键 = 文件名 + 磁盘 mtime**，且 `timestamp == 0` 代表强制过期（`wiResourceManager.cpp:83`、`SetOutdated()` 在 `:213-221`）；容器化资源另存 `container_filename/container_filesize/container_fileoffset`（`:80-82`）→ 支持从大包中按偏移部分读（`:1109`、`:1351-1364`）[实测]。
3. **WE 把 MIP 生成与 BC 压缩推迟到渲染层帧首执行**：资产层只 `push_back` 到两个队列（`wiResourceManager.cpp:942/981`），渲染层在 `wiRenderPath3D.cpp:861` 帧首于**主线程同一 command list** 上清空（`wiRenderer.cpp:3603-3616`）→ 这是「资产层登记、渲染层执行」的反向依赖（`wiResourceManager.cpp:2` 直接 `#include "wiRenderer.h"`）[实测]。
4. **WE 有真正的后台流送**：DDS 解析时按 mip 记录 `StreamingSubresourceData`（`wiResourceManager.cpp:562-587`），运行时按 GPU 显存占用率（`memory_percent > streaming_threshold=0.8`，`:1306-1308`）决定升/降 mip，并在**低优先级 jobsystem 线程**里 `CreateTexture`（`:1295-1296`、`:1385`），主线程只在交换表时持锁（`:1194-1202`、`:1206-1207` try_lock）[实测]。
5. **GPU→CPU 反馈靠一张 R32_UINT UAV + 回读缓冲**：shader 用 `WaveActiveBitOr` 聚合 mip 需求后 `InterlockedOr`（`Shaders/globals.hlsli:599-624`），CPU 侧解码成 `StreamingRequestResolution`（`wiScene.cpp:4391-4400`）[实测]。
6. **WE 只读 `.wiscene`，不具备 FBX/glTF 运行时导入**：全仓 `assimp` 零命中 [实测]；模型链是 `LoadModel2 → wi::Archive → scene.Serialize → scene.Update(0)`（`wiScene.cpp:9201-9275`）。
7. **本项目贴图 100% 未经 BC 压缩**：`ModelConvert.cpp:367-376` 五个槽位全部只传 sRGB/alpha，而 `TextureOptions()` 本身不置 `kDefaultBC`（`TextureConvert.h:23-26`）→ 磁盘 DDS 恒为 `R8G8B8A8`（`TextureConvert.cpp:155-167`）；唯一传 `kDefaultBC | kQualityBC` 的是 HDR 环境光路径（`EnvironmentLightingManager.cpp:173`）[实测]。
8. **本项目资产链完全同步**：`TextureManager.cpp:97` 在 `FindOrLoadTexture` 里 `ReadFileSync` 全量读 + `:132-133` 同步解码，未命中时主线程还会自旋等锁（`:152-156`）；`FileUtility.cpp:120-124` 的 `ReadFileAsync` 全仓无调用点；`ModelLoader.cpp:359-360` 的注释「贴图通过独立异步 I/O 线程池加载」与实现相反 [实测]。
