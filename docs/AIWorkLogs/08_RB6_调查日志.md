## 6. 踩坑记录（对后续研究者有用）

### 坑 1：run_code 的模板字符串里不能直接写反引号

- **现象**：第一次写 §2 时报 `Expected a semicolon`，原因是 Markdown 反引号与 TS 模板字符串冲突。
- **解决**：用占位符（成对的特殊符号）写正文，最后批量替换。同理 LaTeX 的反斜杠、代码块的三反引号也用占位符。
- **代价**：第一次尝试浪费 1 次工具调用。
- **教训**：**写大段 Markdown 时，先用占位符，最后统一替换**，比逐处转义可靠。

### 坑 2：占位符替换不彻底会留下「半替换」状态

- **现象**：第一次替换只替换了开符号，忘了闭符号，导致文档里出现 1715 个孤立的闭符号（形如 `ShaderMaterialCLOSE）。
- **解决**：第二次替换补上，并写了统计脚本核对闭符号计数 = 0。
- **教训**：占位符必须**成对**设计，替换后要**计数校验**。

### 坑 3：「[实测]/[推断] 标注率 100%」不是靠人眼保证

- **现象**：正文写完后，脚本扫描发现 106 行含 `file:line` 但同行没有标注。
- **解决**：写脚本按行类型（表格行 / 摘要条目 / 引用块 / 普通段落）分别插入标注，插入后再扫一遍确认 0 条遗漏。
- **教训**：**G2 这类闸门必须脚本化**，否则 1600 行文档靠肉眼一定会漏。

### 坑 4：初稿里的定量表述容易「凭印象写」

- **现象**：初稿写了「20+ 文件 include」「21.7% 条件编译」「20+ 组宏」「90% 是 TiledLighting」四处估计值。
- **解决**：全部用 `grep -c` / `wc -l` 实测后改成精确值（13/8、21.9%、33、74%），并在正文附可复现命令。
- **教训**：**任何「N+」「X%」都要么实测要么标 [推断]**。本块的 4 处已全部实测化。

### 坑 5：WE 的字段「复用」比想象中多，容易漏

- **现象**：读到 `wiScene_Components.cpp:334-339` 才发现 `INTERIORMAPPING` 把 `subsurfaceScattering` 字段挪用存 interior scale。
- **影响**：若不读这段，会误以为 SSS 字段是"纯 SSS"，进而误判「本项目可以直接砍掉 SSS 字段」——实际上砍掉会连带砍掉 interior mapping 能力。
- **教训**：**先读 WriteShaderMaterial 全文，再读结构声明**。结构声明看不出的复用，只在写入函数里暴露。

### 坑 6：本项目已有真实 bug，研究时不要"假设现状正确"

- **现象**：
  - DefaultPS.hlsl:25-29 与 GBufferPS.hlsl:30-36 对同一个 b1 槽声明了**不同布局**的 GlobalConstants；
  - MaterialConstantData（48B）被 memcpy 进 256B 槽，剩余 208B 未初始化；
  - flags 字段在 HLSL 里声明但**完全没用**；
  - MaterialFlags.h 是 **0 字节空文件**；
  - F0 在 LightingPS 与 DeferredCommon 被**算两次且公式不同**。
- **教训**：研究 WE 时若同时对照本项目，要**先独立核实本项目现状**，不能把「本项目这么写」当成「这么写是对的」。这 5 条恰好构成本块 §7.1.1 最有价值的产出。

### 坑 7：wc -l 对空文件返回 0，但 cat 不报错

- **现象**：MaterialFlags.h 用 `cat -n` 读时无输出，一开始以为是路径错。
- **解决**：`wc -c` 确认 = 0 字节，`ls -la` 确认文件存在（0 字节）。
- **教训**：**"读了但没输出"要区分「文件为空」与「路径错」**。

## 8. 移交说明（给 Lead）

### 8.1 本块最该被下游直接消费的 5 条

1. **ShaderMaterial 逐字段表**（报告 §2.1）：16 个字段 + 15 纹理槽的偏移/打包/语义，可直接照表实现。
2. **ApplyLighting 15 行**（§4.3，lightingHF.hlsli:41-55）：能量守恒的完整公式链，WP7 必须按这个结构写。
3. **metal-rough 的 5 行核心**（§2.4.2，surfaceHF.hlsli:236-240）：`albedo *= (1-max(refl,metal))` + `f0 = lerp(refl, baseColor, metal)` —— 本项目当前缺前半句。
4. **interop 头范式**（§6 J3，ShaderInterop.h:4-53）：30 行宏定义，是消灭「C++ 改字段忘改 HLSL」的唯一低成本手段，且本项目已因此出 bug。
5. **§7.1.2 草案 A**：可直接执行的 7 步改动清单（约 80 行），落在 WP3。

### 8.2 需要注意的交叉校验点

- **C1（RB3 x RB6）**：RB3 的场景材质字段必须能与 §2.1 的 16 个字段一一对应。本块已确认 **WE 的 MaterialComponent 有 19 个 FLAGS 位（wiScene_Components.h:118-137）但只映射到 12 个 shader 选项位（ShaderInterop_Renderer.h:100-115）** —— 差额的 7 位（DIRTY/OUTLINE/PREFER_UNCOMPRESSED/... 与 4 个 _DEPRECATED）是 CPU 侧语义，不传 GPU。若 RB3 把 OUTLINE 当材质字段传给 GPU，就是契约破裂。
- **与 RB7 的边界**：本块的 §4.6 只给 tonemap 的数学形式与链顺序（bloom 必须在 tonemap 前），**不涉及**后处理的 RT 分配/ping-pong，那是 RB7。

### 8.3 若时间允许，下一步最该补的 3 件事

1. **§8 U5（π 归一化）**：这是本块唯一可能造成「IBL 亮度差 3.14 倍」的未确认项，只需一次构建运行即可闭合。建议交给 WP7 实施时顺手验证。
