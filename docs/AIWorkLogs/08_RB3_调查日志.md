## 3. 结论摘要

1. **WE 的 Scene 是「CPU 组件 + GPU 资源」二合一**：`wiScene.h:118` 的 `ShaderScene shaderscene`、:126-167 的三件套 buffer、:173-294 的 SurfelGI/DDGI/Ocean/Impostor 子结构，全部直接挂在 Scene 上；`MeshComponent`（`wiScene_Components.h:727-792`）同一 struct 里既有 `aabb`/CPU 顶点，又有 `generalBuffer`(:728)/`streamoutBuffer`(:729)/`PageAllocator::Allocation`(:730)/裸 `int` 描述符索引(:737-738)/`BLASes`(:770)。**这是分层失败，不是设计选择**——WE 用 `wi::renderer` 自由函数弥补，使得渲染器可以随意读 Scene 成员。
2. **ECS 的 swap-and-pop 会打乱组件索引**（`wiECS.h:324-344`），因此 WE 必须每帧重算「组件索引 ↔ GPU 数组槽位」映射（`wiScene.cpp:266-272` 的 `geometryAllocator.fetch_add`）。本项目对象数 ≤ 数千，可直接让**槽位稳定**，省掉整段逻辑。
3. **suballocation 是本轮唯一补全的第一轮空白**：`wiScene_Components.cpp:1217-1219` 注释明说目的是「avoid rebinding the index buffer for every mesh and can work with purely offsets」；:1220 `SuballocateGPUBuffer(bd.size)` → 成功则 :1223 `CreateBuffer2(&bd, init_callback, &generalBuffer, &suballoc.alias, suballoc.allocation.byte_offset)`，失败则 :1232 退化为独立 buffer。**判定为「可选（本期不取）」**，理由见文档 §6#2（绘制侧三重偏移 + 需要 ALIASING_BUFFER + 教学不直观）。
4. **三件套双缓冲是「一次上传、shader 靠索引取」的落点**，判定 **必需**；但归属应从 Scene 移到 `RenderFeatures`（文档 §6#4 + §6#7）。
5. **Visibility 归渲染侧持有是 WE 最正确的一处分层**（`wiRenderer.h:124-165` 的 `visibleObjects` 在 `wi::renderer` 而非 Scene 里），本项目应照搬这个**归属**（文档 §6#8）。
6. **本轮新增产出**：文档 §2.1 给出组件字段的**逐字段四桶归属**（C=CPU纯数据 / G=GPU资源 / D=描述符索引 / R=运行时状态），此前第一轮 01C 没有这个分类。
