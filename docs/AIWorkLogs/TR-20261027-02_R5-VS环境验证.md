### 5.1 改动 1：`DeployRuntimeDlls.cmake` 按配置选 DLL 变体

| 新增/改动 | 签名/片段 | 位置 | 调用者 |


## 6. 资源生命周期（本轮不涉及 GPU 资源）

本轮只涉及构建产物的 DLL 部署，不进 GPU。**唯一的「资源生命周期」问题是 POST_BUILD 的触发条件**：

| 触发条件 | 是否执行 POST_BUILD | 后果 |
|---|---|---|
| `.exe` 重新链接 | ✅ 执行 | 新 DLL 覆盖 |
| 只改 `DeployRuntimeDlls.cmake` | ❌ 不执行 | 旧 DLL 留在原地，**看起来「改了没生效」** |
| 手动删产物 DLL | ❌ 不执行（除非同时重链接） | 产物缺 DLL，运行时 `0xc0000135` |

**验证修复时必须 touch 源文件强制重链接，或手动删掉产物 DLL 后重链接。** 本轮用的是 touch `Demos/RendererDemoApp/RendererDemoApp.cpp`。

## 8. 方案取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A：用 `$<CONFIG>` 生成器表达式** | 单配置/多配置生成器统一正确；无分支 | 需要重新 configure | **采纳** |
| B：在 `CMakeLists.txt` 里用 `if(CMAKE_CONFIGURATION_TYPES)` 分两套逻辑 | 显式 | 两套逻辑容易漂移；单配置下还要写另一套 | 否：复杂度翻倍 |
| C：不用 CMake 部署，改由 `build.bat` / VS 的「自定义生成步骤」拷 DLL | 可控 | 两条构建入口都要各写一遍，必然漂移 | 否：单点真源原则 |
| **D：在 VS 里只验证 Debug，不管 Release** | 省事 | Release 是必须验证的分层（AGENTS.md 第 1 层要求 Debug+Release 同跑） | 否：违反验收分层 |

## 12. 主动回忆（6 题 + 答案）

| # | 问题 | 答案 |
|---|---|---|
| Q1 | 为什么 `if(CMAKE_BUILD_TYPE STREQUAL "Debug")` 在 VS 生成器下会选错 DLL？ | 因为 VS 生成器是**多配置**生成器，`CMAKE_BUILD_TYPE` 只在配置期求值一次，与 `--config` 无关。本项目 configure 时写的 `Debug`，所以判断恒真，Release 也拿 `debug/bin`。 |
| Q2 | 正确的多配置写法是什么？为什么它对 Ninja 也正确？ | `$<IF:$<CONFIG:Debug>,debug/bin,bin>`。`$<CONFIG>` 在单配置生成器下取值就是 `CMAKE_BUILD_TYPE`，在多配置下取当前构建的配置，所以两边都对。 |
| Q3 | `cmake -G "Visual Studio 17 2022"` 报「找不到编译器」，最可能的原因是什么？ | 环境里同时存在大小写两套 proxy 变量（`NO_PROXY` 与 `no_proxy`），MSBuild 的 `ProcessStartInfo.EnvironmentVariables` 抛重复键异常，被 CMake 误报成找不到编译器。真因藏在 `CMakeFiles/CMakeConfigureLog.yaml` 的 `MSB6001` 里。 |
| Q4 | 为什么在 bash 里 `unset no_proxy` 不能修好 MSBuild？ | bash 只改自己进程的环境；`cmake --build` 派生的 MSBuild 继承的是调用 bash 的父进程（DSH 宿主）的环境。必须在同一个 PowerShell 进程里清，或用 `[System.Environment]::SetEnvironmentVariable($n,$null,'Process')`。 |
| Q5 | 改了 `DeployRuntimeDlls.cmake` 但产物 DLL 没变，为什么？ | `add_custom_command(TARGET ... POST_BUILD)` 只在 target 真的重新链接时执行。只改 cmake 脚本、不触发重链接 → POST_BUILD 不跑 → 旧 DLL 留着。要 touch 一个源文件强制重链接。 |
| Q6 | 怎么证明 VS 构建树与 Ninja 构建树是等价的？ | 拿**渲染输出的 md5** 比，不是拿「能编译、能跑」比。本轮三棵树两两比：DXR `1bea89b2…`、Deferred `16c8aeec…`、切换链路 `ec5736ba…`/`16c8aeec…` 全部逐字节相同。 |

## 附：本轮踩到的环境坑（6 条，已同步到 `R_执行表.md` §8 第 46–51 条）

1. `CMAKE_BUILD_TYPE` 在多配置生成器下是「配置期的固定单值」，不是「当前构建的配置」
2. `cmake -G VS2022` 报「找不到编译器」先怀疑 proxy 变量重复键
3. `unset` 在 bash 里对 MSBuild 无效（继承的是调用方父进程环境）
4. `POST_BUILD` 只在重链接时执行
5. 「构建等价性」要拿渲染输出 md5 比
6. `--config` 与 `CMAKE_BUILD_TYPE` 是两套东西，不要指望联动
