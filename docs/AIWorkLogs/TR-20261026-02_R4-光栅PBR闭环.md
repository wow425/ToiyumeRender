## 3. 目标、范围与非目标

**目标**：让「HDR 场景色 → 曝光 → 色调映射 → 显示色彩空间」成为一条对**所有写 SceneColor 的 Pass** 都成立的链；让 IBL 状态机与 mip 映射与资产事实一致；让 MASK 材质镂空。

**范围**：LightingPS / SkyboxPS / GBufferPS 三个 Shader，RenderParams–LightData–cbuffer 契约，EnvironmentLightingManager 状态机，DeferredRenderer 参数衔接，Demo 验收脚本。

**非目标**（明确不做）：

- 不做 AlphaBlend（BLEND）透明混合
- 不做 Forward 的光照接通（R3 遗留，另立工作包）
- 不做 Shadow / SSAO / TAA（DeferredRenderer 里仍是空壳）
- 不引入 RenderGraph / HDR SwapChain

## 4. 设计概览

### 4.1 模块职责

- `RenderParams`：**唯一 CPU 真源**，只放用户可调量
- `Scene::LightingSystem`：负责 PackParams（唯一折叠点）+ 承载**派生**的 IBL mip 上界
- `ColorPipeline.hlsli`：显示编码链的唯一实现，被多个 Pass 共享
- `EnvironmentLightingManager`：烘焙产物与状态机；Skybox 显式接收参数，不读全局

### 4.2 调用链

```
RendererDemoApp::Update -> m_Params (CPU 真源)
  -> DeferredRenderer::Render -> RenderFrameDesc.Params
     -> Update: BakeEnvironmentTextures -> SetPrefilterMaxMip -> ApplyParams
     -> LightingPass: cbuffer Light -> EncodeDisplayColor
     -> SkyboxPass: SkyboxCameraCB -> EncodeDisplayColor（同一函数）
```

### 4.3 数据流

CPU RenderParams → PackParams() → LightData(112B) → WriteBuffer → StructuredBuffer → CBV → cbuffer Light。

### 4.4 关键设计决策

见 R4 文档 §5。核心三条：色彩链必须共用一份实现；mip 上界属资产事实而非用户参数；AlphaRef 必须用 `f16tof32` 解码。

## 5. 关键实现讲解

### 5.1 关键函数

- `LinearToSRGB`（ColorPipeline.hlsli）：IEC 61966-2-1 分段函数，不用 pow 近似
- `EncodeDisplayColor`：三步合一，Lighting 与 Skybox 共用
- `PackParams`（LightingSystem.cpp）：CPU→GPU 镜像唯一折叠点，新增 DisplayParams
- `SetPrefilterMaxMip`：值变化时清 `s_bHasApplied`，强制下一次 ApplyParams 重传
- `DecodeAlphaRef`（GBufferPS.hlsl）：`f16tof32((flags >> 16) & 0xFFFF)`

### 5.2 边界条件

- `frame.Params == nullptr`（旧 Demo）：Skybox 退回 `GetAppliedParams()`，与 Lighting 一致
- `mipCount <= 1`：mip 上界钳到 1.0，避免负 mip 或退化
- `HDRTexture` 无效：烘焙早退，Skybox/IBL 不写入，日志已有明确错误（R0.2 遗留）
- `exposure <= 0`：`max(exposure, 0.0)` 保证非负

## 6. DX12 专项说明

### 6.1 资源生命周期

本次未新增 GPU 资源。PrefilterCube 仍为 5 mip 的 R16G16B16A16_FLOAT cubemap。描述符计数全程恒定（RTV 13 / SRV 65 / pool 8）。

### 6.2 Descriptor / Root Signature / PSO

- PSO **未改**；AlphaTest 通过 Shader 内 `clip` 实现，未引入新 PSO 变体（代价：始终执行一次分支，可忽略）

### 6.3 Resource State / Barrier / Fence

未改动。烘焙仍在 `ComputeContext::Finish(true)` 内完成，之后统一 Transition 到 PIXEL_SHADER_RESOURCE。

### 6.4 Shader 与 CPU 数据布局一致性

三处契约已同步并加 `static_assert(sizeof(LightData) == 112)`：
- RenderParams / LightData / `cbuffer Light`

## 9. 代码审查结果

以 Reviewer 视角复查 diff，发现并处理以下问题：

1. **顺序缺陷（构建前发现）**：原计划先 ApplyParams 再回填 mip 上界，会导致新值延迟一帧生效。已改为烘焙→回填→ApplyParams。
2. **真源分叉（设计期发现）**：`PrefilterMaxMip` 一度加进 `RenderParams`，形成「用户真源 vs 资产事实」两份真相。已移出，改由 LightingSystem 持有派生值。
3. **常量契约**：`static_assert(sizeof(LightData) == 112)` 保证三处同步；`kLightShaderParamsBytes` 同步。
4. **旧 Demo 兼容**：`frame.Params == nullptr` 时 Skybox 退回已生效参数，不改变旧 Demo 行为。
5. **临时改动已复原**：AlphaTest A/B 时为取证临时注释掉 `clip`，已恢复并重新构建、重跑，最终证据与交付源码一致。

## 11. 回滚与排错指引

- **天空突然变暗/变亮**：检查 `SkyboxCameraCB.DisplayParams` 与 `cbuffer CameraCB` 是否错位（offset 128）
- **模型偏灰**：确认 `EnableSRGBEncode` 为 true，且 SceneColor 是 `*_UNORM`（非 `*_SRGB`）——若将来改成 `_SRGB`，必须同时关掉 Shader 内编码，否则二次编码
- **高光粗糙度响应异常**：看启动日志 `[R4] IBL 烘焙完成` 的 PrefilterMips 是否为 5
- **MASK 材质出现实心黑块**：确认 PSO 用的是 `GBufferPS`，且 `flags` bit6 已置位
- 回滚：删除 `ColorPipeline.hlsli` 并把两个 Pass 的 `EncodeDisplayColor` 调用换回各自的旧实现（Lighting 保留本地 ACES，Skybox 直接 return）。
