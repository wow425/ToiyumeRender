### 抽查 3 —— 本项目 `Engine/02_RHI/Resource/ColorBuffer.h:108-116`（可行性前提类证据）

- **报告里的表述（§7.1 约束 C3）**：每个 `ColorBuffer` 默认就带 UAV —— `CombineResourceFlags()` 在 `m_FragmentCount==1` 时无条件或上 `ALLOW_UNORDERED_ACCESS`。
- **核对命令**：
  ```bash
  sed -n '106,118p' Engine/02_RHI/Resource/ColorBuffer.h
  ```
- **实际输出**：
  ```cpp
  	// 不开MSAA则Flags为渲染+UAV
  	D3D12_RESOURCE_FLAGS CombineResourceFlags(void) const
  	{
  		D3D12_RESOURCE_FLAGS Flags = D3D12_RESOURCE_FLAG_NONE;
  		// 不开MSAA则支持UAV
  		if (Flags == D3D12_RESOURCE_FLAG_NONE && m_FragmentCount == 1)
  			Flags |= D3D12_RESOURCE_FLAG_ALLOW_UNORDERED_ACCESS; // 按位或，有1为1

  		return D3D12_RESOURCE_FLAG_ALLOW_RENDER_TARGET | Flags; // 按位或，混合打包
  	}
  ```
- **命中结果**：✅ **命中**，且发现一处**措辞需要精确化**：代码里的条件是 `Flags == D3D12_RESOURCE_FLAG_NONE && m_FragmentCount == 1` —— 左侧的 `Flags` 是**刚刚被初始化为 NONE 的局部变量**，所以 `Flags == D3D12_RESOURCE_FLAG_NONE` **恒为真**（这是一个无意义的自比较，等价于只判断 `m_FragmentCount == 1`）。
- **修正动作**：已在交付文档 §7.1-C3 与 §9 里保留"无条件（在 `m_FragmentCount==1` 时）"的表述，因为它与代码的**实际行为**一致；但结论叙述改成"条件恒真"，避免读者误以为这里有个额外的开关。**这条修正已在本文档记录，未改动源码**。

## 6. 踩坑

1. **大文件必须 grep 定位**：`wiRenderer.cpp` 19,686 行。本次全程只用 `grep -n` + `sed -n 'a,bp'` 取区间，最大单次区间 100 行左右。**没有一次通读**。
2. **任务清单与仓库实测冲突**：任务要求读 `shaders/fxaaPS.hlsl`，但该文件**不存在**（实际是 `fxaaCS.hlsl` + `fxaa.hlsli`）。教训：任务给的路径也要先 `ls`/`grep` 验证，冲突时以实测为准并记入 §8。
3. **`ColorGrading` / `EyeAdaption` 不是函数名**：在 `wiRenderer.h/.cpp` 里 grep 这两个词只命中 `eyeadaptionkey`（一个 float 成员）与 `texture_colorgradinglut`（Tonemap 的形参）。它们是 **tonemap 的输入通道**，没有独立函数——这一点直接改变了 §1 的"职责边界"写法。
4. **路径含中文与空格时的命令拼装**：在 `run_code` 里拼 bash 字符串时，反斜杠路径极易被吃掉。稳定写法是**正斜杠 + 整条路径双引号**，例如
   `"D:/CS-Self-Study/Computer_Graphics/DX12/工程实现参考/WickedEngine-master/WickedEngine/wiRenderer.h"`。
5. **`tools.write` 的前置条件**：必须先 `tools.read` 目标文件（用 bash `cat` 读不算数），否则报 "file has not been read"。因此对空骨架文件也是先 `read` 再 `edit`。
6. **`edit` 的 `old_string` 必须唯一且仍然存在**：本次 §7.3 的插入一开始锚定 ``F7`` 失败（该占位符已被 §7 正文替换掉），改为锚定 ``F8`` 才成功。教训：**每写完一节立即写回文件**，但插入新内容时要锚定**还没被消耗**的占位符。
7. **占位符分批填写**：骨架里预留了 ``F4``…``F9``，每完成一节立刻 `edit` 回填。**这是本次没有中途失败的关键**——最后一次回填发生在会话末段，若攒到最后一次性写，中间任何一次上下文耗尽都会导致空骨架交付。
8. **推断必须显式标注**：例如"PS 分支的 in-place 更危险"、"ClearUAV 是防御性写法"这类看图说话的结论，全部标 [推断] 并转入 §8，避免污染 [实测] 证据链。
