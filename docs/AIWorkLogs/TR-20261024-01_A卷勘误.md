## 5. 关键实现讲解

### 5.1 关键结论：π 归一化位置（最严重的一条）

卷内旧文写「漫反射 `/PI` 在 `BRDF_GetDiffuse:189`，π 归一化落在 BRDF 函数内」。**源码相反**：

```hlsl
// brdf.hlsli:189-203  —— 没有 /PI
half3 BRDF_GetDiffuse(in Surface surface, in SurfaceToLight surface_to_light)
{
	half3 diffuse = (1 - lerp(surface_to_light.F, 0, saturate(surface.sss.a)));
	return diffuse * surface_to_light.NdotL;
}

// lightingHF.hlsli:49  —— /PI 在这里
half3 diffuse = lighting.direct.diffuse / PI + lighting.indirect.diffuse * ...;
```

**为什么这条最严重**：它正是 `09_升级实施建议` §8.1 阻塞项 **U-1**（"π 归一化落在哪一侧"）的答案。旧结论会让施工者在抄 `BRDF_GetDiffuse` 时**又除一次 π**，漫反射暗 3.14 倍，或反向亮 3.14 倍——且因为只差一个常数，调参时极易被"补偿掉"而不被察觉。

### 5.2 行数缺陷的根因证明（可证伪）

不是"大概"多 1，而是**恰好等于 真实值 + 文件数**：

| 类别 | 真实 | 文件数 | 和 | `_data` 旧值 |
|---|---|---|---|---|
| hlsl | 22,660 | 305 | 22,965 | 22,965 ✓ |
| hlsli | 18,984 | 40 | 19,024 | 19,024 ✓ |
| h | 4,462 | 18 | 4,480 | 4,480 ✓ |

三个类别**同时**精确吻合，排除巧合。结论：脚本对每文件 +1。

### 5.3 边界条件与错误处理

- **无尾换行文件**（9 个）：`wc -l` 少 1、`awk` 正确 → 必须用 `awk`。
- **同名文件跨树**（如 `TextureConvert.cpp` 在 Tooiyume 与 WE 各有一份）：仅靠 basename 会解析到错树 → 解析器加"前缀优先"规则（`Engine/`→项目树，`shaders/`→WE）。
- **并行改写**：edit 失败信息是 `cannot edit ... file has not been read` 或内容不匹配 → 一律**重读后再改**，不重试原参数。
