## 1. 结论

把 DXR 光追作为**新增 Renderer** 接入统一入口 `RendererDemoApp`，光栅路径保持可独立构建、运行与回退。

三段交付：

- **D0 设备能力与请求链**：`Graphics::Initialize` 里 DXR 查询从「仅在 App 请求时查」改为**无条件查询并记录**，能力与请求彻底解耦；`RayTracingApp` 的 `RequiresRaytracingSupport()` 补齐 `const override`（此前是**另一个函数**，请求被基类默认值静默吞掉）。
- **D1 Shader 与加速结构**：Shader 编译链新增 `lib_6_4` 变体（DXIL library，无 `-E`）；新建 `RaytracingPSO`（State Object 独立封装，**不复用** GraphicsPSO 缓存）；BLAS 从 Mesh VB/IB 构建、TLAS 从 `ModelInstance` 变换构建，静态几何复用 BLAS、只在实例变化时重建 TLAS。
- **D2 Ray Dispatch 最小图像**：RayGen/Miss/ClosestHit + SBT 全通，命中返回法线色、未命中返回深蓝背景，结果写入 `R8G8B8A8_UNORM` 输出缓冲并经 `Display::PreparePresentSDR` 统一 Present 上屏；`RayTracingRenderer` 注册进 `RendererRegistry`，UI 面板显示真实 Tier 并可切换。

实测：Debug + Release 均 exit 0；DXR 画面出现彩色法线着色模型；切换 DXR→Forward→Deferred 后光栅画面正常（无回归）；Debug Layer **0 ERROR**。

## 3. 目标、范围与非目标

**目标**：让 DXR 成为统一入口下**可选的一个 Renderer**，具备「设备能力如实上报 → 加速结构真实构建 → DispatchRays 真实出图 → 可切回光栅」的完整闭环。

**范围**：`GraphicsCore`（能力查询）、`RayTracingApp`（override 签名）、`ShaderCompiler.cmake` + `Engine/CMakeLists.txt`（lib_6_x）、`RaytracingPSO`、`RaytracingScene`、`RayTracingRenderer`、`RayTracing.hlsl`、`RendererRegistry`、`RendererDemoApp`（输出重绑 + UI）、`Model.h`（只读访问器）。

**非目标**（明确不做）：

- 不做硬阴影射线 / 反射 / 路径追踪（路线图 D3，且明确「未完成前只能称为 DXR 最小闭环」）
- 不做材质采样 / 贴图 / AlphaTest 的 DXR 版本（诊断画面只输出法线色）
- 不做 AS 的增量更新（`BUILD_RAYTRACING_ACCELERATION_STRUCTURE_MODE_UPDATE`），实例变化走 TLAS 全量重建
- 不做 BLAS 压缩（`PREFER_FAST_BUILD` / compacted size）
- 不引入 RenderGraph、不改 Deferred 的 6 段空壳

```
  -> BindRendererOutput: dynamic_cast<RayTracingRenderer*> -> Display::SceneColorBuffer
  -> Display::Present -> PreparePresentSDR -> CopyBuffer -> Present
```

## 7. 资源生命周期与同步点

| 资源 | 尺寸/格式 | 生命周期 | 同步点 |
|---|---|---|---|
| `Raytracing Scene Geometry`（聚合 VB/IB） | `totalBytes`（各 Model `m_DataBuffer` 按 256 对齐拼接） | 每次 `RebuildGeometry` 重建 | `CopyBufferRegion` → `TransitionResource(NON_PIXEL_SHADER_RESOURCE)` → `FlushResourceBarriers()` 后才 Build |
| BLAS 结果缓冲（每 `(实例,mesh,draw)` 一个） | `ResultDataMaxSizeInBytes` | `RebuildGeometry` 重建 | **创建时即 `RAYTRACING_ACCELERATION_STRUCTURE` 状态，全程不发 ResourceBarrier** |
| `Raytracing Scratch`（BLAS+TLAS 共用） | `max(各段偏移之和, 256)`，各段**互不重叠** | 尺寸变大才重建 | 建前 `TransitionResource(UNORDERED_ACCESS)`；段不重叠 ⇒ 连续 Build 无需中间 UAV barrier |
| TLAS 结果缓冲 | `ResultDataMaxSizeInBytes` | 实例数/尺寸变化才重建 | `m_TopLevelBuilt` 为真时先 `InsertUAVBarrier(*m_TopLevel, true)` 再 Build |
| `Raytracing Instance Data`（每实例 32 B） | `instanceCount * 32` | `RebuildGeometry` 重建 | 经 `m_InstanceDataUpload`（UPLOAD）+ `CopyBufferRegion` → `NON_PIXEL_SHADER_RESOURCE` |
| `Raytracing Instance Descs`（DXR 结构，64 B/实例） | `instanceCount * 64` | 每帧 `UpdateInstances` 重写 | UPLOAD 堆，`TransitionResource` 对其是安全空操作 |
| `Raytracing SBT` | 192 B（3 段 × 64 对齐，每段 32 B 标识符） | `BuildShaderBindingTable` 建一次 | UPLOAD 堆，只读 |
| `RayTracing Scene Color` | `R8G8B8A8_UNORM`，与 Deferred 同格式 | `Initialize` / `OnResize` | `UNORDERED_ACCESS`（DispatchRays）↔ `PIXEL_SHADER_RESOURCE`（Present） |

## 8. 方案取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A：每个 `(实例,mesh,draw)` 一个单几何 BLAS** | `ClosestHit` 只用 `InstanceID()` + `PrimitiveIndex()` 就能定位几何，**Tier 1.0 也能跑**；每实例数据是扁平的 32 B 结构 | BLAS 数量多（本模型 15 个） | **采纳** |
| B：每模型一个多几何 BLAS | BLAS 少 | 需要 `GeometryIndex()` 区分几何，那是 **Tier 1.1 才有的内置**，Tier 1.0 设备直接跑不了 | 否：可用性优先 |
| **A：GPU→GPU `CopyBufferRegion` 聚合几何** | Mesh 元数据已完整描述区段位置与长度，不需要读顶点内容；无同步等待 | 需要多一份几何显存（本模型约 5 MB） | **采纳** |
| B：回读 VB/IB 到 CPU 再重组 | 无额外显存 | `Finish(true)` 同步等待，启动卡顿 | 否：启动体验 |
| **A：`RaytracingPSO` 独立封装 State Object** | 与 `GraphicsPSO` 生命周期/语义完全不同（无 blend/depth/RT 格式），独立更清晰 | 多一个类 | **采纳** |
| B：扩展 `PSO` 基类塞 State Object | 复用 `DestroyAll` | `PSO` 内部持有 `ID3D12PipelineState*`，与 `ID3D12StateObject*` 是不同接口；混进去会让 `SetPipelineState(const PSO&)` 出现类型歧义 | 否：接口不兼容 |
| **A：`DispatchRays` 用 compute 根签名** | 官方 `D3D12RaytracingHelloWorld` 就是这套；D3D12 把光追着色器归到 compute 侧根参数空间 | 与项目里 `GraphicsContext` 的封装不对称，要显式取 `GetComputeContext()` | **采纳**（详见 §11 教训 3） |
| B：用 graphics 根签名 | 与其它 Pass 写法统一 | **实测整屏纯黑且零报错** | 否：踩过 |

## 11. 本轮沉淀的关键经验

1. **`DispatchRays` 读的是计算根签名，不是图形根签名。** 用 `SetGraphicsRootSignature` 绑定 + `DispatchRays` **不报任何错、日志全正常、状态对象和 SBT 都建成功，但整屏纯黑**。必须 `context.GetComputeContext()` 后用 `SetComputeRootSignature` / `SetComputeRootShaderResourceView` / `SetComputeRootDescriptorTable` / `SetComputeRoot32BitConstants`。官方 `D3D12RaytracingHelloWorld` 同理。

2. **HLSL 默认 `column_major`，`float4x4` 会被按列读。** 项目其余 shader 都经由 `StaticMeshVS.hlsl` 等文件里的 `#pragma pack_matrix(row_major)` 或矩阵乘法写法规避；`RayTracing.hlsl` 只 include 了纯函数头 `ColorPipeline.hlsli`，漏了 pragma → `g_InvViewProj` 等价于转置 → 反投影射线方向全错 → 全打空。**判据**：整屏 `(26,38,69)` 正是 miss 背景色 `(0.02,0.03,0.06)` 经 ACES+sRGB 后的精确值 = "RayGen 在跑、UAV 在写、但射线全打空"；纯黑 `(0,0,0)` 才是"没派发"。

3. **`BuildRaytracingAccelerationStructure` / `DispatchRays` 不会自动 `FlushResourceBarriers()`。** `CommandContext::TransitionResource` 只把屏障压进 `m_ResourceBarrierBuffer[16]`，不到 16 个不提交；`DrawInstanced` 内部会 flush，这两个 DXR 入口不会。漏了会报 `EXECUTION ERROR #538 INVALID_SUBRESOURCE_STATE`（几何还在 `COPY_DEST`）。

4. **加速结构资源必须在创建时即为 AS 状态，之后永不发 ResourceBarrier。** 三个连环错误：① 事后 `TransitionResource(..., RAYTRACING_ACCELERATION_STRUCTURE)` → `#526 RESOURCE_BARRIER_INVALID_COMBINATION`；② 用 `D3D12_RESOURCE_FLAG_RAYTRACING_ACCELERATION_STRUCTURE`(0x100) → `#719 CREATERESOURCE_UNRECOGNIZEDLAYOUT`（本机 `d3d12.dll` 10.0.19041 不认，属 Agility SDK 1.7xx 后标志）；③ 用 `RESOURCE_FLAG_NONE` + AS 初始状态 → `#524 MISMATCHING_MISC_FLAGS`。**正解**：`Flags = ALLOW_UNORDERED_ACCESS` + `InitialState = RAYTRACING_ACCELERATION_STRUCTURE`。

5. **生成头漏挂依赖 = shader 修改静默失效。** `Engine/CMakeLists.txt` 的 `shader_attach_header_dependency` 原本只挂了 DeferredRenderer / ForwardRenderer / EnvironmentLightingManager，**漏了 RayTracingRenderer.cpp**。于是改 HLSL → `.cso/.h` 更新 → `.cpp` 不重编 → exe 里仍是旧字节码。**前几轮（row_major、调试输出）全部无效**，排查了很久的黑屏其实是调试着色器根本没被编进去。验证方式：`ls -la out/build/<Cfg>/Engine/CMakeFiles/TooiyumeEngine.dir/<path>.obj` 看时间戳。

6. **`D3D12_RAYTRACING_INSTANCE_DESC.Transform` 是列向量约定，项目 `Matrix4` 是行向量约定。** 按行直拷 `Transform[i][j] = m[i][j]` 会丢掉平移（`m[i][3]` 对仿射矩阵恒 0）。正解：`Transform[i][j] = m[j][i]`，平移走 `Transform[i][3] = m[3][i]`。单模型平移为 0 时不显现，**多模型必现**。

7. **`ModelLoader` 无条件 `Alloc` 全局纹理/采样器堆。** 任何 Renderer 的 `Initialize` 都必须建 `s_TextureHeap` / `s_SamplerHeap`，否则切过去后加载模型会在已 Destroy 的空堆上 `Alloc` → `ASSERT(HasAvailableSpace)` → `STATUS_BREAKPOINT`（exit `-2147483645`）。**DXR 不用材质也必须建。**

8. **`CommandContext::WriteBuffer` 要求源指针 16 字节对齐**（`ASSERT(Math::IsAligned(BufferData, 16))`）。`std::vector::data()` 只保证 `alignof(T)`，不可靠。**每帧上传用 `UploadBuffer` + `Map` + `memcpy`**，且上传缓冲必须是成员（局部变量会在命令列表提交前析构）。

9. **`SetBufferSRV` 的 ASSERT 会挡住加速结构。** AS 资源永远不处于 `PIXEL_SHADER_RESOURCE` / `NON_PIXEL_SHADER_RESOURCE`，而 `SetBufferSRV` 断言这两者之一 → 绑 TLAS 必须直接 `GetCommandList()->SetComputeRootShaderResourceView(...)`。

10. **`DispatchRays` 的 `Width/Height/Depth` 必须每次派发前填。** 它们是 `D3D12_DISPATCH_RAYS_DESC` 的字段，`RebuildTopLevel` 会把 desc 清成 0；若 `Render` 不填，派发的是 **0 条射线** —— 不报错、不崩溃、日志照常、截图纯黑。

11. **根级 SRV（`D3D12_ROOT_PARAMETER_TYPE_SRV`）不携带 `StructureByteStride`。** HLSL 侧声明成 `StructuredBuffer<T>` 会按错误的跨距读取。**改用 `ByteAddressBuffer` + 手算字节偏移**。

12. **`DescriptorHandle` 有 `operator D3D12_CPU_DESCRIPTOR_HANDLE()` 与 `GetCpuPtr()` 两条转换路径**，直接当函数实参传会 C2664 歧义 → 必须先赋给 `D3D12_CPU_DESCRIPTOR_HANDLE` 局部变量。

13. **`D3D12_RAYTRACING_TIER_NONE` 不存在。** SDK 里是 `D3D12_RAYTRACING_TIER_NOT_SUPPORTED = 0` / `_1_0 = 10` / `_1_1 = 11` / `_1_2 = 12`。

14. **黑屏要用 GPU 回读切分责任，再用像素值反推阶段。** 本轮靠「纯黑 vs 深蓝灰 (26,38,69)」直接区分了「没派发」与「射线全打空」两种完全不同的故障，比逐行读代码快得多。

15. **射线方向可视化是最快的矩阵验证手段。** 临时在 RayGen 里把 `payload.HitDistance < 0` 的像素写成 `ray.Direction * 0.5 + 0.5`：屏幕中心 `(127,127,0)` = 方向 `(0,0,-1)` 证明 `InvViewProj` 正确；颜色块状跳变则是矩阵错。**用完必须删干净。**

16. **`lib_6_x` 编译与 `*_6_x` 的区别是「无 `-E`」。** 一份 `.hlsl` 里的 RayGen/Miss/ClosestHit/AnyHit 全部编进同一个 DXIL 库，由 State Object 的 `DXIL_LIBRARY` 子对象按导出名挑选。

17. **Windows 环境变量名大小写不敏感，但允许同时存在 `NO_PROXY` 与 `no_proxy`。** MSBuild 的 `ProcessStartInfo.EnvironmentVariables` 会因此抛 `ArgumentException: 已添加了具有相同键的项`，`cmake -G "Visual Studio 17 2022"` 表现为 **`No CMAKE_CXX_COMPILER could be found`**（误导性极强，真因只在 `CMakeFiles/CMakeConfigureLog.yaml` 里）。`Get-ChildItem env:` 本身也会抛同样的错，要用 `[System.Environment]::GetEnvironmentVariables()`。

## 13. 主动回忆（≥5 题 + 答案）

| # | 问题 | 答案 |
|---|---|---|
| Q1 | 为什么 `DispatchRays` 必须用 `SetComputeRootSignature`？ | D3D12 把光追着色器归到 compute 侧的根参数空间；用 graphics 根签名时根参数**不会生效**，shader 读到的是未绑定槽位 → 射线/常量全错，且**不报错**。 |
| Q2 | BLAS/TLAS 结果缓冲的正确创建方式是什么？为什么不能事后 Transition？ | `CreateCommittedResource` 时 `Flags = ALLOW_UNORDERED_ACCESS` + `InitialState = RAYTRACING_ACCELERATION_STRUCTURE`。D3D12 不允许把资源 barrier 进 AS 状态（#526），只允许创建时即为该状态；且初始状态为 AS 要求资源有 UAV 能力（#524）。 |
| Q3 | `BuildRaytracingAccelerationStructure` 之前为什么要显式 `FlushResourceBarriers()`？ | 因为 `CommandContext::TransitionResource` 是延迟提交（攒在 `m_ResourceBarrierBuffer[16]`），而 `DrawInstanced` 内部会 flush、DXR 的两个入口不会。不 flush 的话几何资源还停在 `COPY_DEST`，报 #538。 |
| Q4 | `D3D12_RAYTRACING_INSTANCE_DESC.Transform` 与项目 `Matrix4` 的行列约定差在哪？ | DXR 是列向量约定（平移在第 3 列 `Transform[i][3]`），项目是行向量约定（平移在第 3 行 `m[3][i]`）。所以要 `Transform[i][j] = m[j][i]`。 |
| Q5 | 为什么每帧上传实例数据要用 `UploadBuffer` 而不是 `WriteBuffer`？ | `WriteBuffer` 内部有 `ASSERT(Math::IsAligned(BufferData, 16))`，而 `std::vector::data()` 只保证 `alignof(T)`。且 `WriteBuffer` 每次都会 `ReserveUploadMemory`，高频调用会快速耗尽上传环。 |
| Q6 | 为什么 `RayTracingRenderer::Initialize` 必须创建 `s_TextureHeap` / `s_SamplerHeap`？ | `ModelLoader.cpp:103/:185` 无条件 `Alloc` 这两个全局堆；DXR 路径不采样材质，但堆必须存在，否则切过去后加载模型直接 `ASSERT` 崩溃。 |
| Q7 | 画面「纯黑」与「深蓝灰」分别对应什么故障？ | 纯黑 = DispatchRays 没派发（Width/Height 为 0、或 Render 被守卫返回）或 UAV 没写；深蓝灰 `(26,38,69)` = RayGen 在跑、UAV 在写、但所有射线都 miss（矩阵/根签名/变换错）。 |
| Q8 | `compile_raytracing_library` 与 `compile_shader` 的唯一区别是什么？ | **不传 `-E`**。`lib_6_4` 把文件内所有 `[shader("...")]` 入口编进同一个 DXIL 库，由 State Object 按导出名挑选；普通 `*_6_4` 必须 `-E <entry>` 只编一个入口。 |
