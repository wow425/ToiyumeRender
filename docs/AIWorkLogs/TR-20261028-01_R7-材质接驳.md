## 0. 施工卡（一句话）

**把 DXR 的 `ClosestHit` 从「中性灰 albedo + Lambert」升级为「真实 BaseColor 贴图 × 材质因子 + GGX/Cook-Torrance」，并用两个正交开关做出 2×2 可自我证伪的验收矩阵。**

- 不做 MetallicRoughness / Occlusion / Emissive / Normal 贴图采样（D3）。

- 不做 IBL / 点光源（DXR 仍只消费太阳）。
- 不动 R6 的硬阴影射线与单次反射结构。

## 2. 开工前复核（P1–P6）

| 编号 | 复核项 | 结论 |
|---|---|---|

## 3. 前后架构图

### 3.1 R6（改前）

```
RayTracing.hlsl
  RayGen ──► TraceRay(primary) ──► ClosestHit
                                      │
                                      ├─ albedo = float3(0.8,0.8,0.8)   ← 硬编码中性灰
                                      ├─ visibility = TraceShadowRay()  ← R6 阴影
                                      ├─ diffuse = albedo * lightRadiance * nDotL * visibility
                                      ├─ shaded = diffuse + albedo * SkyColor(n) * 0.35
                                      └─ (可选) TraceReflectionRay()    ← R6 反射
  根签名 b0 = 48 DWORD / 5 个根参数（t0 TLAS / t1 场景 / t2 实例 / u0 输出表 / b0 常量）
  输出 UAV 独占 m_DescriptorHeap（4 槽），贴图 SRV 在 s_TextureHeap（另一张堆，从没绑过）
```

### 3.2 R7（改后）

```
RayTracing.hlsl
  RayGen ──► TraceRay(primary) ──► ClosestHit
                                      │
                                      ├─ albedo = LoadInstanceAlbedo(...)          ← R7 新增
                                      │     ├─ 读 baseColorFactor（每实例数据）
                                      │     ├─ 3× LoadIndex → 3× LoadVertexUv（手拆半字 + f16tof32）
                                      │     ├─ 重心插值 uv
                                      │     └─ g_Textures[NonUniformResourceIndex(srvBase+0)].SampleLevel(...,0)
                                      │
                                      ├─ visibility = TraceShadowRay()             ← R6 保留
                                      ├─ if (!enableGGX)  R6 Lambert 原样          ← A5a 回归支路
                                      └─ else             GGX/Cook-Torrance        ← R7 新增
                                            direct  = (kd*albedo/π + D*V*F) * radiance * nDotL * visibility
                                            ambient = lerp(diffuseIBL_from_Sky, specIBL_from_Sky + diffuseIBL, metallic)
                                            shaded  = direct + ambient

  根签名 b0 = 52 DWORD / 6 个根参数（+ t3 无界 SRV 表 + s0 静态采样器）
  输出 UAV 与贴图 SRV 合并进同一张 s_TextureHeap（0 号槽 = 输出 UAV，1 号槽起 = 材质贴图）
```

## 5. 关键改动与调用链

### 5.1 每实例数据：32 B → 96 B（`RaytracingScene.h:60-115`）

```cpp
struct RaytracingInstanceData {
    // ── R5 已有（0..31）
    uint32_t VertexOffset, IndexOffset, VertexStride, IndexFormat,
             StartIndex, BaseVertex, PrimitiveCount, InstanceId;
    // ── R7 新增（32..95）
    uint32_t UvByteOffset;      // 32  UV0 在顶点内的字节偏移，0xFFFFFFFF = 无 UV
    uint32_t VertexFlags;       // 36  来自 Mesh::vertexFlags
    uint32_t MaterialIndex;     // 40  = Mesh::materialSlotIdx
    uint32_t SrvTableIndex;     // 44  5 张贴图在全局贴图表里的起点偏移
    float    BaseColorFactor[4];// 48
    float    EmissiveFactor[3]; // 64
    float    NormalTextureScale;// 76
    float    MetallicFactor;    // 80
    float    RoughnessFactor;   // 84
    uint32_t MaterialFlags;     // 88
    uint32_t _padding;          // 92
};
static_assert(sizeof(RaytracingInstanceData) == 96, "必须与 HLSL 的 RaytracingInstanceData 布局一致");
```

代价：64 B × 15 实例 = **960 B**（可忽略）。

**为什么不能省**：ray shader 只能读 `ByteAddressBuffer`（`g_InstanceData`）或描述符，**不能解引用运行时才确定的 GPU 常量缓冲地址**。所以材质标量必须在建 BLAS 时烘进来。

### 5.2 UV 偏移的推导（`RaytracingScene.cpp:313`）

```cpp
const bool hasTangent = (mesh.vertexFlags & Renderer::kVertex_Tangent) != 0;
const bool hasUV0     = (mesh.vertexFlags & Renderer::kVertex_UV0) != 0;
data.UvByteOffset = hasUV0 ? (uint32_t)(12 + 4 + (hasTangent ? 4 : 0)) : 0xFFFFFFFFu;
```

推导链（`Engine/03_AssetSystem/Importers/Mesh/MeshConvert.cpp:308-330`）：

| 属性 | 格式 | 偏移 | 大小 |
|---|---|---|---|
| POSITION | `R32G32B32_FLOAT` | 0 | 12 |
| NORMAL | `R10G10B10A2_UNORM` | 12 | 4 |
| TANGENT | `R10G10B10A2_UNORM`（可选） | 16 | 4 |
| TEXCOORD0 | `R16G16_FLOAT` | 16 或 20 | 4 |

merlin.ty 实测：15 个 mesh 全部 `vbStride=24`、`vertexFlags=0x0f`（POSITION|NORMAL|TANGENT|UV0）→ **UV 偏移恒 20**。

### 5.3 **本轮最关键的一处 bug**：`LoadVertexUv` 用 `Load<float2>` 读 4 字节属性

**错误写法**（第一版）：

```hlsl
// 注释还错误地声称「R16G16_FLOAT 是 4 字节，Load<float2> 内部按 2×16 位解码」
return g_SceneData.Load<float2>(addr & ~3u);
```

**为什么错**：`ByteAddressBuffer::Load<T>` 是**按 T 的字节宽度做裸位拷贝，不做任何格式转换**。`float2` = 8 字节，于是它把

- 前 4 字节（u 的 half + v 的 half）当 float 解释
- 后 4 字节（**属于下一个属性或下一个顶点**）当第二个 float 解释

→ uv 变成 ~1e-38 的 denormal，等价于 **(0,0)**。

**表现（极其隐蔽）**：整张贴图退化成「每个材质一片纯色」，布料褶皱、脸上画好的眼睛全部消失，**但不报任何错、不崩、日志正常**。截图看起来「确实有颜色」，极易被误判为「已经接上了」。

**正确写法**（`RayTracing.hlsl:258-263`）：

```hlsl
float2 LoadVertexUv(uint vertexOffsetInScene, uint vertexIndex, uint vertexStride, uint uvByteOffset)
{
    const uint addr = vertexOffsetInScene + vertexIndex * vertexStride + uvByteOffset;
    const uint packed = g_SceneData.Load<uint>(addr & ~3u);
    return float2(f16tof32(packed & 0xFFFFu), f16tof32(packed >> 16));
}
```

与 `LoadIndex` 处理 16 位索引的方式完全一致（取 32 位字 → 拆半字 → 解码）。

### 5.4 无界 SRV 表 + `NonUniformResourceIndex`（`RayTracingRenderer.cpp:288-291`）

```cpp
m_GlobalRootSig[kGlobalRootMaterialTextures].InitAsDescriptorRange(
    D3D12_DESCRIPTOR_RANGE_TYPE_SRV, 3, UINT_MAX, D3D12_SHADER_VISIBILITY_ALL);
```

HLSL 侧：

```hlsl
Texture2D<float4> g_Textures[] : register(t3);
...
g_Textures[NonUniformResourceIndex(srvBase + TEX_SLOT_BASECOLOR)].SampleLevel(g_MaterialSampler, uv, 0.0f);
```

两个必须点：

1. **必须从 t3 起** —— t0/t1/t2 已被根级 SRV（TLAS / 场景几何 / 实例数据）占用。
2. **必须 `NonUniformResourceIndex`** —— 同一波内不同像素可能采不同材质的贴图，不加这个修饰符编译器会当成 uniform 索引，可能取值错误（甚至越界）。

### 5.5 输出 UAV 与贴图 SRV 合并到同一张堆（`RayTracingRenderer.cpp:120-130`）

```cpp
s_TextureHeap.Create(L"RayTracing Texture Descriptors", D3D12_DESCRIPTOR_HEAP_TYPE_CBV_SRV_UAV, 4096);
s_SamplerHeap.Create(L"RayTracing Sampler Descriptors", D3D12_DESCRIPTOR_HEAP_TYPE_SAMPLER, 2048);

// 必须在模型加载前占住 0 号槽，否则会被第一个材质的 BaseColor 抢走
const DescriptorHandle outputUav = s_TextureHeap.Alloc(1);
m_OutputUavOffset = s_TextureHeap.GetOffsetOfHandle(outputUav);
RefreshDescriptorHeap();
```

**D3D12 硬限制**：一个命令列表同时只能绑一个 CBV_SRV_UAV 堆。原来输出 UAV 独占 `m_DescriptorHeap`（4 槽），贴图 SRV 在 `s_TextureHeap`（从没绑过）→ 两者无法同时可见。现在合并。

**踩过的坑**：`DescriptorHeap::GetHeapPointer()` 返回 `ID3D12DescriptorHeap*`，**不是** GPU 描述符句柄。写成 `(D3D12_GPU_DESCRIPTOR_HANDLE)heap.GetHeapPointer()` 编译通过但值完全错 → 采样越界 → 全黑。必须用 `heap[offset]`（`operator[]` 才返回正确的 `DescriptorHandle`）。

### 5.6 GGX/Cook-Torrance（`RayTracing.hlsl:281-300, 636-660`）

```hlsl
float DistributionGGX(float nDotH, float alpha)
{
    const float a2 = alpha * alpha;
    const float d  = nDotH * nDotH * (a2 - 1.0f) + 1.0f;
    return a2 / max(kPI * d * d, 1e-7f);
}

float VisibilitySmithGGXCorrelated(float nDotV, float nDotL, float alpha)
{
    const float a2 = alpha * alpha;
    const float gv = nDotL * sqrt(nDotV * nDotV * (1.0f - a2) + a2);
    const float gl = nDotV * sqrt(nDotL * nDotL * (1.0f - a2) + a2);
    return 0.5f / max(gv + gl, 1e-7f);   // ← 已含 1/(4·nDotV·nDotL)
}
```

**关键**：`VisibilitySmithGGXCorrelated` 已经包含了 `1/(4·nDotV·nDotL)`，调用点**不能再除分母**。写成 `D*G*F/(4*nDotV*nDotL)` 会重复除，高光会暗 4 倍以上。这里用 `(D * V) * F` 就够。

着色主体：

```hlsl
const float3 f0 = lerp(float3(0.04, 0.04, 0.04), albedo, metallic);
const float3 F  = FresnelSchlick(vDotH, f0);
const float3 specular   = (DistributionGGX(nDotH, alpha) * VisibilitySmithGGXCorrelated(nDotV, nDotL, alpha)) * F;
const float3 kd         = (1 - F) * (1 - metallic);          // 金属无漫反射
const float3 diffuseBRDF= kd * albedo / kPI;
const float3 direct     = (diffuseBRDF + specular) * lightRadiance * nDotL * visibility;

const float3 ambientDiff = albedo * SkyColor(n) * 0.35f;
const float3 ambientSpec = SkyColor(reflect(-viewDir, n)) * F * (1.0f - roughness * 0.7f);
shaded = direct + lerp(ambientDiff, ambientSpec + ambientDiff, metallic);
```

**为什么漫反射要除 π**：Lambert BRDF 是 `albedo/π`。R6 的公式 `albedo * radiance * nDotL` 少了 `/π`，所以 R6 与 R7 的漫反射差一个 3.14 倍 —— 这是 A5b/A5c 与 A5a 亮度不同的**部分**原因（见 §9 U1）。

**为什么环境镜面要乘 `(1 - roughness*0.7)`**：没有 IBL 预过滤贴图，直接用 `SkyColor` 当环境镜面会让粗糙表面像镜子一样发亮。乘一个随 roughness 衰减的系数是廉价近似。

### 5.7 调试通道不再过显示编码链（`RayTracing.hlsl:492-497`）

```hlsl
const uint debugView = (uint)(g_RTParams2.z + 0.5f);
const bool bypassDisplay = (debugView != 0u) && (payload.HitDistance >= 0.0f);
const float3 display = bypassDisplay ? hdr : EncodeDisplayColor(...);
```

**为什么**：Deferred 的调试通道（`LightingPS.hlsl:188-216`）是在曝光/ACES/sRGB **之前** `return` 的，注释写明「调试通道要显示的是缓冲区的原始数值」。R7 原先无条件走 `EncodeDisplayColor` → 同一个通道名在两条路径下画出的东西不是一个东西 → A7 无法比对。

**注意 `payload.HitDistance >= 0` 这个条件**：未命中（背景）时仍走编码链，这样背景色与 Deferred 的 skybox 一致，比对时背景不该成为噪声源。

## 6. 资源生命周期与同步点

| 资源 | 创建 | 销毁 | 备注 |
|---|---|---|---|
| `s_TextureHeap`（4096 槽） | `RayTracingRenderer::Initialize:118` | `Shutdown:148` | **0 号槽 = 输出 UAV**，1 号起 = 材质贴图 |
| `s_SamplerHeap`（2048 槽） | `Initialize:119` | `Shutdown:149` | ModelLoader 会 `Alloc`，即使 DXR 用静态采样器也必须建 |
| 输出 UAV 描述符 | `RefreshDescriptorHeap:255-262` | — | `OnResize` 时重建（`RefreshDescriptorHeap` 再调一次） |
| `RaytracingInstanceData` 缓冲 | `RebuildGeometry` | `Destroy` | 96 B × N |
| TLAS / BLAS | `RebuildGeometry` / `RebuildTopLevel` | `Destroy` | 创建即 AS 状态，**永不 Transition** |

**同步点（三个必须）**：

1. BLAS/TLAS Build 前必须 `gfxContext.FlushResourceBarriers()` —— `BuildRaytracingAccelerationStructure` 不像 `DrawInstanced` 那样自动 flush。
2. `DispatchRays` 前必须 `FlushResourceBarriers()` —— 同理。
3. 输出缓冲 `SceneColor` 的 `UNORDERED_ACCESS → PIXEL_SHADER_RESOURCE` Transition 由 `CommandContext` 的屏障缓冲统一提交。

**切 renderer 的时序**：`SwitchRenderer` → `IdleGPU` → `UnloadModel` → 旧 `Shutdown()`（`s_TextureHeap.Destroy()`）→ 新 `Initialize`（`Create` + `++m_Generation`）→ 重新加载模型 → 所有描述符偏移重新分配。**代际号变化意味着任何缓存的偏移都失效**，ModelLoader 的采样器缓存已按代际校验，DXR 侧因为每次 Switch 都重建实例数据，天然安全（`r7_06 == r7_04` 是这一点的硬证据）。

## 7. 与 WE 比较

| 维度 | 本项目 R7 | WE 引擎做法 | 差距 |
|---|---|---|---|
| 材质数据传递 | 每实例 96 B 烘进 ByteAddressBuffer | 用 SBT 里带局部根签名 + 常量，避免每实例膨胀 | 方案 B 是正解，已留演进（D6） |
| 贴图寻址 | 无界 SRV 表 + `NonUniformResourceIndex` | 描述符索引表（`uint` heap index）间接寻址 | 本项目更简单但受 4096 槽上限约束 |
| 光照模型 | GGX 直射 + SkyColor 假环境 | 完整 IBL + 多光源 + 阴影混合 | 差 IBL 与多光源 |
| alpha test | 未做 | AnyHit + `IgnoreHit()` | P2 补齐 |
| 材质来源 | glTF 标量 + BaseColor 贴图 | 完整 PBR 材质图 | P1 补齐 |

## 8. 方案取舍

| 方案 | 描述 | 结论 |
|---|---|---|
| **A：无界 SRV 表** | 根签名声明 `UINT_MAX` 个 SRV（t3 起），每实例存堆内相对偏移 | ✅ **采纳**（D6）—— 不增加 SBT 记录数，切换材质只改索引 |
| B：SBT 本地根签名 | 每个 hit group 记录带自己的根常量/描述符表 | ⬜ **留演进** —— 更省内存、更符合 DXR 最佳实践，但要为每个材质建独立 SBT 记录，工作量翻倍 |
| C：把材质烘进几何 | 每三角形一份材质常量 | ❌ 否决 —— 与 BLAS 复用冲突，内存爆炸 |

## 12. 主动回忆（8 题）

1. **为什么 `LoadVertexUv` 不能用 `Load<float2>`？** → `Load<T>` 是裸位拷贝不做格式转换，`float2` 读 8 字节会把下一个属性的 4 字节拼进来，uv 变 denormal ≈ (0,0)，整张贴图退化成纯色且不报错。

2. **为什么材质标量必须烘进 `ByteAddressBuffer`，不能直接读 GPU 常量缓冲？** → ray shader 只能解引用描述符（CBV/SRV）或根级句柄；`Model::m_MaterialConstants` 的 GPU 地址是运行时值，HLSL 无法把 `uint64` 当地址解引用。

3. **为什么输出 UAV 和贴图 SRV 必须在同一张堆？** → D3D12 一个命令列表同时只能绑一个 CBV_SRV_UAV 堆。

4. **`VisibilitySmithGGXCorrelated` 返回的 `V` 能不能再除 `4*nDotV*nDotL`？** → 不能，函数里 `0.5f / (gv+gl)` 已经包含了这一项（Smith 高度相关可见性项的定义）。

5. **为什么 `g_Textures[]` 必须从 t3 起？** → t0/t1/t2 已被根级 SRV 占用（TLAS / 场景几何 / 实例数据）。

6. **为什么调试通道要跳过 `EncodeDisplayColor`？** → Deferred 的调试通道在曝光/ACES/sRGB 之前 return，显示的是缓冲区原始数值；R7 若走编码链，同名通道画出的东西就不是一个东西，A7 无法比对。

7. **`srvTable` 为什么不能用？** → 全仓零赋值，Debug 恒 `0xCDCD`（52685）。必须用 `mesh.materialSlotIdx` 查 `model->m_Materials[]`。

8. **A5a 为什么必须逐字节等于 R6 基线？** → 这是本轮的「可自我证伪点」：如果两个开关都关还不能回到 R6 的 `a43b6059…`，说明改动污染了旧路径，A5b/A5c/A5d 的差异就无法归因。

## 附：本轮踩到的坑（9 条）
