# TR-20261026-05：点击鼠标导致程序退出修复

- 日期：2026-10-26
- 阶段：运行时缺陷修复（输入系统）
- 状态：**DONE**
- 分支/基线提交：master @ 51c09d0

## 1. 结论

点击窗口导致程序退出的问题已修复。**根因不是崩溃，而是输入映射表用错**：
`GameInput` 把 DirectInput 的**扫描码 DIK** 直接传给了 `GetAsyncKeyState`（它要 **VK 虚拟键码**）。
`DIK_ESCAPE = 0x01` 恰好等于 `VK_LBUTTON`，于是「按下鼠标左键」被判定为「按下 Escape」，
`IsDone()` 返回 true，主循环正常退出（退出码 0，无任何异常）。

修复：拆出独立的 `s_VKMapping` 表，`GetAsyncKeyState` 改用 VK。

技术文档：`docs/AI/R4/R4.3_点击闪退修复.md`

## 2. 施工前状态与证据

- 现象：渲染正常，点击即退出
- cdb 附加（`sxe av; sxe ch`）：点击后无任何异常
- 代码内 `SetUnhandledExceptionFilter`：日志无 `[CRASH]` 输出
- → **推翻"崩溃"假设，确认是主动退出**

退出条件只有一处：

```cpp
bool IGameApp::IsDone(void) { return GameInput::IsFirstPressed(GameInput::kKey_escape); }
```

## 3. 根因

```
DIK_ESCAPE = 0x01   （DirectInput 扫描码）
VK_LBUTTON = 0x01   （Windows 虚拟键码，鼠标左键）
VK_ESCAPE  = 0x1B
```

`GameInput::Update` 里：

```cpp
const unsigned char vk = s_DXKeyMapping[i];   // 实为 DIK
down = (::GetAsyncKeyState(vk) & 0x8000) != 0; // 当作 VK 用 —— 错
```

链路：鼠标左键 → `GetAsyncKeyState(0x01)` 为真 → `s_Buttons[0][kKey_escape]=true`
→ `IsDone()` → 主循环 break → exit(0)。全程无错误。

同表还掩盖了第二个 bug：字母键全部映射错位（`DIK_W=0x11` vs `VK_W=0x57`），
这是「WASD 时灵时不灵」的根源。

## 4. 修复

- 新增 `s_VKMapping[GameInput::kNumKeys]`，用标准 VK 宏填满常用键
- 保留 `s_DXKeyMapping`（DIK）仅用于索引 `s_Keybuffer`
- `GetAsyncKeyState` 改用 `s_VKMapping`

## 5. 验证

用**真实鼠标事件**（`SetCursorPos` + `mouse_event`）验证，而非 `PostMessage`
（后者不经过 `GetAsyncKeyState`，复现不出）：

## 8. 方法论教训

### 8.1 「闪退」必须先分崩溃还是主动退出

| 类型 | 特征 | 手段 |
|---|---|---|
| 崩溃 | 非零退出码、有异常 | 调试器 / `SetUnhandledExceptionFilter` |
| 主动退出 | **退出码 0**、日志干净 | 读 `while` 循环判定条件 |

本次是后者。一开始盯着"崩溃"找，方向完全错。**退出码是 0 就该先读退出条件。**

### 8.2 模拟输入要选对层级

```
PostMessage(WM_*)  → 只经过 WndProc/ImGui，不经过 GetAsyncKeyState
mouse_event       → 系统级注入，走完整硬件输入路径  ← 本次需要这个
```

### 8.3 一张表两个语义，是这类 bug 的温床

`s_DXKeyMapping` 名字里带 "DX"（DirectX），实际存 DIK；
调用处却把它当 VK 用。**名字没提示出差异，是埋雷点。**
现在拆成 `s_DXKeyMapping`(DIK) / `s_VKMapping`(VK)，名字直说语义。

## 9. 已知限制

- `s_VKMapping` 只覆盖常用键；未覆盖的键在该通路下不响应（DirectInput 通路仍可用）
