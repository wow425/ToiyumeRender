## 1. 结论

Visual Studio 里打开本仓库后 CMake 无法配置/构建的问题已修复。四条构建路径全部实测通过：
VS presets（Debug/Release，101/101）与旧 `scripts\build.bat`（未回归）。
VS 构建产物与脚本构建产物的渲染结果 **10 张截图 md5 逐字节相同**。

技术文档：`docs/AI/R4/R4.1_VisualStudio构建修复.md`

## 2. 施工前状态与证据

命令行 `scripts\build.bat Debug` 一直成功，但 VS 里失败 → 说明不是代码问题，是构建配置问题。

直接复现（用 VS 自带的 cmake，在不设环境变量的情况下）：

```
CMake Error: Could not read presets from ...
Error: @4,15: Invalid extra field "_comment" in root object
```

## 3. 目标与范围

**目标**：在 VS 里打开项目 → 能配置 → 能构建 → 能运行。

**范围**：`CMakePresets.json`、根 `CMakeLists.txt` 的依赖解析、运行时 DLL 部署、vcpkg 依赖打包完整性。

**非目标**：不改任何渲染代码；不改 VS 安装目录；不动用 `git reset/clean`。

## 4. 四个根因（详见 R4.1 文档 §2）

| # | 根因 | 修法 |
|---|---|---|
| 1 | `CMakePresets.json` 根对象含非法 `_comment` → CMake 拒绝解析整个 presets | 删除该字段，注释写进 `description` |
| 2 | 依赖硬依赖 `VCPKG_ROOT` 环境变量，VS 不继承 shell 变量 | 双路径：有 toolchain 就用，否则用仓库内 `vcpkg_installed` |
| 3 | 运行时 DLL 靠 toolchain 的 `APPLOCAL_DEPS` 拷贝，走路径 B 就缺 DLL | 新增 `DeployRuntimeDlls.cmake` 显式部署 |
| 4 | 仓库内 `vcpkg_installed` 的 DirectXMesh **缺 `dx12` feature** → 缺 D3D12 重载 → LNK2019 | 用 `vcpkg.json` 的 feature 重装 |

### 4.1 第 4 条的排查过程（本轮最有价值的部分）

1. 两构建的 `LINK_LIBRARIES` 相同 → 排除链接顺序/路径
2. 两构建的 `DEFINES` 相同 → 排除宏差异
3. 两个 `DirectXMesh.lib` 的 **md5 不同**
4. `grep D3D12_INPUT_LAYOUT_DESC`：仓库根目录那份 **0 处**，旧构建目录那份 **5 处**

→ 仓库根目录是 5 月生成、不带 `dx12` feature 的旧包；旧构建目录是后来重新解析的新包。
这也是「为什么命令行能过、VS 不能过」的真正分界点：两者用的**不是同一个** `vcpkg_installed`。

## 5. 关键实现

- `CMakePresets.json`：`windows-base` 不再写 `CMAKE_TOOLCHAIN_FILE`，改传 `VCPKG_ROOT`；
  真正的解析逻辑下沉到 CMakeLists
- `CMakeLists.txt` 依赖段：三选一分支 + 明确的可操作错误信息
- `Engine/20_cmake/DeployRuntimeDlls.cmake`：函数式部署，**必须由各 Demo 在自己目录调用**
- `Engine/CMakeLists.txt`：删掉原先那段永远不生效的集中部署循环

## 6. DX12 专项

不适用（本轮未改渲染代码）。但涉及 D3D12 链接契约：`DIRECTX_MESH_IMPORT` 让 DirectXMesh
成为 dllimport，所以 `ComputeInputLayout(D3D12...)` 这类符号必须由 DLL 的导入库提供，
纯头文件的 `Utilities` 目标替代不了这一条。

## 9. 代码审查结果

1. **发现并修正了自己的错误**：最初把 DLL 部署写成根 CMakeLists 里的循环，
   首次验证立即报 `TARGET ... was not created in this directory`。
   原因是 `add_custom_command(TARGET)` 要求同目录，改为函数式由各 Demo 自调用。
2. **发现并修正了旧代码的隐患**：`Engine/CMakeLists.txt` 里那段 `foreach + if(TARGET)`
   部署循环**从来不生效**（Engine 早于 Demos，target 还不存在），
   属于静默失效的死代码，已删除并注释指向新位置。
3. **未覆盖用户改动**：全程只做增量编辑，未用 `git reset/clean`。
4. **未改 VS 本体**：只调用了 `F:\VS\Community` 下已有的 cmake/ninja/vcvars，未写任何文件到该目录。
