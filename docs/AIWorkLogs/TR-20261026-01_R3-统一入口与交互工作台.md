## 1. 施工目标

**一句话**：把 Renderer 从「写死在 Demo 里的全局对象」变成「渲染器注册表里可运行时替换的实例」，并在这个统一入口上挂一套 Dear ImGui 工作台，让渲染参数只有一个真源。

对应原则门：**G3 架构迁移与特性开发不同批**（本阶段只做入口/切换/参数通路，不填任何渲染特效）。

**不做什么**（防范围膨胀）：

1. **不删旧 Demo**。`ForwardApp` / `DeferredApp` / `RayTracingApp` 保持可构建可运行，只在必要处补接线（Forward 的 `Update` / `SetAspectRatio` / `-Screenshot`）。
2. **不填 DeferredRenderer 的 6 段空壳**（SSAO / Shadow / Transparent / PostProcess / TAA / Tonemap）。它们只有 `PIXBeginEvent`，属 R6 范围，架构迁移期禁止顺手填。
3. **不实现 DXR Renderer**。注册表只注册 Deferred / Forward；Renderer 面板用 `TextDisabled` 明确写 `DXR renderer: Not implemented (R5)`。
4. **不动 RHI 的公开契约**。本阶段对 RHI 的改动全部是修 bug（堆类型屏障、描述符堆缓存、描述符归还），没有新增/删除公开接口。

## 6. 资源 / 数据流 / 生命周期

| 资源 | 尺寸/格式 | 生命周期 | 同步点 |
|---|---|---|---|
| `DeferredBuffer`（4 GBuffer + SceneColor + Depth + Velocity） | GBuffer 各 1920×1080；SceneColor `R8G8B8A8_UNORM`；Depth `D32_FLOAT` | 归 `DeferredRenderer` 实例；`Shutdown()` → `DestroyDeferredBufferTargets()` → `BufferManager::DestroyAll()` | `SwitchRenderer` 先 `IdleGPU()` |
| `ForwardBuffer`（SceneColor[8] + Depth） | 同上；SceneColor 只用 [0] | 归 `ForwardRenderer` 实例 | 同上 |
| `s_TextureHeap` / `s_SamplerHeap` | CBV_SRV_UAV 4096 / SAMPLER 2048，shader-visible | **进程级全局但生命周期归当前 Renderer**；`Shutdown()` 里 `Destroy()`，`BuildDescriptorHeaps()` 里重建 | `CommandContext::Reset()` 清堆缓存（本次修） |
| `ImGui` SRV 堆 | CBV_SRV_UAV 64，shader-visible | `ImGuiLayer::Initialize` 建 / `Shutdown` 销毁；与 Renderer 无关，跨 Renderer 存活 | ImGui 后端每次 InvalidateDeviceObjects 会回调 Alloc/Free |
| `m_LightGPUBuffer` | `StructuredBuffer`，1 元素 × 96 字节 | 进程级静态；每次 `InitializeResources()` 重建、`Shutdown()` 释放 | `ApplyParams` 里 COPY_DEST → `WriteBuffer` → GENERIC_READ |
| `GpuTimer` 查询堆 / 回读堆 | TIMESTAMP 2×3 槽；Readback 3×16 字节 | `GpuTimer::Initialize` / `Shutdown`；与 Renderer 无关 | Map 前必须 `GetGraphicsQueue().IsFenceComplete(fence)` |
| `ModelInstance` 的 MeshConstants 缓冲 | `m_NumNodes × sizeof(MeshConstants)` | 随 `ModelInstance`；`operator=` 重建 | `Update` 里 CPU Map → Unmap → COPY_DEST → `CopyBufferRegion` → GENERIC_READ |

## 7. 与 WE 的比较

| 项 | WE 的做法 | 本 WP 的做法 | 为什么 |
|---|---|---|---|
| Renderer 抽象 | 引擎内多套 Renderer 由统一入口按配置创建，通过基类指针持有 | 同思路，但只做「基类 + 注册表 + unique_ptr」最小闭环 | 抄（架构方向一致），改（不引入 WE 的完整 RenderGraph） |
| UI 插入点 | UI 画在 backbuffer，Present 前单独一次 pass | 画在 SceneColor，被 `PreparePresentSDR` 整体复制 | 改：不动 Display 的状态机（路线图 §6.2 方案 A） |
| 参数真源 | 渲染设置集中在全局配置对象，UI 只改配置 | `RenderParams` 结构体 + `ApplyParams` 单点上传 | 抄（避免 UI 与渲染各持一份） |
| 注册机制 | 显式注册表初始化 | 显式注册（本次修复）+ 保留自动注册模板 | 抄：显式优于依赖静态初始化器 |

## 8. 方案取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A：UI 画到 SceneColor，随 `CopyResource` 一起进 backbuffer | 完全不改 `Display.cpp` 的状态机；`PreparePresentSDR` 的尺寸校验天然覆盖 | UI 会进入 GPU 回读截图（实际上这是优点）；UI 分辨率随 SceneColor | **采纳** |
| B：`CopyResource` 之后、`Present` 之前直接画到 backbuffer | 省一次复制 | 要额外处理 `COPY_DEST → RENDER_TARGET → PRESENT`；`Display.cpp` 需要知道 UI 的存在 | 否：把 UI 概念泄漏进 Present 层 |
| C：每帧在 UI 里直接调 `SwitchRenderer` | 代码短 | `GraphicsContext` 正开着，`Shutdown/Initialize` 内部再开上下文会打乱录制（实测会崩） | 否：改为「登记 pending，下一帧帧首执行」 |
| D：依赖 `RendererAutoRegister` 静态对象自动注册 | 零样板代码 | 静态库 dead-strip 时静默失效（实测注册表为空） | 否：改为 `Instance()` 内显式注册 |

## 12. 主动回忆

| # | 问题 | 答案 |
|---|---|---|
| Q1 | 为什么 `SwitchRenderer` 第 1 步必须 `IdleGPU()`？ | 旧的 Renderer 资源上一帧还在被 in-flight 命令列表引用；直接 `Shutdown` 会命中 `#921 OBJECT_DELETED_WHILE_STILL_IN_USE`，Debug Layer 直接断死。 |
| Q2 | 为什么 UI 里的「切换」不能在按钮回调里直接执行？ | `RenderUI` 执行时 `GraphicsContext` 是开着的；`SwitchRenderer` 内部的 `Shutdown`/`Initialize` 会提交自己的命令列表（`InitializeBuffer` 甚至 `Finish(true)`），在已打开的命令列表里再开上下文会打乱录制。 |
| Q3 | 注册表为空的真正原因是什么？ | `RendererAutoRegister<T>` 是 `DeferredRenderer.cpp` / `ForwardRenderer.cpp` 里的文件级静态对象，这两个 .obj 在静态库里；Demo 的 `dynamic_cast` 不 odr-use 任何符号，链接器不把它们从库里拉出来，静态初始化器从未运行。 |
| Q4 | `RESOURCE_BARRIER_INVALID_HEAP` #741 是怎么触发的？ | `CommandContext::CopyBufferRegion` 无条件对**源**资源发 `COPY_SOURCE`，而 `WriteBuffer`/`FillBuffer` 的源是 `LinearAllocator` 的 UPLOAD 堆页面；UPLOAD/READBACK 堆资源状态固定，不能转换。修法是 `TransitionResource` 对这两种堆早退。 |
| Q5 | 运行时换模型后模型为什么消失？ | `ModelInstance::operator=` 重建了 MeshConstants 缓冲但没置 `m_IsDirty`；`Update` 的第二守卫 `if (!m_IsDirty) return;` 让上传从未发生，WorldMatrix 是垃圾 → 顶点退化成零面积三角形。 |
| Q6 | `LightingSystem::ApplyParams` 为什么用 `WriteBuffer` 而不是 `InitializeBuffer`？ | `InitializeBuffer` 内部 `Finish(true)` 强等 GPU，不能每帧调；`WriteBuffer` 走 CPU 线性分配区 + `CopyBufferRegion`，配合 `TransitionResource(COPY_DEST)` / `(GENERIC_READ)`。 |
| Q7 | Debug View 分支为什么放在曝光与 ACES 之前？ | 若先过曝光/tonemap，数值会被压扁，看不出 GBuffer 的真实内容（例如 Depth 会被 tonemap 拉伸）。 |
| Q8 | `-Screenshot` 的目录为什么要用反斜杠？ | `SaveToWICFile` 拿到被正斜杠污染的路径会返回 `ERROR_INVALID_NAME (0x8007007B)`；日志里路径会被截断成 `D;F:\DSH\...`。 |
