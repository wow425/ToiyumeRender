# TR-20261026-04：窗口全黑与点击闪退修复

- 日期：2026-10-26
- 阶段：运行时缺陷修复
- 状态：**DONE**（用户实机确认正常显示）
- 分支/基线提交：master @ 51c09d0

## 1. 结论

VS 里启动 RendererDemoApp 窗口全黑、点击闪退的问题已修复。
根因是 `PreparePresentSDR` 的格式校验过严，把 `R8G8B8A8_TYPELESS`(27) 与
`R8G8B8A8_UNORM`(28) 判为不匹配，导致**每一帧都在拷贝前 return**，
`Present` 从未执行。失败日志又因是 `LOG_TRACE` 被编译成空语句，所以完全静默。

实测：修复前 12 秒内 `Present skipped` **2196 次**，修复后 **0 次**；
窗口正常显示（用户确认）。

技术文档：`docs/AI/R4/R4.2_窗口全黑修复.md`

## 2. 施工前状态与证据

- 现象：窗口全黑，点击退出（返回码 0），日志无任何错误
- GPU 回读截图：**完全正常**（模型/天空/IBL 都对）
- → 问题被切分为「渲染无罪，呈现断裂」

诊断关键一步：发现失败信息用的是 `LOG_TRACE`，
而它在非 `TOOIYUME_VERBOSE_LOG` 下是 `do{}while(0)`，**被编译器删除**。
临时提到 `LOG_INFO` 后立刻拿到：

```
scene=1920x1080 fmt=27  backbuffer=1920x1080 fmt=28
```

## 3. 根因

`PixelBuffer::DescribeTex2D` 有意把资源格式归一化为 TYPELESS：

```cpp
Desc.Format = GetBaseFormat(Format);  // UNORM → TYPELESS
```

但 `PreparePresentSDR` 用枚举字面相等校验，于是 `27 != 28` 恒真，
每帧 return。二者位布局相同，`CopyResource` 本来合法。

## 4. 修复

`Engine/01_Application/Display.cpp`：

1. 格式校验改为「位布局家族兼容」（R8G8B8A8 / B8G8R8A8 / R16G16B16A16 / R16G16 / R32）
2. 宽高仍严格相等（`CopyResource` 硬约束）
3. 未知格式回落严格比较，不因放宽而掩盖问题
4. 失败日志 `LOG_TRACE` → `LOG_INFO`
5. `Present()` 增加 HRESULT 检查，失败时打印

## 5. DX12 专项

### 5.1 资源状态

`PreparePresentSDR` 中的状态机未改动：
SceneColor `COPY_SOURCE` → backbuffer `COPY_DEST` → `PRESENT`。修复后首次真正执行，
Debug Layer 0 ERROR，说明这条状态链本身是正确的。

### 5.2 格式与资源描述

`D3D12_RESOURCE_DESC::Format` 反映的是**创建时**的格式（TYPELESS），
而视图（RTV/SRV）可以有具体格式。做资源间比较时必须区分：

- **位布局**（能否 CopyResource / 能否别名）→ 按家族比较
- **视图格式**（采样时如何解释 / 是否 sRGB 解码）→ 必须精确

本次踩的是前者，原先却按后者（精确相等）处理。

### 5.3 无 Barrier / Fence 改动

不适用：本次只修正了一个 CPU 侧的早退条件。

## 10. 方法论教训（重要）

上一轮我把「GPU 回读正常」当作「功能完成」，这是**错误的验证方法**：

```
GPU 回读  → 只经过 Render() 后的 SceneColor，不经过 PreparePresentSDR / Present
窗口可见  → 必须经过 CopyResource → backbuffer → Present
```

两者是**不同的链**，前者正常不代表后者正常。本轮正是这样漏掉的。

今后渲染类验收必须**分层**：

| 层 | 手段 |
|---|---|
| 渲染 | GPU 回读截图 + 像素统计 |
| 呈现 | 窗口可见性 + `Present` 返回值/跳过计数 |
