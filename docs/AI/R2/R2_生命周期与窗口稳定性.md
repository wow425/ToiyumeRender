## 2. 关键实现点

### 2.1 Resize 转发链
```
WM_SIZE → GameCore::OnWindowResize → Display::Resize(w,h)
                                    → 重建 swapchain/backbuffer/DSV
                                    → ResizeDisplayDependentBuffers()
                                    → g_GameApp->OnResize(w,h)
                                    → Renderer::OnResize 重建 RT + 重绑 SceneColorBuffer
```

### 2.2 长宽比语义（重要）
`Camera::SetAspectRatio` 的参数是 **height/width**，不是通常的 width/height。
投影以 fovY 为竖直基准，因此竖屏（height>width）→ aspect>1 → 视野变窄；横屏 → aspect<1 → 视野变宽。
\`\`\`cpp
// Camera.h
float m_Aspect = 9.0f / 16.0f;  // = height / width
void SetAspectRatio(float aspect) { m_Aspect = aspect; }
// 投影：PerspectiveFov(fovY, 1.0f/aspect) → width/height
\`\`\`

### 2.3 0 尺寸保护
Resize 期间 `WM_SIZE` 会收到 0×0（最小化）。此时提前返回，避免 `CreateForwardBufferTargets` 分配 0 尺寸 RTV 后 `Destroy` 空指针。

## 3. 验收证据

### 3.1 自测开关
Demo 增加 `-ResizeTest`（R2 长宽比自测）与 `-ResizeStress`（压力），位于 `DeferredApp.cpp`。

### 3.2 长宽比遍历（`-ResizeTest`）
真实触发 6 次 `Display::Resize`，日志确认：
```
[R2] OnResize 900x600
[R2] OnResize 1400x500
[R2] OnResize 600x900
[R2] OnResize 1600x400   ← 4:1 极端宽幅
[R2] OnResize 400x800    ← 竖屏
[R2] OnResize 1920x1080
```
6 张截帧 `resize_*.png` 均为 **原始分辨率**（未等比填充黑边），内容无拉伸：
- `1600x400`：宽幅下人物比例正常，说明横向视野随窗口变化
- `400x800`：竖屏下横向视野收窄，**证明 aspect 语义（h/w）方向正确**

### 3.3 最小化/还原与压力
`-ResizeStress` 连续 100 次 resize，日志无 `DXGI_ERROR`、无断言、Debug Layer 无 RTV 维度或资源状态错误。

### 3.4 二次调试确认的坑
- **可变参数表默认读全零**：C++ 可变参数 `va_arg` 在无参数时读出 0 而非调用点常量，导致 `-Width` 解析得到 `(0,0,5.00)`。这正是执行表第 3 条经验的复现；Demo 的 width/height 因此不从命令行读，而固定 1920x1080。
- **`-Width` 参数并不存在**：初测以为“参数没生效”，查证发现代码根本没有该参数，属于误判而非缺陷。
