## 5. 耦合风险与重复实现（每条带证据）

### 5.1 【内存泄漏·确定】烘焙期 `malloc` 的 Mesh 块从不释放

- 分配：`Mesh* mesh = (Scene::Model::Mesh*)malloc(sizeof(Scene::Model::Mesh) + sizeof(Scene::Model::Mesh::Draw) * (numDraws - 1));` — ModelConvert.cpp:86
- 移交：`meshList.push_back(mesh);` — ModelConvert.cpp:155（`meshList` 就是 `ModelData::m_Meshes`，ModelLoader.h:32）
- 搜证：`m_Meshes` 在 `Engine/05_Scene` 仅 ModelLoader.h:32 一处；`Engine/05_Scene/Model` 目录 `delete`/`free(` **0 命中**；`Engine/03_AssetSystem` 内只有 ModelConvert.cpp:86 的 `malloc` 与 IndexOptimizePostTransform.cpp:266 的 `delete[] indexSorted`。
- 后果：每次烘焙泄漏 `numMeshes × (sizeof(Mesh) + (numDraws-1)×sizeof(Draw))`。烘焙是一次性路径，量级可控，但**是真实泄漏**，且 `ModelData` 无析构函数意味着以后新增任何 `new` 都会继续累积。

### 5.2 【强耦合·确定】两套纹理槽位枚举，靠人工同步

- 定义 1：`glTF.h`:140-141 `enum { kBaseColor, kMetallicRoughness, kOcclusion, kEmissive, kNormal, kNumTextures };` + `static_assert(kNumTextures==5)`
- 定义 2：ConstantBuffers.h:34-45 同一组名字 + 同一个 `static_assert(kNumTextures==5)`
- 第三方：GBufferPS.hlsl:3-7 的 t0..t4 **只能靠注释**约束。
- 风险机制：两处断言都只检查**数量 == 5**。若有人把 glTF.h 的枚举顺序改成 `{BaseColor, Normal, …}` 而数量不变，**两个 static_assert 都通过**，但 `TextureOptions` 的 sRGB 标志与默认贴图会整体串槽 —— 这正是 ConstantBuffers.h:20-33 注释里记录过的历史事故（"sRGB 标志与默认贴图整体串槽"），修复手段是让导入层显式用 `glTF::Material::kBaseColor` 限定名（ModelConvert.cpp:355-357 注释）。

### 5.3 【重复实现·确定】同一份数据三套结构 + 两套解码入口

| 重复项 | 位置 A | 位置 B | 说明 |
|---|---|---|---|
| 材质常量布局 | ConstantBuffers.h:48-77 `MaterialConstants`（`alignas(256)`，`alphaRef:16`） | Material.h:38-47 `MaterialConstantData`（"Unaligned mirror"，无 `alignas`，44B） | 靠 `memcpy` 44B 对齐（ModelLoader.cpp:371-373）；两处**都没有 offsetof 断言** |
| 材质标志位域 | glTF.h:118-135 `alphaCutoff:16` | ConstantBuffers.h:74 `alphaRef:16` | 位位置必须一致，靠 ModelConvert.cpp:306 原样搬 `flags` |
| DDS 解码 | TextureManager.cpp:151-188 `ManagedTexture::CreateFromMemory`（**在用**） | Texture.cpp:188-197 `Texture::CreateDDSFromMemory`（**0 调用者**） | 两处各自调 `CreateDDSTextureFromMemory` 并各自管描述符 |
| TGA 解码 | Texture.cpp:136-186 **手写 TGA 头解析**（`filePtr+=2`、读 `width/height/bitCount`、`new uint32_t[w*h]`） | TextureConvert.cpp:71-79 DirectXTex `LoadFromTGAFile` | 两套独立实现，手写那套无人调用 |
| GlobalConstants 构造 | ForwardRenderer.cpp:231-236 | DeferredRenderer.cpp:363-368 | 两份逐字段赋值，字段增删要改两处（注释互相引用 R1.7，说明已经因为漏改出过事） |
| Camera 契约 | Camera.h:27-33 | LightingPS.hlsl:63-69 | 中间只有注释，无共享头、无断言 |

### 5.4 【状态不一致·INFERRED】纹理 SRV 表偏移没有代际校验，采样器有

- 采样器侧：ModelLoader.cpp:18-32 定义 `SamplerCacheEntry{generation, offset}`；:177-183 命中判定要求 `generation == s_SamplerHeap.GetGeneration()`。注释解释得很清楚：切 Renderer 时 `s_SamplerHeap.Destroy()+Create()` 会把游标归零，旧 offset "碰巧"仍落在合法范围却指向别的采样器，"不会崩溃、不会报错，只会让贴图采样模式静默错掉"。
- 纹理侧：ModelLoader.cpp:103-104 `s_TextureHeap.Alloc(kNumTextures)` 得到的 `SRVDescriptorTable` **直接写进 `Material::SRVTable`**（:192-193、:206-207），**没有任何代际字段**。同样的 Destroy+Create 之后，`Material::SRVTable` 会指向新堆里的另一段描述符。
- 等级：INFERRED —— 只读到注释说明堆会重建，**没有运行验证切 Renderer 后画面是否错乱**；但同一文件里"采样器需要代际、纹理不需要"这种不对称本身即为风险。

### 5.5 【顺序耦合·确定】BuildMaterials 先跑且不可回滚

- `BuildModel` 第一行就是 `BuildMaterials(model, asset);`（ModelConvert.cpp:414），而 `BuildMaterials` 在 :395 立即 `CompileTextureOnDemand`（**写盘**）。
- 随后 `const glTF::Scene* scene = …; if (scene == nullptr) return false;`（:418-420）—— 此时纹理已编译、`ModelData` 已部分填充，失败返回不清理。
- 调用方 `LoadModel` 在 `!BuildModel(...)` 时 `return nullptr`（ModelLoader.cpp:309-310），`modelData` 析构，但磁盘上的 .dds 已产生。
- 后果：烘焙失败会留下"孤儿 DDS"，下次 `CompileTextureOnDemand` 因 mtime 更新而跳过重编，可能用上错误选项的贴图。

### 5.6 【未闭环·确定】描述符堆只分配不回收

- `s_TextureHeap.Free` / `s_SamplerHeap.Free` **全仓 0 命中**（grep Engine+Demos）。
- 分配点：ModelLoader.cpp:103（每模型 5 个 SRV）、:185（每采样器组合 5 个）、ForwardRenderer.cpp:370、DeferredRenderer.cpp:549（各 1 个）。
- 后果：反复换模型/换 Renderer 时 SRV 堆单调增长，只有整堆 `Destroy` 才能回收。
- 相关：`ManagedTexture` 自己那份描述符有 `Free`（TextureManager.cpp:198-206），但 **`LoadMaterials` 拷进去的那份（:103/:166）没有**。
