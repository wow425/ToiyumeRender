## 5. 代表性模块分析：DeferredRenderer（对应任务卡要求 ③）

**为什么选它**（选择理由要说清，否则「代表性」是空的）：它是全仓唯一同时满足三点的模块——① 有完整可运行的 GPU 提交路径（`DrawIndexed` + `Draw(3,0)`）；② 有可验证的失败模式（6 段空壳、能力位虚报）；③ 处于架构迁移的枢纽位置（`RendererRegistry` 三个 Renderer 之一，下游连着 BufferManager / LightingSystem / EnvironmentLightingManager / TextureManager）。

### 5.2 关键机制（三条，逐条给证据）

**(1) 排序-批处理机制。** `MeshSorter` 用 `SortKey` union 把 `objectIdx:16 | psoIdx:12 | key:32 | passID:4` 压进 64 位（`BaseRenderer.h:124-137`），按 key 排序后顺序提交以减少状态切换。`DeferredRenderer::Update` **每帧** `DefaultSorter.Reset()` 再重新 `AddMesh`（`:207-247`，注释里明确写了「每帧重建 vs 只在 dirty 追加」的取舍与被否方案 B）。`Reset()` 不清 `m_CurrentPass`（`BaseRenderer.cpp:26-32`）——这是已知缺陷（03 报告 §6 状态 2）。

**(2) 根签名-描述符表分离机制。** GBuffer 根签名有 7 个根参数（`kMeshConstants` CBV b0 VS / `kMaterialConstants` CBV b0 PS / `kMaterialSRVs` SRV 0..10 / `kMaterialSamplers` Sampler 0..10 / `kCommonSRVs` SRV t10..t20 / `kCommonCBV` CBV b1），静态采样器槽 10，`DeferredRenderer.cpp:552-576`。Lighting 另有一套 10 槽描述符表（`DeferredRenderer.h:63-77 LightingSlot`）。**两套根签名并存**，是 Deferred 与 Forward 唯一真正不同的架构点。

**(3) 状态迁移-重建机制。** `OnResize` 先改 viewport/scissor（`:146-172`），再 `if(!m_Initialized) return`（`:174`），然后 `IdleGPU()`（`:194`，注释记录了「拉伸窗口闪退」的真实根因：Display::Resize 的 IdleGPU 只等调用前提交的工作，而 OnResize 释放的 RT 仍被上一帧命令列表引用 → Debug Layer 断言 → `CRT abort 2170`），最后 `DestroyDeferredBufferTargets()` + `CreateDeferredBufferTargets()`（`:196-197`）。
