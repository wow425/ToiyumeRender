# docs/AI — AI 施工档案目录

本目录收录所有 **AI 参与本项目产生/维护的文档**。按「文档的作用」分子目录，不按时间、不按人。

## 目录约定

| 子目录 | 收录什么 | 不收录什么 |
| --- | --- | --- |
| `worklogs/` | 每一次施工的工作日志：`TR-YYYYMMDD-NN_<slug>.md`。记录改了什么、为什么改、验证到哪一层、哪些未验证。 | 一次性排查草稿、临时脚本输出 |
| `guides/` | 面向人的教程、操作手册、踩坑总结（如光追管线教程）。 | 施工过程记录 |
| `architecture/` | 工程结构、模块职责、数据流、构建布局等**稳定结论**的说明。 | 未定稿的设计草案 |
| `reviews/` | 阶段性审计、代码复查、问题清单与整改跟踪。 | 日常施工日志 |

## 命名

- 工作日志：`TR-YYYYMMDD-NN_<slug>.md`（`NN` 为当日序号，两位）
- 其余：`<主题>_<可选日期>.md`，用下划线分词，体现「这是什么」

## 硬规则

1. **新建文件前先决定它属于哪一类**；四类都不像，说明它不该放在 `docs/AI`。
2. 工作日志必须写明 **基线**（起点 commit 或状态）与 **验证层级**；未验证项必须显式列为「未验证」，不得留白也不得写成已通过。
3. 状态用词只有：`DONE` / `IMPLEMENTED_UNVERIFIED` / `PARTIAL` / `BLOCKED` / `REJECTED`。
4. 涉及代码的结论必须带 `路径:行号`。
5. `docs/AI` 之外的仓库文档（如根 `README.md`）保持原位置，不被本目录吸收。
