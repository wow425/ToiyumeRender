## 2. 需求 1：鼠标视角

### 根因

`GameInput::KbmUpdate` 里：

```cpp
if (!s_KbmReady)
{
    memset(&s_MouseState, 0, sizeof(s_MouseState));   // ← 鼠标位移永远为 0
    return;
}
```

`s_KbmReady` 依赖 DirectInput8Create 成功。**本机实测该调用失败**，于是走这条分支，
每一帧都把 `s_MouseState` 清零。键盘因为还有 Win32 消息通路（`NotifyWin32Key`）能用，
唯独鼠标彻底没有数据来源 —— 表现为「拖鼠标，视角纹丝不动」。

### 修复

用 Win32 的 `GetCursorPos` 求相邻帧差分作为后备：

```cpp
POINT pt = {};
if (::GetCursorPos(&pt))
{
    if (s_LastCursorPosValid)
    {
        s_MouseState.lX = pt.x - s_LastCursorPos.x;
        s_MouseState.lY = pt.y - s_LastCursorPos.y;
    }
    s_LastCursorPos = pt;
    s_LastCursorPosValid = true;
}
```

同时用 `GetAsyncKeyState(VK_LBUTTON/...) ` 补上鼠标按键状态。

**已知限制**：没有独占捕获，光标撞到屏幕边缘后不再产生位移。
彻底解决需要 `ClipCursor` 或让 DirectInput 正常工作。

### 顺带改进：改成「按住左键拖动」

`CameraController::Update` 原本无条件累加鼠标位移，导致：
1. 鼠标划过 ImGui 面板时相机乱转
2. 无法区分「操作 UI」与「控制相机」

改为编辑器常见约定 —— **按住左键才转视角**，并用 `WantCaptureMouse` 在
鼠标悬停 UI 时屏蔽：

```cpp
const bool leftDown     = GameInput::IsPressed(GameInput::kMouse0);
const bool uiWantsMouse = Renderer::ImGuiLayer::WantCaptureMouse();

if (leftDown && !uiWantsMouse)
{
    yaw   += GameInput::GetAnalogInput(GameInput::kAnalogMouseX) * m_MouseSensitivityX;
    pitch += GameInput::GetAnalogInput(GameInput::kAnalogMouseY) * m_MouseSensitivityY;
}
```

## 3. 需求 2：#820 清屏值不匹配

### 根因

D3D12 要求 `ClearRenderTargetView` 使用的清屏值与资源**创建时**的
`D3D12_CLEAR_VALUE` 一致。而 `ColorBuffer::Create` 内部：

```cpp
D3D12_CLEAR_VALUE ClearValue = {};
ClearValue.Color[0] = m_ClearColor.R();   // ← 此刻 m_ClearColor 还是默认全 0
...
CreateTextureResource(..., ClearValue, ...);   // 固化到资源上
```

`ForwardRenderer` 却在 **Create 返回之后**才 `SetClearColor(0.10, 0.12, 0.16, 1.0)`：

```cpp
m_ForwardBuffer->SceneColorBuffer[0] = BufferManager::CreateColorBuffer(...);  // 清屏值 = 0
m_ForwardBuffer->SceneColorBuffer[0]->SetClearColor(Color(0.10f, 0.12f, 0.16f, 1.0f));  // 太晚
```

事后改成员变量只影响 CPU 侧读取，**改不动已创建资源的描述**。
于是每帧 `ClearRenderTargetView` 都报 #820，并走驱动慢路径。

### 修复

把清屏色改成**创建参数**：

```cpp
static std::shared_ptr<ColorBuffer> CreateColorBuffer(
    const std::wstring& name, uint32_t width, uint32_t height,
    DXGI_FORMAT format, uint32_t mipCount = 1,
    const Color* clearColor = nullptr);   // ← 新增
```

```cpp
if (clearColor != nullptr)
    buffer->SetClearColor(*clearColor);   // 必须在 Create 之前
buffer->Create(...);
```

## 4. 需求 4：Deferred 拉伸窗口闪退（本轮最难）

这是**三个独立缺陷叠加**的结果，排查过程中每修一个就露出下一个。

### 4.1 缺陷 A：GpuTimer 用断言终止进程

崩溃栈（cdb 抓取）：

```
Renderer::GpuTimer::TryGetElapsedMs+0x159
RendererDemoApp::Update+0x171
GameCore::UpdateApplication
```

**与渲染资源生命周期毫无关系** —— 是 GPU 计时器的回读 Map 失败后
用 `ASSERT(false)` 结束进程。

正确语义：GPU 计时是**可选诊断功能**，拿不到样本就跳过这一帧
（调用方本来就处理 `return false`），绝不能因此让渲染器崩溃。

同类问题还有 `GpuTimer::Begin` 里的「上次 Begin 没配对 End」断言 ——
Resize 期间 Present 早退会导致 End 不被调用，下一帧 Begin 就命中断言。

### 4.2 缺陷 B：ResizeBuffers 的 flags 与创建时不一致

```
ResizeBuffers FAILED hr=0x887A0005  (DXGI_ERROR_DEVICE_REMOVED)
```

创建时：`swapChainDesc.Flags = DXGI_SWAP_CHAIN_FLAG_ALLOW_MODE_SWITCH`
Resize 时：`ResizeBuffers(..., 0)`   ← flags 不一致

DXGI 要求两者一致。前几次 resize 在驱动容忍范围内勉强成功，
累积到某一点后设备被移除 —— 这解释了「有时能过几次才崩」的间歇性。

### 4.3 缺陷 C：Resize 后未重新查询 backbuffer 索引

这是最终的 `DEVICE_REMOVAL #232` 直接原因：

```
DXGI_ERROR_ACCESS_DENIED: The application attempted to use a resource
it does not access to. This could be, for example, rendering to a texture
while only having read access. [ EXECUTION ERROR #232 ]
```

`ResizeBuffers` 会重建全部 backbuffer，DXGI 的「当前可写索引」随之改变，
但 `g_CurrentBuffer` 仍是 resize 前的值。下一帧对错误索引的 buffer 发
`COPY_DEST` 屏障 —— 而它实际处于 `PRESENT` 状态，GPU 判定为非法访问。

修复：

```cpp
g_CurrentBuffer = s_SwapChain1->GetCurrentBackBufferIndex();
```

### 4.4 还修了一处防御

`PreparePresentSDR` 里 `SceneColorBuffer.GetResource()->GetDesc()` 没有判空。
`SceneColorBuffer` 是 `shared_ptr`，Resize 期间**对象还活着但底层资源已 Destroy**
（`m_pResource` 被置空）—— 只看指针非空会漏掉这种情况。

## 5. 需求 5-7：编辑器 UI 能力

### 5.1 恢复默认值（Material/Lighting）

```cpp
void ResetToDefaults(void) { *this = RenderParams{}; }
```

**为什么用整体赋值而不是逐字段写**：`RenderParams` 有十几个字段且还会增加。
逐字段手写每加一个就要记得同步，漏掉的那个永远恢复不了 —— 而且只有用户按
Reset 时才会撞上，极难发现。整体赋值天然与字段定义保持同步。

不需要额外通知 GPU：`LightingSystem::ApplyParams` 每帧做 memcmp，
参数一变就自动重传。

### 5.2 多模型场景（Scene/Model）

**架构变更**：`ModelInstance m_Model` → `std::vector<SceneModel>`。

三个关键设计决策：

**(a) 为什么用 `unique_ptr` 持有 ModelInstance**

`ModelInstance` 内含 `UploadBuffer` / `ByteAddressBuffer` / `unique_ptr<AffineTransform[]>`，
**没有拷贝赋值**。而 `std::vector` 扩容要求元素可移动或可拷贝 ——
直接放值类型会让 `vector<SceneModel>` 编译失败（本轮实际踩到）。
用 `unique_ptr` 后元素只是指针，可自由移动，生命周期仍由容器独占。

**(b) 为什么增删必须在帧边界执行**

`RenderFrameDesc.Models` 里放的是 `ModelInstance` 的**元素指针**。
若在 ImGui 回调里直接改 `m_SceneModels`，vector 扩容会让这些指针失效，
下一帧渲染就读到已释放内存。

因此 UI 只登记 `m_PendingAddModelIndex` / `m_PendingRemoveModel`，
由 `ApplyPendingActions`（帧首）真正执行。

**(c) 位置拖动为什么可以立即生效**

它只改 `ModelInstance` 内部的 `m_Locator` 并置脏，不改变容器结构、
不涉及 vector 扩容、不涉及 GPU 资源增删 —— 没有上述隐患。

```cpp
void ModelInstance::SetWorldPosition(const Vector3& position)
{
    const Scalar scale = m_Locator.GetScale();
    const Vector3 localCenter = m_Model->m_BoundingSphere.GetCenter();
    m_Locator.SetTranslation(position - localCenter * scale);
    m_IsDirty = true;   // 必须置脏，否则 Update 的门控会让改动不生效
}
```

注意语义：设置的是**包围球中心**的位置，不是模型原点。本地空间的原点与
包围球中心通常不重合（美术导出常带偏移），直接设 translation 会让模型
偏离鼠标位置一个「本地中心偏移 × 缩放」的量。

**GPU 生命周期**：删除模型时必须先 `IdleGPU()`，否则上一帧的命令列表
仍在读被删模型的缓冲，命中 D3D12 #921 `OBJECT_DELETED_WHILE_STILL_IN_USE`。

### 5.3 Feature 开关（Renderer）

与 DevTools 的 sRGB encode 走**同一套机制**：

```
UI  →  RenderParams（唯一 CPU 真源）  →  RenderFrameDesc::Params  →  渲染器
```

UI 侧不做任何缓存，渲染器每帧从参数读。

**诚实标注**：`DeferredRenderer::Render` 里 Shadow / SSAO / Transparent /
PostProcess 这四段**目前只有 PIX 事件、没有 GPU 命令**。所以面板逐项标注
`[stub: no GPU commands yet]` —— 打开它们不会改变画面。

这不是"假控件"：开关本身的接线是正确的，等对应 Pass 实现后无需改动就会生效。
路线图明确禁止"拨了没反应却不说"的 UI，所以标注是必须的。

## 7. 学到什么

### 7.1 断言不是错误处理

本轮最大的教训。`GpuTimer` 里两处 `ASSERT(false, ...)` 直接导致了
「拉伸窗口闪退」。它们本该是**可恢复的功能降级**（跳过这一帧采样），
却被写成了**进程终止**。

判断标准：**这个失败是否影响核心功能？**
- 影响（资源创建失败、状态机错乱）→ 断言/终止合理
- 不影响（性能统计拿不到样本）→ 必须降级

### 7.2 「间歇性」崩溃往往意味着状态累积

`ResizeBuffers` 的 flags 不一致不是每次都崩，而是「过几次才崩」。
这类现象要优先怀疑：某个值只在下一次操作才生效、某个计数器没复位、
或驱动有容忍阈值。**不要因为"这一把没崩"就认为修好了。**

### 7.3 一个症状可能由多个缺陷叠加

本轮 4 号需求修了 4 个缺陷才彻底解决。每修一个就露出下一个 ——
如果只修第一个就宣布完成，用户下次 resize 还是崩。

**验证必须跑到底**，而且要重复多次（间歇性问题尤其如此）。

### 7.4 容器的指针失效是隐蔽炸弹

`RenderFrameDesc.Models` 存 `ModelInstance*`，而 `vector` 会扩容搬移元素。
这类问题不会在编译期暴露，运行时表现为「偶发的野指针」或「模型消失」。

规避方式：**改容器的操作全部集中到帧边界**，渲染期间只读不写。

### 7.5 类型系统可以提前拦住这类错误

`ModelInstance` 没有拷贝赋值这件事，是编译器帮我发现的（`vector` 编译失败）。
如果当初写成裸指针数组，这个约束就消失了，运行时的隐患反而更多。
**让编译期替你发现约束，比运行时调试便宜得多。**
