## §1 职责边界

### 1.1 负责什么 [实测]

1. **HDR 域内链**：TAA/FSR2 → Underwater → 自定义(BeforeTonemap) → DoF → MotionBlur。每个效果是一个自由函数，函数体里自带全部 GPU 状态（BindComputeShader / BindResource / BindUAV / PushConstants / Barrier / ClearUAV / Dispatch / EventBegin-End）。`wiRenderPath3D.cpp:2347-2460` [实测]
2. **HDR→LDR 跨界三件套**：`ComputeLuminance`（眼适应，产出 luminance buffer）、`ComputeBloom`（泛光，产出 mipchain 纹理）、`Postprocess_Tonemap`（曲线/调色/抖动）。三者不是链上三个独立 pass：前两者的**产物**被 tonemap 当输入纹理/buffer 用，渲染只发生在 tonemap 那一次 dispatch 里。`wiRenderPath3D.cpp:2462-2505`、`shaders/tonemapCS.hlsl:131-147` [实测]
3. **LDR 域内链**：Sharpen → FXAA → ChromaticAberration → CRT，四个各自一次 dispatch。`wiRenderPath3D.cpp:2508-2533` [实测]
4. **GUI 背景模糊**：Downsample4x ×2 + Blur_Gaussian(wide=true)，独立于主链，输出到 rtGUIBlurredBackground。`wiRenderPath3D.cpp:2545-2558` [实测]
5. **统一线程粒度**：除 blur 外所有 CS 都是 `[numthreads(8,8,1)]`，dispatch 尺寸一律 `(w+7)/8, (h+7)/8`。`shaders/ShaderInterop_Postprocess.h:5` [实测]

### 1.2 不负责什么 [实测]

1. **不管 RT 的创建/尺寸/格式/别名**：rtMain、rtPostprocess 在 `wiRenderPath3D.cpp:111-172` 建立并注册进 aliasing allocator（`Add({&desc_rtPostprocess,&desc_rtPrimitiveID,&desc_rtSceneCopy})`）；链层切换时只插一次 `GPUBarrier::Aliasing(&rtPrimitiveID, &rtPostprocess)`。`wiRenderPath3D.cpp:164,171,2346` [实测]
2. **不管 ping-pong**：效果函数签名里只有 `const Texture& input` / `const Texture& output`，完全不知道自己在链的第几环；交替由调用方 `rt_read`/`rt_write` + `std::swap(rt_read, rt_write)` 手工完成。`wiRenderPath3D.cpp:2342-2343,2493-2494` [实测]
3. **不管效果顺序**：代码里不存在"后处理链"对象或描述表，顺序就是 RenderPath 里一串硬编码 `if`。`wiRenderPath3D.cpp:2470-2533` [实测]
4. **不做跨 pass 全局同步规划**：没有统一的 barrier 批处理，每个 Postprocess_* 自己按需 Barrier；链层只在 pass 边界插 Alias barrier。`wiRenderer.cpp:17133-17141` [实测]
5. **不登记 bindless 依赖**：TAA 用了 `texture_velocity`、`texture_depth_history`、`texture_lineardepth`、`texture_depth`，但 `Postprocess_TemporalAA` 自己一个都没绑 —— 它们来自 globals.hlsli 的 bindless 宏（从 `GetCamera()` 的 descriptor index 取），由 `wi::renderer::BindCommonResources` 铺好。`wiRenderPath3D.cpp:2364-2370`、`shaders/globals.hlsli:787,789` [实测]
6. **不负责 jitter 生成**：`camera->jitter` 由 RenderPath 用 halton 序列填（TAA 与 FSR2 两条分支），效果函数只消费。`wiRenderPath3D.cpp:424-438` [实测]
7. **不负责 GUI/着色器编译**：CSTYPE_* 的 .cso 在 `LoadShaders` 里并行加载。`wiRenderer.cpp:1104-1135` [实测]


## §2 关键类型与数据结构

### 2.1 通用 push-constant 结构（被十几个效果共用）

```hlsl
struct PostProcess                      // ShaderInterop_Postprocess.h:9-15，32 字节
{
    uint2  resolution;                  // 目标分辨率（像素）
    float2 resolution_rcp;              // 1/resolution
    float4 params0;                     // 语义随效果改变，靠 #define 起别名
    float4 params1;
};
```
- 别名表（同一结构，不同效果读不同字段）：`shaders/ShaderInterop_Postprocess.h:22-28,40-41,44-52` [实测]
  - 眼适应：`luminance_adaptionrate=params0.x`、`luminance_log_min=params0.y`、`luminance_log_max=params0.z`、`luminance_log_range=params0.w`、`luminance_log_range_rcp=params1.x`、`luminance_pixelcount=params1.y`、`luminance_eyeadaptionkey=params1.z`
  - Sharpen / Chromatic：`params0.x` = amount
  - TAA：`params0.x` = first_frame 标志（1.0=首帧）
  - Upsample_Bilateral：`params0.x`=threshold、`params0.w`=in.w/out.w 缩放比、`params1.xy`=输入尺寸、`params1.zw`=输入尺寸倒数
  - Gaussian/Bilateral blur：`params0.xy`=方向向量（1,0 或 0,1）
  - Downsample4x：`params0.x` = hdrToSRGB 开关
- **含义**：WE 没有"每效果一个 CB"，而是"一个 32B 的 push constant + 每效果自己的 #define 视图"。`shaders/ShaderInterop_Postprocess.h:9-15` [实测]

### 2.2 tonemap 专用 push-constant [实测]

```hlsl
struct PushConstantsTonemap             // ShaderInterop_Postprocess.h:136-150，48 字节
{
    float2 resolution_rcp;
    uint2  exposure_brightness_contrast_saturation; // 打包成 2 个 half4（4 个 half）
    int texture_input;                  // bindless SRV 索引（-1 = 未绑定）
    int buffer_input_luminance;
    int texture_input_distortion;
    int texture_colorgrade_lookuptable;
    int texture_bloom;
    int texture_output;                 // bindless UAV 索引
    int texture_input_distortion_overlay;
    uint flags_hdrcalibration;          // 低 16 位 = TONEMAP_FLAGS，高 16 位 = half(hdr_calibration)
};
```
- 4 个连读参数（exposure/brightness/contrast/saturation）被压进 **一个 uint2**：CPU 侧 `XMHALF4 e(exposure,brightness,contrast,saturation)`，再把两个 32 位 half 各塞进 x/y；shader 侧 `unpack_half4` 还原。`wiRenderer.cpp:17377-17381`、`shaders/tonemapCS.hlsl:102-106` [实测]
- `hdr_calibration` 是 half，被塞进 flags 的高 16 位（`XMConvertFloatToHalf(hdr_calibration) << 16u`）。`wiRenderer.cpp:17405` [实测]
- 开关枚举：`TONEMAP_FLAG_DITHER=1<<0`、`ACES=1<<1`、`SRGB=1<<2`、`UCHIMURA=1<<3`。`shaders/ShaderInterop_Postprocess.h:129-135` [实测]
- 所有纹理/缓冲输入都是 **bindless 索引（int）**，-1 表示未绑定；shader 侧用 `[branch] if (idx >= 0)` 判断。`shaders/tonemapCS.hlsl:110-134` [实测]

## §4 算法与公式

### 4.1 tonemap 的 8 步内部流水（Q2 主答）[实测]

`tonemapCS.hlsl` 的 main 是一个严格线性序列，**8 类效果塞进同一个 CS**，靠 bindless 索引是否为 -1 + flags 位来分支：

| 步 | 操作 | 代码 | 位置 |
| --- | --- | --- | --- |
| 0 | `uv = (DTid.xy + 0.5) * resolution_rcp`，再按 scissor 剔除 | `if(!GetCamera().is_uv_inside_scissor(uv)) return;` | `shaders/tonemapCS.hlsl:97-100` |
| 1 | 解包 4 个 half：exposure/brightness/contrast/saturation；flags 取低 16 位，hdr_calibration 取高 16 位 | `unpack_half4(...)`, `f16tof32(flags>>16u)` | `shaders/tonemapCS.hlsl:102-108` |
| 2 | **distortion 重投影**：用 distortion 贴图的 rg 加偏移；overlay 版再乘 2 减 1 | `uv += tex.SampleLevel(...).rg;` / `*2-1` | `shaders/tonemapCS.hlsl:110-120` |
| 3 | 采样 input（half4） | `bindless_textures_half4[...].SampleLevel(sampler_linear_clamp, uv, 0)` | `shaders/tonemapCS.hlsl:124-128` |
| 4 | **眼适应乘子**：exposure *= luminance buffer 的 EXPOSURE 槽（float Load） | `bindless_buffers[...].Load<float>(LUMINANCE_BUFFER_OFFSET_EXPOSURE)` | `shaders/tonemapCS.hlsl:130-136` |
| 5 | **加 bloom**：对 bloom 的 mip1.5 / 3.5 / 4.5 各采一次取平均后相加 | `bloom += SampleLevel(...,1.5) + (...,3.5) + (...,4.5); bloom/=3;` | `shaders/tonemapCS.hlsl:138-147` |
| 6 | **曲线**：SRGB 标志位决定走 ACES / Uchimura / Reinhard，再 `ApplySRGBCurve_Fast`；非 SRGB（HDR 输出）只乘 hdr_calibration | | `shaders/tonemapCS.hlsl:149-169` |
| 7 | **colorgrading LUT**：3D 纹理按 result.rgb 采样直接替换 | | `shaders/tonemapCS.hlsl:171-175` |
| 8 | **dither**：`result.rgb += (dither(DTid.xy)-0.5)/64.0`；**contrast/brightness**：`(c-0.5)*contrast+0.5+brightness`；**saturation**：`mul(saturationMatrix(sat), c)`；最后 `saturateMediump` 写 UAV | | `shaders/tonemapCS.hlsl:177-193` |

**关键结论**：contrast/brightness/saturation 是在**曲线之后、写回之前**做的（属于 LDR 域操作）；bloom 与 exposure 是曲线**之前**加的（HDR 域）。dither 排在 colorgrading 之后、contrast 之前。`shaders/tonemapCS.hlsl:138-185` [实测]

### 4.2 三条曲线公式 [实测]

| 曲线 | 公式 | 位置 |
| --- | --- | --- |
| Reinhard（默认） | `x / (x + 1)` | `shaders/globals.hlsli:1094-1096` |
| ACES (MJP BakingLab 近似) | `col=mul(ACESInputMat,col); col=clamp(col,0,100); col=RRTAndODTFit(col); col=mul(ACESOutputMat,col); saturate` | `shaders/tonemapCS.hlsl:30-45` |
| ACES RRT/ODT 拟合 | `a = v*(v+0.0245786) - 0.000090537; b = v*(0.983729*v+0.4329510) + 0.238081; return a/b;` | `shaders/tonemapCS.hlsl:23-28` |
| Uchimura (GT7) | 参数 `P=1.0, a=1.0, m=0.22, l=0.4, c=1.33, b=0.0`；三段权重 `w0=1-smoothstep(0,m,x)`、`w2=step(m+l0,x)`、`w1=1-w0-w2`，分段 `T=m*pow(x/m,c)+b`、`L=m+a*(x-m)`、`S=P-(P-S1)*exp(CP*(x-S0))` | `shaders/tonemapCS.hlsl:50-92` |
| ACES 输入矩阵 | `{0.59719,0.35458,0.04823},{0.07600,0.90834,0.01566},{0.02840,0.13383,0.83777}` | `shaders/tonemapCS.hlsl:8-13` |
| ACES 输出矩阵 | `{1.60475,-0.53108,-0.07367},{-0.10208,1.10813,-0.00605},{-0.00327,-0.07276,1.07602}` | `shaders/tonemapCS.hlsl:16-21` |
| sRGB OETF（快速） | `select(x<0.0031308, 12.92*x, 1.13005*sqrt(x-0.00228) - 0.13448*x + 0.005719)` | `shaders/ColorSpaceUtility.hlsli:50-53` |

### 4.3 Bloom：separate + mipchain [实测]

- **Pass1 "Bloom Separate"**：对输入 4 个**对角半像素偏移**各采一次取平均 → 乘 exposure（若给 luminance buffer 则再乘它的 EXPOSURE 槽）→ `min(color,10)` 上限钳制（注释明说"高光会导致 bloom 过强"）→ `max(color - threshold, 0)` → 写 UAV。`shaders/bloomseparateCS.hlsl:14-35`
- **Pass2 "Bloom Mipchain"**：`GenerateMipChain(res.texture_bloom, MIPGENFILTER_GAUSSIAN, cmd, mipopt)`，`mipopt.gaussian_temp=&res.texture_temp`、`mipopt.wide_gauss=true`。`wiRenderer.cpp:11509-11513`
- 资源规模：bloom 纹理 = **1/4 分辨率**，`mip_levels = min(5, log2(max(w,h)))`，格式 `R11G11B10_FLOAT`；每 mip 都显式 CreateSubresource(SRV/UAV)。`wiRenderer.cpp:11413-11430`
- 入口先对 bloom+temp 两张整张 ClearUAV。`wiRenderer.cpp:11452-11462`

### 4.4 眼适应（EyeAdaption）[实测]

- 实现是 `ComputeLuminance`，**不是**独立函数名 EyeAdaption；参数 `adaption_rate`、`eyeadaptionkey`（默认 0.115，见 `wiRenderer.h:410`）。`wiRenderer.cpp:11353-11359`
- 工作在 **sourceImage 的 1/2 分辨率**。`wiRenderer.cpp:11364-11368`
- 固定动态范围：`log_min=-10.0`、`log_max=2.0`、`log_range=12.0`、`log_range_rcp=1/12`；`pixelcount = (w/2)*(h/2)`。`wiRenderer.cpp:11371-11377`

### 4.13 Q4：ShaderInterop_Postprocess.h 的"CB 布局"与 CPU 侧对应 [实测]

1. **后处理的所谓 CB 其实不是 CBV，而是 root constants（push constants）**。宏展开：`PUSHCONSTANT(name,type)` 在 HLSL/SPIR-V 分支= `ConstantBuffer<type> name : register(b999)`（DXC），在 SPIR-V 分支= `[[vk::push_constant]]`，在 C++ 分支= **空**（因为 `ShaderInterop.h` 在 `__cplusplus` 下把 `CONSTANTBUFFER/PUSHCONSTANT` 都定义成空，结构体本身仍可被 CPU 当普通 POD 用）。`shaders/ShaderInterop.h:26,32,48,50`
2. DX12 后端：`PushConstants` 断言 `param.ParameterType == D3D12_ROOT_PARAMETER_TYPE_32BIT_CONSTANTS` 且 `size <= Num32BitValues*4`，然后 `SetGraphicsRoot32BitConstants / SetComputeRoot32BitConstants`。`wiGraphicsDevice_DX12.cpp:7506-7540`
3. root signature 是从**编译好的 shader blob 反序列化**出来的（`GetRootSignatureDescAtVersion`），`RootSignatureOptimizer::init` 按 `RegisterSpace==0` 找出唯一一个 32BIT_CONSTANTS 根参数记作 `PUSH`（断言只能有一个）。`wiGraphicsDevice_DX12.cpp:3906,3924,1214-1220`
4. CPU 侧对应方式：**直接把同一个 struct 当 POD 填，然后 memcpy 式的 `PushConstants(&obj, sizeof(obj), cmd)`** —— 头文件被 C++ 和 HLSL 同时 include，所以两边字段偏移天然一致。`wiRenderer.cpp:17377-17418`
5. 唯一"打包"的字段是 tonemap 的 `exposure_brightness_contrast_saturation`（`XMHALF4` → 两个 `uint`）和 `flags_hdrcalibration`（低 16 位 flags + 高 16 位 half）。`wiRenderer.cpp:17379-17405`
6. 与**普通 CBV** 的区别：`CBUFFER(name, slot)`/`CONSTANTBUFFER(name,type,slot)` 走 `register(bN)`，例如 `CONSTANTBUFFER(fsr, FSR, CBSLOT_FSR)`，CBSLOT_FSR=2(DX12)/4(Vulkan)。`shaders/ShaderInterop_Postprocess.h:120`、`shaders/ShaderInterop.h:107,132` [实测]

### 5.2 Q5：in-place（src == dst）安全性 [实测]

**结论：单个 Postprocess_* 函数对 (input, output) 级别的 in-place 是"有条件不安全"，WE 靠调用方强制 ping-pong 回避。**

1. **算法层为什么不安全**：这些都是 CS，用 `SampleLevel(sampler_linear_clamp, ...)` 读 input 的**邻居像素**（sharpen 4 邻居、FXAA 3×3+、chromatic 3 通道异位、downsample 4 角、tonemap 的 bloom mip）`shaders/sharpenCS.hlsl:15-21`、`shaders/fxaaCS.hlsl:29`。若 src==dst，先写出的像素会污染后读的邻居 —— 这是**算法竞态**，任何 barrier 都救不了。
2. **WE 的正解是调用方 ping-pong**：链层持有 `rt_read`/`rt_write` 两个指针，每个效果调用后 `std::swap`。`wiRenderPath3D.cpp:2341-2343,2493-2494,2520-2533`
3. **唯一"效果级 in-place 安全"的例子**：GUI 模糊最后一步
   ```cpp
   Postprocess_Blur_Gaussian(rtGUIBlurredBackground[2], rtGUIBlurredBackground[1], rtGUIBlurredBackground[2], cmd, -1, -1, true);
   ```
   这里 `input == output == [2]`、`temp == [1]`。安全的原因是**两趟各自都是"读一张、写另一张"**：横向 input[2]→temp[1]，纵向 temp[1]→output[2]；中间 groupshared 缓存也把 tile 读完了才写。`wiRenderPath3D.cpp:2552-2554`、`shaders/blur_gaussian_float4CS.hlsl:139-147,177`
4. **TAA 是特例**：函数签名里没有 output，双缓冲在资源包内部（`GetCurrent/GetHistory`），调用方无法越过它。`wiRenderer.h:888-897`
5. **Upsample_Bilateral 的 PS 分支不做 ClearUAV**，只有 CS 分支做；所以 in-place 在 PS 分支下更危险 [推断]。

### 5.3 barrier 模式（每个效果都一样的四段式）[实测]

```
<bind shader / resources / push constants>
Barrier(out: layout -> UNORDERED_ACCESS)
ClearUAV(out, 0)
Barrier(Memory(out))
Dispatch(...)
Barrier(out: UNORDERED_ACCESS -> layout)
```
- 注意回滚目标是 `out.desc.layout`（创建时的 layout），不是显式的 `SHADER_RESOURCE`。`wiRenderer.cpp:17236,17243`
- `ClearUAV` + `Memory` barrier 的作用是让"清 0"对后续 CS 的 UAV 写可见；dispatch 覆盖全屏时理论上不必清，属防御性写法 [推断]。`wiRenderer.cpp:17228-17230`
- blur 用 `PushBarrier/FlushBarriers` 而不是直接 `Barrier`，为了把多张资源的转换合并成一次 barrier。`wiRenderer.cpp:12635-12636,12687-12689`
- 链层只额外插一次 **Aliasing barrier**（rtPostprocess 与 rtPrimitiveID/rtSceneCopy 共享显存）。`wiRenderPath3D.cpp:2346`、`wiRenderPath3D.cpp:164,171`

### 5.4 跨帧资源与生命周期 [实测]

1. TAA 双缓冲 `texture_temporal[2]` 在检测到分辨率变化时重建；TAA 关闭时整个资源包被清空（`temporalAAResources = {};`）。`wiRenderPath3D.cpp:431-439`
2. Bloom 与 Luminance 资源由 RenderPath 按需创建，但要检查 `IsValid()`；WE 用 `CreateBloomResources(res, internalResolution)` 一次建齐 bloom+temp+mip subresource。`wiRenderer.cpp:11413-11430`
3. Luminance buffer 的 1024 bins 是**跨帧累积**的（`adaption_rate` 控制新旧比例），所以 ClearUAV 只做一次（创建时用 `values` 初始化）。`wiRenderer.cpp:11340-11347`
4. 全局输入（velocity/depth/depth_history/lineardepth）不属于任何后处理资源包，来自 camera 结构体 + `BindCommonResources`。`wiRenderPath3D.cpp:2337`、`shaders/globals.hlsli:787,789,1447-1458`

### 5.5 别名与内存复用 [实测]

`rtPostprocess` 与 `rtPrimitiveID`、`rtSceneCopy` 共用一个 aliasing 分配（`aliasing_allocator.Add({&desc_rtPostprocess,&desc_rtPrimitiveID,&desc_rtSceneCopy})`），`offset_rtPostprocess` 保存偏移，创建时传入同一个 `aliasingAllocation`。所以链开始前必须把上一个使用者的写入排空并插 `GPUBarrier::Aliasing`。`wiRenderPath3D.cpp:164,171,2346`


## §6 可迁移性判定（逐项三选一 + 理由 + 替代方案）

### 6.1 判定标准（先说明尺子，避免"看着有用就要搬"）

| 判定 | 含义 |
| --- | --- |
| **必需** | 不做就无法形成正确/可用的后处理链，或缺失会导致当前架构无法成立 |
| **可选** | 与本项目目标（MiniEngine 血缘的 DX12 学习渲染器、全分辨率、单 RT）匹配度中等；做了收益明确，不做不阻塞 |
| **规模不匹配** | WE 的实现依赖本项目没有的子系统（bindless、FSR2 动态分辨率、mip 链工具、多 RT 池、历史深度），照搬会引入远超收益的复杂度 |

### 6.2 逐项三选一

**① tonemap 独立成 CS 通道 —— 【必需】**
- **理由**：它是"唯一跨 HDR→LDR 的边界"，也是当前项目**最严重的架构债**——tonemap 现在混在 Lighting PS 内部 `Engine/Shader/02_Deferred/LightingPS.hlsl:165`，导致 Skybox（:379 之后独立绘制）与未来的透明 Pass **不会被 tonemap**，只有 deferred 光照结果被处理，画面必然不一致 [实测]。
- **本项目替代方案**：不搬 `PushConstantsTonemap` 那套 half4 打包 `shaders/ShaderInterop_Postprocess.h:136-150`，改用本项目已有的 **root constants 通道**：`g_CommonRS[0] = InitAsConstants(0,4)` `Engine/02_RHI/Pipeline/GraphicsCommon.cpp:172` + `ComputeContext::SetConstants(RootIndex, X,Y,Z,W)` `Engine/02_RHI/Command/CommandContext.h:413-421`。参数只需 4 个 DWORD：`exposure`、`curveId`、`invGammaFlag`、`ditherAmount`。
- **不搬什么**：distortion/overlay 重投影 `shaders/tonemapCS.hlsl:110-120`（本项目无 distortion 贴图）、3D LUT colorgrading `shaders/tonemapCS.hlsl:171-175`（需额外 3D 纹理资源链）。

**② Bloom —— 【可选】（建议先做"只取阈值 + 单级模糊"的降级版）**
- **理由**：视觉收益/成本比最高的"看起来像现代渲染器"的效果；但 WE 的完整版是 separate + 5 级 mipchain + wide gaussian `wiRenderer.cpp:11442-11524`，需要 `GenerateMipChain`（本项目无此工具）与每 mip 的 SRV/UAV `wiRenderer.cpp:11413-11430`。
- **本项目替代方案**：只做 **1/4 分辨率单级**：threshold + 13-tap 双向可分离高斯（复用 WE 的 9-tap 权重表 `shaders/blur_gaussian_float4CS.hlsl:88-99`），两张 1/4 RT ping-pong。tonemap 时按 WE 的方式采 3 个不同 mip 求平均 `shaders/tonemapCS.hlsl:138-147` → 降级为**采同一张的 3 个固定偏移**以模拟多尺度。
- **不搬什么**：`wide_gauss` 33-tap `shaders/blur_gaussian_float4CS.hlsl:16-51`、`tmp` 资源与 mip 优化参数 `wiRenderer.cpp:11509-11513`。

**③ TAA —— 【必需】（但方式完全不同）**
- **理由**：项目已付出成本：`TemporalEffects.h` API 完整 `Engine/04_Renderer/TemporalEffects.h:22-39`、VelocityBuffer 已创建 `Engine/04_Renderer/Renderer/Deferred/DeferredRenderer.cpp:540`、`TAACS.hlsl` 已写好 `Engine/Shader/04_PostProcess/TAACS.hlsl:1-93`、Pass 空壳已就位 `Engine/04_Renderer/Renderer/Deferred/DeferredRenderer.cpp:421-425`。**三处都已就位却一处没接**——这是"半成品债"，比完全没做更危险。
- **本项目替代方案**：**不要搬 WE 的 temporalaaCS.hlsl**（它依赖 velocity/depth/depth_history/lineardepth 四个 bindless 输入 `shaders/temporalaaCS.hlsl:27-44`、Gather 预载 tile、深度选速度 `shaders/temporalaaCS.hlsl:53-76`）。本项目直接用**已有的 TAACS.hlsl**：它已含 `gAlpha>=0.999` 冷启动分支 `Engine/Shader/04_PostProcess/TAACS.hlsl:41-46`、`historyUV = uv - velocity` `Engine/Shader/04_PostProcess/TAACS.hlsl:52`、3×3 均值±1.5σ 钳制 `Engine/Shader/04_PostProcess/TAACS.hlsl:63-87`——**已经覆盖 WE 的核心三步**，缺的只是：tile cache（不需要，因为不是 8×8 共享内存版）、深度选速度（本项目无历史深度）。
- **可选的补强**：把 WE 的**混合因子公式**移植进来，替换固定的 `gAlpha`：`blendfactor = saturate(lerp(0.05, 0.8, frac(max(|vx|*W, |vy|*H)) * 0.5))` `shaders/temporalaaCS.hlsl:99-105` —— 这是纯算术，零资源成本。

**④ FXAA —— 【可选】（与 TAA 二选一，不建议同时要）**
- **理由**：单 pass、无历史、无额外资源，是"最廉价能看到的抗锯齿"。但与 TAA 功能重叠：WE 自己的链也是 `TemporalAA →（LDR 段）→ FXAA` 顺序串联 `wiRenderPath3D.cpp:2511-2533`。
- **本项目替代方案**：**不要整段内联 FXAA 3.11**（`fxaa.hlsli` 是 400+ 行第三方代码，含 39 档 quality preset `shaders/fxaaCS.hlsl:6-12`）。本项目只移植其**核心 2 步**：亮度边缘检测 + 沿边缘方向 1/8、1/4、1/2 步长的 3-tap 混合（约 40 行）。若要完整版，直接 vendored 一份 `fxaa.hlsli` 并注明来源即可（许可证宽松），不属"形式照搬"。
- **不要做**：`fxaaPS.hlsl`（**该文件不存在**，见 §8）。

**⑤ Sharpen —— 【可选】**
- **理由**：实现是整个后处理里最小的（1 行）`shaders/sharpenCS.hlsl:21`，与 TAA 配合能补偿 TAA 的软边。
- **本项目替代方案**：原样使用公式 `out = center + (4*center - top - bottom - left - right) * amount`，参数走 root constant 第 1 个 DWORD。**唯一注意**：本项目 TAACS 的邻域钳制会削掉高频 `Engine/Shader/04_PostProcess/TAACS.hlsl:80-87`，sharpen 应放在 **TAA 之后**（与 WE 一致：LDR 段 `wiRenderPath3D.cpp:2511-2516`）。

**⑥ Chromatic Aberration —— 【可选】（教学性价比极高）**
- **理由**：约 15 行，把"UV 扰动 + 三通道分采"讲得最清楚 `shaders/chromatic_aberrationCS.hlsl:16-30`。
- **本项目替代方案**：直接用 WE 公式，但把 `amount` 改成**只与到屏幕中心距离相关**的标量（WE 的 `resolution_rcp` 耦合会让 1080p/4K 表现不一致 `shaders/chromatic_aberrationCS.hlsl:20` [推断]）。写 alpha=1 的规则要保留（否则 back buffer alpha 影响 Present）。

**⑦ Gaussian Blur（通用版 + Bilateral 变体）—— 【规模不匹配】**
- **理由**：WE 的 `Postprocess_Blur_Gaussian` 是为"GUI 背景模糊 + 后处理上采样"服务的通用件，带 `mip_src/mip_dst`、`wide_gauss`、Bilateral 三种模式 `wiRenderer.h:566-575`，还要求 input/temp/output 三张同格式 RT。
- **本项目替代方案**：如果只为 bloom，用 §6.2② 里的私有两趟 CS 就够；如果要做 GUI 背景模糊，写一个**只支持 FLOAT4、单 mip** 的简化版，参数 `direction` 走 root constant。**不搬**格式白名单 switch `wiRenderer.cpp:12614-12631` 与 Bilateral 深度权重 `shaders/blur_gaussian_float4CS.hlsl:157-175`。

**⑧ Downsample4x / Upsample_Bilateral —— 【规模不匹配】**
- **理由**：这两个是 **FSR/DLSS 式动态分辨率**的配套件。`Upsample_Bilateral` 要求尺寸比为 2 的幂并据此选 depth mip `wiRenderer.cpp:18277-18281`，还要求输出格式落在白名单里否则 `assert(0) // implement format!` `wiRenderer.cpp:18290-18310`。本项目是全分辨率渲染 `Engine/04_Renderer/Renderer/RendererConfig.h:17`，没有低分辨率 RT。
- **本项目替代方案**：暂不实现。若未来要做性能缩放，**先做"整条链在 N% 分辨率 + Present 时用 FullScreenVS 的线性采样放大"**（零新代码，只需改 CreateDeferredBufferTargets 的 width/height `Engine/04_Renderer/Renderer/Deferred/DeferredRenderer.cpp:522-540`），这比移植 Bilateral 上采样便宜得多。

**⑨ ComputeLuminance / 自动曝光 —— 【规模不匹配】**
- **理由**：1024-bin 直方图 + 两级归约 + 跨帧 `adaption_rate` 累积 `wiRenderer.cpp:11353-11423`，且它在 **1/2 分辨率**上工作 `wiRenderer.cpp:11364-11368`。视觉收益在"场景快速明暗切换"时才明显，本项目是学习用的静态场景。
- **本项目替代方案**：先用**固定的 exposure 常量**走 root constant（已是 §6.2① 的设计），把 `adjustedExposure = exposureKey / avgLuminance` 留作注释里的 TODO。若真要自动曝光，最小实现是 **1/16 降采样 + 单次原子加进 1×1 buffer**（比 WE 的 1024-bin 直方图少 90% 代码）。

**⑩ CRT / 胶片颗粒等纯 LDR 玩具效果 —— 【可选】**
- **理由**：几乎零成本（每个 15-30 行），适合放到链尾练手 `wiRenderer.h:911-919`。
- **本项目替代方案**：严格放在 **tonemap 之后**（LDR 域），参数全部走 root constants；不要引入 WE 的 `params0.y` 是否做 sRGB 往返的二义开关 `wiRenderer.h:911-919` [推断]。

**⑪ Push constants（root 32-bit constants）作为效果参数通道 —— 【必需】**
- **理由**：后处理效果的参数（amount / threshold / direction / hdrToSRGB）都是**每 draw 几个 float**，用 CBV 需要每帧分配 ring buffer，成本与复杂度都更高。WE 全部后处理都走这条路 `wiGraphicsDevice_DX12.cpp:7506-7540`。
- **本项目替代方案**：**已经有了** —— `g_CommonRS[0] = InitAsConstants(0, 4)` `Engine/02_RHI/Pipeline/GraphicsCommon.cpp:172` + `SetConstantArray/SetConstants` `Engine/02_RHI/Command/CommandContext.h:253-260,402-421` + `RootSignature::InitAsConstants` `Engine/02_RHI/Pipeline/RootSignature.h:30`。所以**零新增基础设施**，只需在 shader 里用 `cbuffer` 的 4 个 DWORD 槽。
- **不搬什么**：WE 的 `register(b999)` 约定 `shaders/ShaderInterop.h:50` 与 `RootSignatureOptimizer` 从 blob 反序列化 root sig 的机制 `wiGraphicsDevice_DX12.cpp:3906,3924,1214-1220`（本项目 root sig 是手写 C++）。

**⑫ ShaderInterop 双端共享头（C++ 与 HLSL 同时 include 同一结构体）—— 【必需】**
- **理由**：这是 WE 真正值得学的**架构级**做法：`ShaderInterop.h` 用 `#ifdef __cplusplus` 把宏定义成空 `shaders/ShaderInterop.h:26,32`，同一个 struct 在 CPU 侧当 POD 填、在 GPU 侧当 cbuffer 布局 —— 消除"CPU 结构体与 HLSL cbuffer 错位"这一整类 bug。
- **本项目现状**：本项目**已经在用这个模式但只在注释里**：`LightingPS.hlsl:37-42` 明确写着"必须与 C++ 的 Scene::Camera::CameraData 逐字段一致"——**靠人工纪律维持，没有编译期保证** [实测]。
- **本项目替代方案**：新建 `Engine/Shader/01_Default/ShaderInterop_Tooiyume.h`（或放进已有 `01_Default/Common.hlsli`），把 `CameraData`、`LightData`、以及新的 `PostProcessConstants` 都放进 `#ifdef __cplusplus` 分支；C++ 侧改为 `#include` 该头。**不搬** WE 的 `CONSTANTBUFFER/PUSHCONSTANT` 宏名与 `b999` 约定。

**⑬ bindless 描述符（`bindless_textures_half4[...]`）—— 【规模不匹配】**
- **理由**：WE 所有后处理 shader 都靠 bindless 索引取输入 `shaders/tonemapCS.hlsl:124-128`、`shaders/temporalaaCS.hlsl:27-44`，TXAA 甚至把 `texture_lineardepth` 做成 emulator `shaders/globals.hlsli:1447-1458`。
- **本项目替代方案**：本项目用**显式 register + DescriptorTable** `Engine/04_Renderer/Renderer/Base/BaseRenderer.h:54-64`，后处理 pass 每个效果只用 2-4 张输入，直接 `SetDynamicDescriptor` `Engine/04_Renderer/Renderer/Deferred/DeferredRenderer.cpp:370-372` 即可。bindless 要等"上千材质纹理"量级才有收益。

**⑭ rtPostprocess 的 aliasing（与 rtPrimitiveID/rtSceneCopy 共享显存）—— 【可选】**
- **理由**：这是显存优化 `wiRenderPath3D.cpp:164,171,2346`，不是功能需求。
- **本项目替代方案**：先各开各的 RT（本项目 RT 数量还在个位数）。若以后要省显存，本项目已有 `ColorBuffer::Create` 的 `VidMemPtr` 别名入口 `Engine/02_RHI/Resource/ColorBuffer.h:62-66`——**这正是 WE aliasing 的等价物**，接口已具备。

**⑮ PostprocessVS 全屏三角 —— 【可选】（本项目已有等价物）**
- **理由**：WE 的所有后处理实际都走 CS，VS 只服务少数 PS 分支 `wiRenderer.cpp:18283-18289`。
- **本项目替代方案**：**什么都不用做** —— 项目已有 `FullScreenVS.hlsl`，用 `SV_VertexID` 生成 `uv = float2((vI<<1)&2, vI&2)` 的**全屏三角**（该"溢出到 [-1,3] 的 uv"与 WE 是同一个技巧，只是参数化不同）`Engine/Shader/02_Deferred/FullScreenVS.hlsl:6-15`，且已在 Lighting Pass 用 `Draw(3,0)` 跑通 `Engine/04_Renderer/Renderer/Deferred/DeferredRenderer.cpp:392`。

### 7.2 Q6：WP8 最小可实现效果集 = **tonemap + TAA**（AA 选 TAA 而非 FXAA）

**选 TAA 的理由（不是审美，是资产盘点结论）**：本项目已经把 TAA 的 4 件套铺好了 3.5 件——
1. API 层：`TemporalEffects` 的 `Initialize/Update/GetJitterOffset/ClearHistory/ResolveImage` 全部声明好 `Engine/04_Renderer/TemporalEffects.h:22-39`；
2. 抖动基础设施：`s_JitterX/s_JitterY/s_FrameIndexMod2` 已存在 `Engine/04_Renderer/TemporalEffects.cpp:36-43`，`m_MainViewport.TopLeftX = 0.0f; // taa用` 已注明用途 `Engine/04_Renderer/Renderer/Deferred/DeferredRenderer.cpp:73-74`；
3. 速度缓冲：`VelocityBuffer` 已按 `R16G16_FLOAT` 创建 `Engine/04_Renderer/Renderer/Deferred/DeferredRenderer.cpp:540`；
4. shader：`TAACS.hlsl` 已完整实现重投影+钳制+冷启动 `Engine/Shader/04_PostProcess/TAACS.hlsl:1-93`。

**而 FXAA 要从零写**（`fxaaPS.hlsl` 不存在 `shaders/fxaaCS.hlsl:1`，本项目也没有任何 LDR 边缘检测代码）。所以 WP8 选 TAA = **复用已有 90% 资产**；FXAA 放到 WP9 作为"TAA 之外的备选 AA"。

#### 效果 ①：Tonemap（CS）

**Shader 要点**（`Engine/Shader/04_PostProcess/TonemapCS.hlsl`，目标 60-90 行）：
- `[numthreads(8,8,1)]`（与 WE 的 `POSTPROCESS_BLOCKSIZE 8` 一致 `shaders/ShaderInterop_Postprocess.h:5`）。
- 绑定：`Texture2D<float4> gInput : register(t0); RWTexture2D<float4> gOutput : register(u0); SamplerState gLinearClamp : register(s0);` 然后 `cbuffer PostProcessConstants : register(b0) { float gExposure; float gCurveId; float gInvGamma; float gDitherAmount; }`——**正好吃满 `g_CommonRS[0] = InitAsConstants(0,4)` 的 4 个 DWORD** `Engine/02_RHI/Pipeline/GraphicsCommon.cpp:172`。
- 曲线：先只做 **Reinhard (`x/(x+1)`)** + **Narkowicz ACES**（把 LightingPS 里删掉的 a=2.51,b=0.03,c=2.43,d=0.59,e=0.14 搬过来改用）`Engine/Shader/02_Deferred/LightingPS.hlsl:57-62` —— 两条用 `gCurveId` 切。**不要**一开始就上 WE 的 3×3 矩阵版 ACES `shaders/tonemapCS.hlsl:8-45` 与 Uchimura 三段式 `shaders/tonemapCS.hlsl:50-92`。
- sRGB 编码：`pow(x, 1/2.2)` 或移植 WE 的快速拟合 `1.13005*sqrt(x-0.00228)-0.13448*x+0.005719` `shaders/ColorSpaceUtility.hlsli:50-53`（后者更快，建议直接抄公式）。

## §8 未确认项

### 7.3 改造顺带必须决策的一件事：sRGB 编码放在哪

实测发现本项目**整条输出路径上没有 sRGB 编码**：
