# A5 特效模拟与资产管线（WE 渲染技术总目录 第 5 卷）

> 证据等级：**[实测]** 读过该行；**[推断]** 由命名/调用点推测，施工前须回源确认。路径相对 `WickedEngine-master/WickedEngine/`。
> 本卷覆盖 WE 的**非光栅化模拟**（粒子/SPH/毛发/云/水/风/湿痕）与**资产管线**（VT、BC 压缩、MIP、mesh blend、纹理工具、GPU 排序）。

## §3 关键技术逐项详解

### A5-28 / A5-29 资产压缩与 MIP 的「登记-执行分离」〔必需〕

**功能**：解决"资产层不知道 CommandList、渲染层不知道资产"的时序矛盾。资产线程只把 (纹理, 选项) 推进队列，渲染层的帧首主线程统一消费。

**结构（三段，逐行实测）**：

| 段 | 位置 | 行为 |
|---|---|---|
| 登记 | `wiRenderer.cpp:19360 AddDeferredMIPGen`、`:19366 AddDeferredBlockCompression` | 加锁 → push_back → 解锁（`:19362-19364`/`:19368-19370`） |
| 调用点 | `wiResourceManager.cpp:942/981`、`wiScene.cpp:5510/5524` | 贴图导入/几何导入完成时调用 |
| 执行 | `wiRenderPath3D.cpp:861` → `wiRenderer.cpp:3603-3616` | 先做 paint，再逐条 GenerateMipChain（`:3608`）、BlockCompress（`:3613`），最后 clear |

**关键细节（实测）**：

- 执行发生在**主线程、帧最前**，注释原文 "Execute it first thing in the frame here, on main thread, to not allow other thread steal it"（`wiRenderPath3D.cpp:861`）。
- `BlockCompress` 不是"挑个 CS 直接压"：它先按格式换 CS（`wiRenderer.cpp:10585-10631`），再为整条 mip 链申请一张 `bc_raw` 暂存纹理（`:10634-10643`，尺寸向上取 2 的幂且至少 64），逐 mip 派发（`:10664-10672`），最后才 copy 进 BC 纹理（`:10676` 起）。
- `GenerateMipChain` 每级都插入 6 个面各自的成对屏障（`wiRenderer.cpp:10329-10334` / `:10358-10366`），CubeArray 派发布 z=6（`:10354`）。
- mip 着色器里**保覆盖**是可选项：置了 `MIPGEN_OPTION_BIT_PRESERVE_COVERAGE` 才按 alpha 加权平均（`generateMIPChain2DCS_float4.hlsl:27-38`），否则算术平均（`:40-51`）。

**对本项目取舍**：**必需（结构）**。TooiyumeRender 的贴图 100% 未压缩：`Engine/03_AssetSystem/Importers/Model/ModelConvert.cpp:367-376` 五处 `SetTextureOptions` 只传 sRGB/alpha，从不置 `kDefaultBC`（该位定义在 `Engine/03_AssetSystem/Importers/Texture/TextureConvert.h:18`，而 `TextureOptions()` 在 `:23-26` 里根本没带它）。同时 `TextureConvert.cpp:25` 的失效判据只有"dds 不存在或比源文件旧"，**不含 flag** —— 即便补上 `kDefaultBC` 也不会重编译已有 dds，必须同批修（§5-G3）。参考实现的正确形态：登记与执行分离 + 执行在帧首主线程 + 压缩走 GPU。

### A5-01 ~ A5-05 粒子系统五段式〔规模不匹配，但 A5-04 的范式可选〕

**功能**：GPU 全托管粒子：发射 → 模拟 → 排序 → 收尾，全程无 CPU 回读。

**结构（一次 Update，逐行实测 `wiEmittedParticle.cpp:434-816`）**：

| 阶段 | 行 | 行为 |
|---|---|---|
| 组装 CB | `:446-548` | 发射点矩阵、寿命/重力/阻力/拖拽、SPH 核常数一次写进 EmittedParticleCB |
| 发射 | `:581-586` | 三选一 CS（普通/体积/网格），派发 (count+63)/64 |
| 计数跳板 | `:595` | `kickoffUpdateCS` 把 aliveCount_afterSimulation 换成 IndirectDispatchArgs（`emittedparticle_kickoffUpdateCS.hlsl:14`） |
| SPH（可选） | `:617-721` | 分区→分配→分桶→密度→力，5 次 DispatchIndirect（Event 名见 `:616/638/660/686/705`） |
| 模拟 | `:748-770` | 按 IsSorted()/深度碰撞选 4 变体之一，DispatchIndirect |
| 排序 | `:786` | 仅排序路径：`wi::gpusortlib::Sort(MAX_PARTICLES, distanceBuffer, counterBuffer, offsetof(ParticleCounters, culledCount), culledIndirectionBuffer, cmd)` |
| 收尾 | `:794-814` | `finishUpdateCS` 把 culledCount 转成 THREADCOUNT_MESH_SHADER 的 IndirectDrawArgs（`emittedparticle_finishUpdateCS.hlsl:16`） |

**粒子数据结构**（`ShaderInterop_EmittedParticle.h:7-17`）：position/mass/force/velocity/life/maxLife/sizeBeginEnd/color/rotation_rotationVelocity —— 三个 float3 夹 float 混排，正好 4 字节对齐无空洞，这是 CPU 端 memcpy 上传能成立的前提。

**软边只值 6 行**（`emittedparticlePS_soft.hlsl:79-84`）：取 2×2 GatherRed 的场景线性深度，用最大值减本片元深度、除以粒子尺寸，saturate 后乘 alpha。将来做体积雾/软粒子可直接照抄。

**对本项目取舍**：**规模不匹配**（无粒子需求，且 MS 路径需 SM6.5）。但 **A5-04 值得单抽**：把"CPU 回读计数器 → 再决定派发大小"改成"GPU 内 IndirectArgs 接力"，与 WP4 的 fence 完成值设计同源。SPH 五段的核心是 `SPH_GridHash` 把三维格点线性化（`emittedparticle_sphbinningCS.hlsl:24-25`），代价是必须保证"计数 → 分配偏移 → 再填桶"三相（`emittedparticle_sphpartitionCS.hlsl:26` → `emittedparticle_sphcellallocationCS.hlsl:15` → `emittedparticle_sphbinningCS.hlsl:28-29`），这也解释了为何要 5 个独立派发。

### A5-13 / A5-14 / A5-15 体积云的四段数据流〔规模不匹配〕

**功能**：从天气图到屏幕，需要**烘焙 → 步进 → 阴影 → 重投影**四条腿。

**结构（分辨率/格式实测自 `wiRenderer.cpp:16804-16836`）**：

| 资源 | 分辨率 | 格式 | 行 |
|---|---|---|---|
| texture_cloudRender | 屏幕 1/4 | R16G16B16A16_FLOAT | `:16811-16815` |
| texture_cloudDepth | 屏幕 1/4 | R32G32_FLOAT | `:16817-16818` |
| texture_reproject[2] | 屏幕 1/2 | RGBA16F | `:16821-16826` |
| texture_reproject_depth[2] | 屏幕 1/2 | R32G32_FLOAT | `:16828-16832` |
| texture_reproject_additional[2] | 屏幕 1/2 | R8_UNORM | `:16833-16836` |
| 云阴影图 | 512² | R11G11B10_FLOAT | `:4193-4198` |
| 形状噪声 | 64³，6 mip | RGBA8 | `:4471-4475` |

**细节**：

- 主步进的步数/阴影采样数/地面贡献全部来自天气参数（`volumetricCloud_renderCS.hlsl:112-115`），代码里没有硬编码常量 —— 是运行时开关而非编译变体。
- 多次散射展开成 `MS_COUNT` 个衰减八度（`volumetricCloud_renderCS.hlsl:101`），密度阈值 `:108` 决定提前退出。
- 重投影历史权重区间 `float2(0.86, 0.96)`（`volumetricCloud_reprojectCS.hlsl:17`），去遮挡时回退到 8 面云图（`:23-29`）而非直接取当前帧，避免闪噪。
- 云"捕获"是同一份 renderCS 加 `VOLUMETRICCLOUD_CAPTURE` 宏（`volumetricCloud_renderCS_capture.hlsl:1-2`），画进 cubemap 供反射。

**对本项目取舍**：**规模不匹配**。要 3D 纹理、持久历史缓冲、天气图资产；本项目连 Texture2DArray 都少。A2-09 的烘焙天空已覆盖"看起来对"。**唯一可借的是分辨率分层法**：昂贵积分在 1/4、历史在 1/2、上采样回全屏 —— 若本项目做体积光/雾升级，应直接采用这个层级。

### A5-18 ~ A5-22 海洋：频谱→FFT→位移图→屏幕网格〔规模不匹配〕

**功能**：Tessendorf 式频谱海洋。每帧 CPU 只改一个时间标量，其余全在 GPU。

**结构（链，实测）**：

```
oceanSimulatorCS  ──H(0)→H(t)──→ float2 打包（field0 = ht + i*dt_x）
                                        └ field1 = Dy（另一段缓冲）
        ▼
fft_512x512_c2c（6 趟 radix008 乒乓，wiFFTGenerator.cpp:168-193）
        ▼
oceanUpdateDisplacementMapCS → 位移图（RGBA16F，xyz = dx/dy/dz）
        ▼
oceanUpdateGradientFoldingCS → 梯度图（rg = 梯度, a = fold）+ mip 链
        ▼
oceanSurfaceVS/PS：屏幕网格 → 与水面平面求交 → 采样位移 → 再投影
```

**三处值得记的实现技巧**：

1. **双场实数 FFT 打包**：逆变换输出为实，于是两条场塞进一个复数缓冲（`oceanSimulatorCS.hlsl:42-48`，注释明写 "Two-for-one real FFT packing"），省掉一个缓冲与一趟 FFT。
2. **符号修正**：逆变换时按 `(x+y)&1` 交替取反（`oceanUpdateDisplacementMapCS.hlsl:14`），这是频移的经典处理，漏掉会得到棋盘格。
3. **存梯度而非法线**：`oceanUpdateGradientFoldingCS.hlsl:26` 注释说明"存梯度保留了两个差分值"，同时用 Jacobian 行列式 `:31` 估白浪折叠量 `:34`。梯度可以任意缩放着色，法线不行。

**对本项目取舍**：**规模不匹配**。但 **A5-22 的读回**值得单列：`wiRenderer.cpp:5682 ReadbackOcean` → `wiOcean.cpp:429`，是本卷唯一带 CPU 回读的模拟，正好作为 WP4"读回必须晚于 fence 完成值"的对照素材（粒子/云则完全没有回读）。

### A5-26 / A5-27 虚拟纹理与 mesh blend〔规模不匹配，但各有可取的一段〕

**VT 三 CS 的本质是三级流水**：

- `virtualTextureTileRequestsCS.hlsl:42` 每个 2×2 像素组取 4 个反馈值的 **min**（不是 max）—— 反馈写的是"可接受的最高 LOD"，取 min 即最保守需求。
- `virtualTextureTileAllocateCS.hlsl:50` 把 x,y,lod 打包进一个 uint（`(x&0xFF)<<24 | (y&0xFF)<<16 | (lod&0xFF)<<8`），**一张 UAV 就回传三个字段**，避免多缓冲。
- `virtualTextureResidencyUpdateCS.hlsl:31-47` 显式区分"遇到空洞（0xFFFF）就作废 minLod"与"否则取最高可用"，注释（`:33-37`）说明这是分配失败导致 mip 链不连续。

**mesh blend 三步**：prepare（掩码 + 边缘检测，`wiRenderer.cpp:18602`）→ expand（多趟 JFA，步长表 `:18535` 为 64,32,16,8,4,2,1，循环 `:18631-18654`）→ resolve（PS 镜像采样，`:18684-18700`）。它是本卷唯一把"aliasing allocator + 乒乓"用在屏幕空间纹理上的例子（`:18556-18565`）。

**对本项目取舍**：**规模不匹配**。VT 只被地形驱动（`wiTerrain.cpp`），本项目无地形；mesh blend 要 primitiveID 缓冲与区域编码，代价远超收益。**可取的是"每级/每趟插入精确成对屏障"的写法**（`wiRenderer.cpp:10329-10366` 的 6 面成对屏障），本项目 RT 状态机可直接照搬。

### A5-23 / A5-24 / A5-25 轻量模拟三件套〔可选〕

**风（A5-23）**：`windCS.hlsl:5-22` 用 6 个不同尺度的 noise_gradient_3D 叠加（`:13-18`），再 `sin(mad(time, speed, offset))`（`:21`）；输出 float2 存"当前+上一帧"（`:28`），顶点侧插值即可做风动。派发在 `wiRenderer.cpp:5233-5236`，且**只在风向非零时**才跑（`:5227-5231` 的三分量判断）—— 最廉价的开关。

**湿痕（A5-24）**：`wetmap_updateCS.hlsl` 是"逐顶点持久状态"的样板 —— 状态存在 RWBuffer<float> 里（`:28`），每帧只做 lerp 演化（`:82`），用海面位移算水线（`:35-48`）、用阴影图 9 次比较判断雨是否被挡（`:64-72`）。C++ 侧对所有物体逐实例派发（`wiRenderer.cpp:11168-11184`），注释明说 "every object wetmap is updated, not just visible"（`:11167`）。

**空气透视（A5-25）**：`aerialPerspectiveCS.hlsl:35-41` 先走 LUT 快路径（相机体积 LUT），只有高海拔或高质量模式才 `:74` 进 IntegrateScatteredLuminance 全步进；末尾 `:84-90` 把雾量从 AP 里扣掉，理由是"雾必须在 AP 之上"（注释 `:82-83`）。这种"两个效果谁盖谁"的显式扣减，是合成顺序容易踩的坑。

**对本项目取舍**：三者都是 **可选**，但成本极低（风 1 个 CS、湿痕 1 个 CS + 一个 float 缓冲、AP 1 个 CS）。若要做湿地/吹植被，A5-23/A5-24 是现成的最小实现。
