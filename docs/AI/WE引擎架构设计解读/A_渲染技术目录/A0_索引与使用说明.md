# A0 索引与使用说明：WE 渲染技术总目录

> **本目录解决一个问题**：改造 TooiyumeRender 时，需要「WE 是怎么做 X 的、代码在哪、能不能抄」，而不是再去翻 4 万行着色器。
> 本目录是 `09_升级实施建议.md` 的**技术检索层**：09 回答「先做什么」，本目录回答「那件事 WE 是怎么做的」。

## 5. 规模基线（为什么它是「总目录」）

| 项 | 数量 | 来源 |
|---|---|---|
| `shaders/` 顶层文件数 | **365**（305 `.hlsl` + 40 `.hlsli` + 18 `.h` + 2 `.vcxitems`） | `find . -maxdepth 1 -type f` [实测] |
| `.hlsl` 着色器 | **305**（合计 **22,660** 行） | `cat *.hlsl \| wc -l` [实测] |
| `.hlsli` 共享头 | **40**（合计 **18,984** 行） | `cat *.hlsli \| wc -l` [实测] |
| `.h` 头 | **18**（合计 **4,462** 行；17 个 `ShaderInterop_*.h` + 1 个总入口 `ShaderInterop.h`） | `cat *.h \| wc -l` [实测] |
| `wiRenderer.h` 导出的渲染层入口 | **207** 个 `void` 函数 | `wiRenderer.h` [实测] |
| `wiRenderer.cpp` 实现行数 | **19,686** | [实测] |
| `wiRenderPath3D.cpp` 实现行数 | **3,326** | [实测] |

> **⚠ 2026-10-24 23:0x 基线更正**：本表旧值（hlsl 22,965 / hlsli 19,024 / h 4,480 / wiRenderPath3D 3,327）**全部偏大**，根因已定位——`_data/WE_shader_inventory.txt` 的统计脚本对**每个文件**多计了 1 行。证明：`cat *.hlsl | wc -l` = 22,660，而旧值恰好等于 22,660 + 305（=文件数），hlsli 亦然（18,984 + 40 = 19,024）、h 亦然（4,462 + 18 = 4,480）。同一缺陷导致 `_data/WE_shader_inventory.md` 中**每个文件的行数也 +1**（如 `objectHF.hlsli` 记 1,153，实为 1,152），并已在 A1–A5 各卷的 `文件:起始-结束` 区间末端产生 64 处 off-by-one（已全部修正）。**三条计数口径**：`wc -l` 计换行符数（9 个无尾换行的文件会少 1）；`awk 'END{print NR}'` 计逻辑行（推荐，与文本编辑器一致）；`_data` 用的是「wc -l 再 +1」，对任何文件都错。`wiRenderPath3D.cpp` 的 3,327 不是同一缺陷（3,326 + 1），已按实测直接更正。

> **结论**：本目录覆盖的是 WE 渲染能力的**全集大纲**，不是精选。单卷遗漏某项时，以 `_data/WE_shader_inventory.txt` 反查文件名补入——但**行数一律以 `awk` 重新实测为准，不采信 `_data` 里的行数列**。
>
> **条目规模**：A1 29 条 / A2 21 条 / A3 35 条 / A4 **36 条** / A5 **30 条** / A6 28 条，**合计 179 条**，共 **782 处 `文件:行` 引用**（A1:53 / A2:41 / A3:209 / A4:164 / A5:133 / A6:182；2026-10-24 23:50 全部并行写入停止后逐卷实测求和，命令见下）。
>
> 条目数口径：`grep -o '^| A[1-6]-[0-9][0-9] ' <卷> | sort -u | wc -l`。引用数口径（宽正则，含 `Engine/` 前缀与含中文的路径）：`grep -oE '[^\s|`()\[\]<>"]+?\.(cpp|hpp|h|hlsl|hlsli|md|json|txt):[0-9]+(-[0-9]+)?' <卷> | wc -l`。行号续引（形如 `:1234`，无文件名）不计入引用数。各卷改写后须按上述命令重新校准。
