# A1 几何与光栅管线（WE 渲染技术总目录 第 1 卷）

> 证据等级：**[实测]** 读过该行；**[推断]** 推测，施工前须回源。路径相对 `WickedEngine-master/WickedEngine/`。

## §1 管线位置

```
Scene.visibility ──┬─→ UpdateRenderData / Async (实例/材质/蒙皮上传)
                   ├─→ DrawShadowmaps (阴影级: shadowVS/PS/MS)
                   └─→ DrawScene ──→ 每 pass (prepass / gbuffer / forward / transparent)
                                     │
                                     ├─ 排序: renderQueue_{opaque,transparent}
                                     ├─ 选 PSO: ObjectRenderingVariant → GetObjectPSO
                                     └─ batch_flush → 逐实例 Bind* + DrawIndexedInstanced
```

另有两条独立的光栅支线：**可见性缓冲（visibility_*）**与**网格着色器/meshlet**。

## §3 关键技术的逐项详解

### A1-01 / A1-02 对象主 VS/PS 与材质入口〔必需〕

**功能**：整个光栅化管线的主体。VS 做世界/视图/投影变换、蒙皮、风动位移；PS 采样材质纹理并进入光照。

**结构**：

- `objectVS_common.hlsl` 只有 4 行（实测），真正的实现全在 `objectHF.hlsli`（**1153 行**）——包括 `GetVertexID`(`:152`)、`GetPositionWind`(`:162`，风动位移)、`GetUVSets`(`:185`)、`GetAtlasUV`(`:193`)、`GetVertexColor`(`:193` 附近)。
- `objectPS.hlsl` 也只有 6 行，光照入口在 A2 卷的 `lightingHF.hlsli` / `shadingHF.hlsli`。

**对本项目取舍**：**必需**。这种「薄入口 + 大 HLSI 共享头」的形态正是本项目该学的结构：`Engine/Shader/` 下的 VS/PS 应该只保留入口，公共逻辑进 `Common.hlsli`。

### A1-04 阴影图绘制〔必需〕

**功能**：为每个光源（尤其方向光的级联）绘制深度图，供 A2 卷的阴影采样。

**结构**：`DrawShadowmaps`（`wiRenderer.cpp:6691`）内部按级联循环，每级设置阴影矩阵 → 绑定该级的 DSV → 用 shadowPS 的 alphatest/transparent 变体绘制。变体矩阵：`shadowVS/PS/MS` × `{普通, alphatest, transparent}`。

**对本项目取舍**：**必需**。TooiyumeRender 当前无阴影（无 shadow pass）；最小实现只需 1 级方向光阴影 + PCF，无需级联。

### A1-09 ~ A1-13 可见性缓冲五段式〔规模不匹配〕

**功能**：WE 的「按 tile 记录 primitiveID，再只对可见像素做材质采样」的延迟着色变体，可减少 GBuffer 带宽。

**结构（五段，逐段实测）**：

| 段 | 着色器 | 行号 | 入口 |
|---|---|---|---|
| 1 分析 | `visibility_analyzeCS.hlsl` | `:27` main | `Visibility_Prepare` `wiRenderer.cpp:11625` |
| 2 解析 | `visibility_resolveCS.hlsl` | `:29` main | 同上 |
| 3 表面 | `visibility_surfaceCS.hlsl` | `:25` main | `Visibility_Surface` `:11770` |
| 4 着色 | `visibility_shadeCS.hlsl` | `:37` main | `Visibility_Shade` `:11827` |
| 5 速度 | `visibility_velocityCS.hlsl` | `:16` main | `Visibility_Velocity` `:11877` |

**对本项目取舍**：**规模不匹配**。它需要完整的 bindless 描述符体系 + tile 位集基础设施，本项目是单 D3D12、3 pass、4096 槽的规模。09 的 N8/D10 已明确不引入 bindless；GBuffer 带宽在本项目的分辨率下不是瓶颈。

### A1-05 曲面细分 / A1-06 网格着色器〔规模不匹配〕

**功能**：HS/DS 用位移贴图细分表面；MS 用 mesh shader 直接生成三角形簇。

**对本项目取舍**：**规模不匹配**。两者都需要额外的 PSO 变体与预处理（meshlet 构建在 `meshlet_prepareCS.hlsl:8-40`），本项目无位移贴图资产，且 MS 需要 SM 6.5+ 与专用管线。09 的 N12 已判定这类接口应砍。

### A1-15 ~ A1-17 深度派生工具〔必需〕

**功能**：深度是 AO/SSR/DoF/雾 的共同输入，但直接读 depth 需要格式转换；WE 提供两组 CS 在需要时现算。

**对本项目取舍**：**必需**。项目当前只有 depth buffer，无线性深度与法线重建。这三者单价极低（各几十行 CS），且是 WP8 多个效果的前置。

## §4 批次与 PSO 选择（对 WP2/WP5 最关键）

| 概念 | 位置 | 说明 |
|---|---|---|
| renderQueue | 声明在 `wiRenderer.cpp:338-339`（`static thread_local RenderQueue renderQueue / renderQueue_transparent`）；`wiRenderPath3D.cpp:929` 是 `drawscene_flags`，**不是队列** | 按材质/几何切分的绘制队列 |
| ObjectRenderingVariant | `wiRenderer.cpp:348-362`（实测位域：renderpass 4 + shadertype 8 + blendmode 4 + cullmode 2 + tessellation 1 + alphatest 1 + sample_count 4 + mesh_shader 1 = **25 位**） | 位打包决定 PSO 变体，**不是**运行时分支 |
| GetObjectPSO | `wiRenderer.cpp:364-368` | 由 variant + pass 查表 |
| batch_flush | `wiRenderer.cpp:3196-3422`（**实测 227 行** lambda） | 逐 subset 绑 PSO + 索引缓冲后 `DrawIndexedInstanced` / `DispatchMesh` |

**对本项目的含义**：TooiyumeRender 当前用「遍历比较原生指针」来选 PSO（`DeferredRenderer.cpp:605-609`），等价于把 variant 语义压进了指针比较，一旦加变体就会爆炸。WP2 必须先把 variant 显式化。

## §5 数据流总图

```
Scene (ECS)
  ├─ MeshComponent ──→ GPU vb/ib (suballocated)
  ├─ MaterialComponent ──→ StructuredBuffer（bindless SRV）
  └─ ObjectComponent ──→ instance buffer (per-frame mapped)
           │
           ▼
   Visibility（视锥 + 遮挡）
           │
           ├─→ 阴影：shadowVS/PS  → 级联 DSV
           ├─→ Prepass：objectVS_prepass → Z
           └─→ 主 pass：objectVS/PS → GBuffer / Forward RT
```
