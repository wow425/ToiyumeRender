## §1 本卷在管线中的位置

WE 的 GI 不是一个阶段，而是**分三个阶段分别发生**的：

```
① 不透明绘制之前（compute 命令列表，wiRenderPath3D.cpp:907-925）
   UpdateRaytracingAccelerationStructures  ← BLAS/TLAS 或自建 BVH 重建
   SurfelGI   ← 世界空间面元（有持久化状态，必须先更新）
   DDGI       ← 探针体积（有持久化状态，必须先更新）

② 不透明绘制之后、后处理之前（HDR 域，写回半分辨率 GI 图）
   1110 RTShadow            ┐
   1119 ScreenSpaceShadow   │ 阴影合成（进 light_color）
   1283 VXGI_Voxelize       │ 体素化（R 通道，可在此之前）
   1444 RTReflection        │
   1455 RTDiffuse           │ 光追 GI（写 rtRTReflection / rtRTDiffuse）
   1465 VXGI_Resolve        │ 体素锥追踪（写 rtVXGI_dif/spec）
   1838/1848/1857/1866 AO   │ 四选一：SSAO / HBAO / MSAO / RTAO（写 rtAO）
   1885 SSR   （仅当 RT 反射关闭）
   1898 SSGI
        │
        ▼  半分辨率 + 时空降噪 + 双边/联合上采样 → 全分辨率 GI 图
   全分辨率着色器消费（§3.9）：objectHF.hlsli / shadingHF.hlsli
        │
        ▼
   进 A3 后处理链（TAA → tonemap …）
```

**[实测]** 三条关键事实：
1. 所有 GI pass 的入口都在 `wiRenderPath3D.cpp`，且**调用顺序即依赖顺序**（`wiRenderPath3D.cpp:1444` 反射先于 `:1455` 漫反射，`:1898` SSGI 在 AO 之后）。
2. 每个 pass 开头都有三连守卫：设备能力 / AS 有效性 / `raytracing_ctx` 是否忙（`wiRenderer.cpp:15478-15484`、`wiRenderer.cpp:13918-13924`）。这是**异步命令列表**约束，不是可选优化。
3. SSR 与 RTReflection 互斥：`wiRenderPath3D.cpp:1883` 的条件是 `getSSREnabled() && !getRaytracedReflectionEnabled()`。

## §3 关键技术的逐项详解

### 3.1 SSR：Hi-Z 步进 + 三档 tile + 三段降噪〔可选，学习价值最高〕

**功能**：只用「深度 + 法线粗糙度 + 上一帧颜色」求镜面反射，不依赖 BVH、不依赖 bindless。是**本项目在没有光追时唯一现实可实现的反射方案**。

**结构（pass 顺序逐行实测，`Postprocess_SSR` 内）**：

| 序 | pass | C++ 行 | 着色器 | 说明 |
|---|---|---|---|---|
| 1 | tile 粗糙度横向 | `wiRenderer.cpp:15089` | `ssr_tileMaxRoughness_horizontalCS.hlsl:12-40` | 每 tile（32px，`ShaderInterop_Postprocess.h:43`）沿 x 扫，深度=0 记 1.0 |
| 2 | tile 粗糙度纵向 | `wiRenderer.cpp:15116` | `ssr_tileMaxRoughness_verticalCS.hlsl:40-60` | 沿 y 合并且**同时写三档间接参数** |
| 3 | 深度层级 | `wiRenderer.cpp:15153` | `ssr_depthHierarchyCS.hlsl:13-41` | mip0 用 GatherRed 直接由深度算 min/max，其余 mip 由上一级 Gather |
| 4 | 光线步进（间接） | `wiRenderer.cpp:15269/15272/15276` | `ssr_raytraceCS.hlsl:228` + `_cheap`/`_earlyexit` 变体 | 三档 `DispatchIndirect`，各自读自己的 tile 表 |
| 5 | 空间解算 | `wiRenderer.cpp:15295` | `ssr_resolveCS.hlsl:87` | 邻域加权 + 方差，写 reprojectionDepth |
| 6 | 时间解算 | `wiRenderer.cpp:15334` | `ssr_temporalCS.hlsl:136` | 双候选重投影 + 3×3 Welford |
| 7 | 双边上采样 | `wiRenderer.cpp:15382` | `ssr_upsampleCS.hlsl:28` | 半分辨率 → 全分辨率 |

**三档分派规则（`ssr_tileMaxRoughness_verticalCS.hlsl:44-58` [实测]，阈值 `:16` `SSRRoughnessCheap = 0.35`）**：
- `minRoughness < 0.35` → 走 **expensive**（全 Hi-Z，`HierarchicalRaymarch`），写 `tiles_tracing_expensive`（`:46-47`）
- 否则 `maxRoughness > 0.35 && minRoughness < ssr_roughness_cutoff` → 走 **cheap**（线性 `RayMarch`），写 `tiles_tracing_cheap`（`:49-52`）
- 否则 → **earlyexit**（整块直接写 0）（`:54-58`）

分派量写进 `tile_tracing_statistics[0].dispatch_*.ThreadGroupCountX`，一次 `InterlockedAdd` 带 **`tile_tracing_replicate = sqr(32/downscale/8)`**（`:41`），因为「一个 tile 要展开成多个 8×8 组」；写入位置用 `prevCount / tile_tracing_replicate` 反算（`:47`）。tile 本身编码成 `(x & 0xFFFF) | ((y & 0xFFFF) << 16)`（`:40`）——**一个 uint 同时存 tile 的 xy**。

**参数传递全是宏（`ShaderInterop_Postprocess.h:43-67` [实测]）**：
```
ssr_roughness_cutoff = postprocess.params0.z     sr_frame = params0.w
ssr_ratiofactorx/y   = postprocess.params1.xy    ssr_downscalefactor = params1.z
rtdiffuse_range = rtreflection_range = ssao_range = params0.x
rtdiffuse_frame = rtreflection_frame = ssgi_frame = sr_frame
```
**即：一个 32 字节的 `PostProcess` 常量块被四类 GI 复用**，靠宏把同一字段在不同 shader 里取不同名字。本项目若要做 GI，最省事的复制品就是这个「一张 8-DWORD 常量表供所有后处理/ GI 共用」的约定。

**ratiofactor 的由来（`wiRenderer.cpp:15235-15237` [实测]）**：`ratiofactor = 全分辨率分辨率 / 深度层级分辨率`，`downscalefactor = quality_downscalefactor`。cheap 档要把屏幕 UV 乘 ratiofactor 换到层级空间，命中后再除回来（`ssr_raytraceCS.hlsl:333-344`）。

**光线路由（`ssr_raytraceCS.hlsl` [实测]）**：`InitialAdvanceRay:30` → `AdvanceRay:44` → `HierarchicalRaymarch:84`（按 mip 步进，命中进细层）→ `BinarySearch:139` → `ValidateHit:212`（厚度 1.5 与边缘淡出 `:24-25`）。像素级早退由 `NeedReflection`（`stochasticSSRHF.hlsli:25-28`）判定：`roughness <= cutoff && depth > 0`。

**为什么必须做抖动**（`ssr_raytraceCS.hlsl:242-247` [实测]）：`screenJitter = floor(blue_noise(...) * downscalefactor)`，深度与法线**都按 jitter 后的像素取**，这样半分辨率追踪与全分辨率报告一致；注释明说「Hi-Z tracing 与 pass 的深度必须匹配」。

**降噪三段（这是全卷最可复用的模式）**：
1. 空间（`ssr_resolveCS.hlsl:121-155` [实测]）：`sampleCount = resolveSpatialReconstructionCount`，权重 `GetWeight`（`:19`）按法线/粗糙度/NdotV，方差用 `GetWeightedVariance`（`:45`）增量式；**亮度压缩技巧**：采样前 `rgb *= rcp(1+L)`（`:136`），加权平均后再 `*= rcp(1-L)`（`:152`）——为了在大动态范围下让弱信号也参与权重。
2. 时间（`ssr_temporalCS.hlsl:185-198` [实测]）：**双候选重投影**——`prevUVVelocity = uv + velocity` 与 `prevUVReflectionHit = CalculateReprojectionBuffer(uv, reprojectionDepth)`（`:22`）各自采样历史，取与当前均值亮度更接近的那个。这是反射特有的鬼影消除手段（EA SEED DD18 slide 45，注释 :177-178 已标）。
3. 上采样（`ssr_upsampleCS.hlsl:41-49` [实测]）：方差 `> varianceEstimateThreshold(0.015)` 用大半径 8，否则 0；再由粗糙度插值。**半径由方差决定**是它与普通双边的区别。

**两道粗糙度阈值的分工（`wiRenderer.cpp:15235` + `wiRenderPath3D.h:58` [实测]）**：`SSRRoughnessCheap = 0.35` 是**算法内部**的「用 Hi-Z 还是线性步进」分界；`reflectionRoughnessCutoff = 0.6f`（`wiRenderPath3D.h:58`，由 `getReflectionRoughnessCutoff()` 传入，`wiRenderPath3D.cpp:1890`）是**用户可调**的「这个像素还值不值得做反射」分界。落在 `[0.35, 0.6]` 的像素只会走 cheap 档——这正是三档设计的目的：把「中等粗糙度」这类最耗时的区间单独降级。

**对本项目取舍**：**可选但优先**。依赖清单：深度图（有，`SceneDepthBufferFormat=D32_FLOAT`，`RendererConfig.h:18`）、法线+粗糙度（**缺 B 通道粗糙度**，见 §6 G3）、上一帧颜色（需自建历史，项目无）、速度缓冲（**只创建未写入**，见 §6 G2）。它不需要 DXR、不需要 bindless，与项目「单 D3D12 + 固定槽位」的约束兼容。

### 3.2 SSGI：交错多尺度 gather，不是光追〔可选〕

**功能**：屏幕空间单次反弹近似，但**不做逐像素光线步进**，而是把屏幕拆成 16 个交错相位，在 4 个尺度上做加权邻居 gather。

**结构（逐行实测）**：
- 资源（`wiRenderer.cpp:14141-14203`）：`texture_atlas_depth/color` = 1/8 分辨率 R32_FLOAT / R11G11B10_FLOAT、4 mip；`texture_depth_mips`、`texture_normal_mips`、`texture_diffuse_mips` = 1/2 分辨率 4 mip，逐 mip 建 SRV/UAV。
- 反交错（`ssgi_deinterleaveCS.hlsl:28-107`）：一次 dispatch 同时写 2x/4x/8x/16x 四套 atlas 与 regular 目标（`:75-107` 的四层嵌套 `all(GTid.xy % n) == 0`）。
- 宽采样（`CSTYPE_POSTPROCESS_SSGI_WIDE`，`wiRenderer.cpp:14304`）：16x 档 `range=8, spread=2`（`:14319-14320`），8x 档 `range=4, spread=4`（`:14344-14345`）。
- 窄采样（`CSTYPE_POSTPROCESS_SSGI`，`:14358`）：4x 与 1x 档，最终 dispatch `z=16`（`:14404-14409`）。
- 内核（`ssgiCS.hlsl:95-191`）：组内先把 2×2 Gather 展开成 4 像素缓存（`:106-148`），再 `for x in [-range,range]` 双循环按 `spread` 采样并做 `rangespread_rcp2` 权重（`:174-183`），最后按 `interleaved_pixel` 写回（`:190`）。
- 上采样（`ssgi_upsampleCS.hlsl:36`）：**联合双边**（深度+法线作权重），4x→2x→1x 两跳（`wiRenderer.cpp:14501-14530`）。

**对本项目取舍**：**可选**。它比 SSR 简单（无光线步进、无 tile 分派），但需要 4 mip 的深度/法线链 + 16 相位交错，**收益（间接光近似）确实高**。若只做一件屏幕空间 GI，SSGI 的性价比高于 SSR。

### 3.3 RTAO：光追 AO + AMD DNSR〔可选〕

**核心在 `rtaoCS.hlsl:17-94` [实测]**：
- `numthreads(8,4)`，每组 32 线程，`groupIndex` 直接当位号（`:92` `1u << groupIndex`）。
- **每个线程 1 条光线**，方向 = `hemispherepoint_cos(blue_noise, tangent)`（`:50`），范围 `rtao_range`（`:45`）。
- 用 `RAY_FLAG_ACCEPT_FIRST_HIT_AND_END_SEARCH`（`:59`）—— AO 只需要「有没有挡住」。
- 结果压成 `output_tiles[flatTileIdx]` 的 32 位位图（`:93` `InterlockedOr`），**每像素只存 1 bit 可见性**，而不是浮点 AO 值。

**降噪完全复用 AMD FidelityFX DNSR**：`rtao_denoise_tileclassificationCS.hlsl:15-29` 里是 `FFX_DNSR_Shadows_IsFirstFrame / GetBufferDimensions / GetEye` 等回调；`rtao_denoise_filterCS.hlsl:6-7` 用 `min16float2/3` 打包（`#define float16_t2 min16float2`，`:7`）。降噪产物是 `R8_UNORM`（`wiRenderer.cpp:13586-13587`）。

**对本项目取舍**：**可选**。位图表示法值得抄（1 bit/像素，降噪前极省带宽），但 DNSR 是一整套约 3 个 shader + 2 张 history 的移植量。

### 3.4 RTShadow 与屏幕空间阴影：同一份着色器的两个宏变体

**这一点旧版没写清**：`rtshadowCS.hlsl` 全文只有 3 行 [实测]——
```hlsl
#define RTAPI
#define RTSHADOW
#include "screenspaceshadowCS.hlsl"
```
即 **RTShadow 与屏幕空间阴影共用 `screenspaceshadowCS.hlsl`**，靠 `RTAPI`/`RTSHADOW` 宏切换。核心差异在 `:52-59`：非 RTSHADOW 时把射线起点搬到视空间并做固定步数扫描；RTSHADOW 时用 `TraceRayInline`（`:54-84`）。

**遮罩打包（这是全卷最值得抄的小技巧）[实测]**：
- `MAX_RTSHADOWS = 16`（`screenspaceshadowCS.hlsl:9`）
- 每光源 8 bit：`mask_shift = (shadow_index % 4) * 8`、`mask_bucket = shadow_index / 4`（`:298-301`）→ `uint4` 存 16 个光源的可见度
- RTShadow 侧再把 4 个光源压成 **tile 位掩码**（`:309-319`），供降噪判断「本 tile 是否需要重算」

**降噪策略非对称 [实测]**：`rtshadow_denoise_temporalCS.hlsl:104-124` —— 前 4 个光源走完整时空降噪（`ResolverAABB` + 亮度权重 `lumWeight` + **速度补偿** `blendFinal = lerp(blendFinal, 0.2, saturate(velocityBlend/100))`，注释标 "Unreal"）；第 5–16 个光源只做 `lerp(current, previous, blendFinal)` 的简单时域混合。`Postprocess_RTShadow` 里对应 `for (int i = 0; i < 4; ++i)` 的三处循环（`wiRenderer.cpp:15625/15690/15730`）。

**对本项目取舍**：**规模不匹配**（16 光源 × 半分辨率 × 四段降噪）。但 `uint4` 8bit/光源的打包格式与「只对前 N 个光源做完整降噪」的策略，可直接用于项目将来的阴影增强。

### 3.5 RTReflection：唯一使用真 RTPSO 的 pass〔可选〕

**注意默认关闭**：`wiRenderer.cpp:89` 是 `//#define RTREFLECTION_WITH_RAYTRACING_PIPELINE`（**被注释**）。默认走的是 `rtreflectionCS.hlsl` 的内联 `wiRayQuery`；只有打开宏才走 `rtreflectionLIB.hlsl` 的 raygen/closesthit/anyhit/miss 四段（`rtreflectionLIB.hlsl:30 / :73 TraceRay / :90 / :172 / :195`）。`rtreflectionCS.hlsl:140-186` 是内联版里**手写的「closesthit 等价物」**：加载表面 → Unlit 直出 → 否则逐光源调用 `light_directional/point/rect/spot`（`:172-198`），最后 `ApplyLighting`。

**结构**：每像素 1 条 GGX 重要性采样光线（`rtreflectionCS.hlsl:55` `ReflectionDir_GGX`），输出 3 张图（颜色 / `rayDirectionPDF` / `rayLengths`），与 SSR **完全同构**，因此时间解算与上采样直接**复用 SSR 的两个 shader**（`wiRenderer.cpp:14824` 绑 `CSTYPE_POSTPROCESS_SSR_TEMPORAL`、`:14872` 绑 `..._SSR_UPSAMPLE`）。

**对本项目取舍**：可选，且需明确「本项目暂无 DXR」。但 `rtreflectionCS.hlsl:140-186` 这段「光线命中后如何用项目自己的光照公式着色」是光追落地时最难的部分，可直接照抄结构。

### 3.6 RTDiffuse：每像素 2 条余弦光线〔规模不匹配〕

`rtdiffuseCS.hlsl:23-218` [实测]：`numthreads(8,4)`、`samplecount = 2`（`:50`）、方向 `hemispherepoint_cos(blue_noise, tangent)`（`:54`）、`TMax = rtdiffuse_range`（`:58`）。命中后用 `RayCone` 传播锥角（`:62-64`）决定纹理 mip——这是它比 SSR 多出来的东西。降噪三段常数：空间 `resolveSpatialSize = 8.0` / `Count = 4`（`rtdiffuse_spatialCS.hlsl:13-14`）、时间 `temporalResponse = 0.98` / `disocclusionThreshold = 0.89`（`rtdiffuse_temporalCS.hlsl:15-19`）、上采样双边半径 `0..8` 由方差选（`rtdiffuse_upsampleCS.hlsl:12-16`）。

有意思的复用：`rtdiffuseCS.hlsl:204-207` 在 DDGI 可用时**用 DDGI 的 irradiance 覆盖间接漫反射**，`:118-122` 还会叠加 Surfel GI。也就是说 WE 把「光追/世界空间/屏幕空间」三者当可叠加的组件，而非互斥。

**对本项目取舍**：**规模不匹配**。2 spp 的漫反射 GI 必须配完整时空降噪才可用，维护成本 > 收益。

### 3.7 世界空间三族：VXGI / Surfel / DDGI（全部规模不匹配）

| 族 | 持久结构 | 每帧成本来源 | 关键常数（[实测]） |
|---|---|---|---|
| VXGI | 3D 体素纹理 + clipmap + SDF | 场景**重新体素化**（保守光栅化 GS） | `res = 64`（`wiScene.h:212`）、RGBA 压 32bit（`voxelHF.hlsli:16-19`：9+9+9+5 bit，暗部 `pow 1/8` 提精度） |
| Surfel GI | 面元缓冲 + 分箱网格 + 矩/球谐 | 光线预算调度（每帧 ≤100k 条） | `SURFEL_LIVE_TARGET=80000`（`ShaderInterop_SurfelGI.h:23`）、`SPAWN_BUDGET=8192`（`:48`）、`RAY_BUDGET=100000`（`:53`） |
| DDGI | 探针体积 + 八面体深度/颜色 | 探针光追更新 | `grid_dimensions = (32,8,32)`（`wiScene.h:195`）→ 8192 探针；`DDGI_MAX_RAYCOUNT` 为上限 |

**VXGI 的两个可抄点 [实测]**：
1. **颜色打包**（`voxelHF.hlsli:10-34`）：`rgb/10 → saturate → pow(1/8)` 再各 9 bit，alpha 5 bit 用于原子平均。RLS 里执行的是 `atomic 平均` 而非覆盖，因此 alpha 是权重。
2. **clipmap 偏移下的时域**（`vxgi_temporalCS.hlsl:62-89`）：当 `g_xVoxelizer.offsetfromPrevFrame` 非零，只在重叠区间做 `lerp(prev, cur, blend_speed)`（`:84`），不重叠直接取当前（`:89`）。这是「世界空间结构移动时如何重投影」的通用答案。

**Surfel 的两个可抄点 [实测]**：
1. **光线预算**（`surfel_updateCS.hlsl:246-273`）：`rayCountRequest = max_inconsistency * ray_boost`，再按 `SURFEL_RAY_UPDATE_PERIOD_CAP` 做相位摊销（`:241-244`），最后 `rayCount = clamp(..., 0, BUDGET - offset)` 且 `&= 0xFF` 打包进 `raydata` 高 8 位、偏移低 24 位。**同一个 uint 存「从哪开始、要几条」**——极省。
2. **新生面元不炸点**（`surfel_integrateCS.hlsl:109-131`）：新生儿初始辐照度 = 邻域 SH 的**几何权重加权平均**，注释明说 "so it can't pop"。

**DDGI 两个可抄点 [实测]**：
1. **动态光线数**（`ddgi_rayallocationCS.hlsl:47-61`）：`rayCount = saturate(max_inconsistency) * push.rayCount`；探针在视锥外只给 10%（`:52-55`）；首帧给满（`:60-61`）；最后 `align` 到 bucket 并对 `[BUCKET, MAX]` 夹紧（`:57-58`）。
2. **分配表回填**（`:74-80`）：`alloc = probeIndex & 0xFFFFF | (i & 0xFFF) << 20` —— 20 bit 探针 + 12 bit 光线号，一条 uint 全搞定。

**对本项目取舍**：全部**规模不匹配**。它们共同前提是「持久世界空间状态 + 每帧预算调度 + 场景重建检测」，项目当前连帧资源环都没有（见 §6）。列入 09 的「不许抄」清单。

### 3.8 DXR 与自建 BVH：两条实现的分叉点〔可选 / 规模不匹配〕

**分叉在 `wiRenderer.cpp:5702-5813` [实测]**：
```
if (CheckCapability(RAYTRACING)) {
    TLAS 实例数据 CopyBuffer (:5707)      ← CPU 上传的实例表 → GPU
    BLAS: 遍历 scene.meshes[i].BLASes
```

**实例掩码（三种 GI 各自的剔除策略）[实测]**：`wiRenderer.h:38-40` 定义 `shadow = 1<<0`、`reflection = 1<<1`、`diffuse = 1<<2`；使用点 `wiRenderer.cpp:15555`（阴影）、`:14699`（反射）、`:13986`（漫反射，注释说明是为了跳过毛发/草这类 alpha-test 密集几何）。

**软件遍历**：`raytracingHF.hlsli:282 TraceRay_Closest` / `:344 TraceRay_Any`，栈深 32（`:89`），可选 `RAYTRACE_STACK_SHARED` 放 groupshared（`:94`）。

**对本项目取舍**：DXR 部分**可选（远期）**；自建 BVH 与软件遍历**规模不匹配**（项目只有 D3D12，DXR 内建 AS 已足够）。但 `UpdateRaytracingAccelerationStructures` 的**三态 BLAS 策略**（完整/重建/refit）是任何加速结构都要面对的问题，值得记住。

### 3.9 消费侧：光栅着色器如何合成 GI（★ 旧版缺失，施工必读）

这是「GI 做出来了，怎么用」的答案，全部 [实测]。

**A. 在 `objectHF.hlsli:1022-1035`（物体着色，SSR/SSGI/AO）**
```hlsl
if (camera.texture_ssr_index >= 0)  ssr  = tex[ScreenCoord];
    lighting.indirect.specular = lerp(lighting.indirect.specular, ssr.rgb * surface.F, ssr.a);
if (camera.texture_ssgi_index >= 0) surface.ssgi = tex[ScreenCoord].rgb;
if (camera.texture_ao_index >= 0)   surface.occlusion *= tex[ScreenCoord].r;
```
- SSR 用 **alpha 当置信度**做 lerp，且**乘 `surface.F`**（菲涅耳）——不是直接替换。
- SSGI 不直接进 lighting，而是存 `surface.ssgi` 供后续项使用。
- AO **乘法**进 `surface.occlusion`。

**B. 在 `shadingHF.hlsli:125-175`（间接光优先级链）**

| 序 | 条件 | 动作 | 行 |
|---|---|---|---|
| 1 | `!IsGIApplied() && texture_rtdiffuse >= 0` | `lighting.indirect.diffuse = tex[pixel].rgb`（**整替换**），置 GIApplied | `:125-129` |
| 2 | `!IsGIApplied() && OPTION_BIT_SURFELGI_ENABLED` | 有屏幕图就用屏幕图（索引 `[surface.pixel]`）；无则 `SampleSurfelGI(P,N)` 世界空间采样 | `:132-143` |
| 3 | `!IsGIApplied() && texture_vxgi_diffuse >= 0` | 整替换 | `:147-151` |
| 4 | `texture_vxgi_specular >= 0` | `indirect.specular = vxgi.rgb * F + indirect.specular * (1 - vxgi.a)` | `:153-157` |
| 5 | `ddgi.probe_buffer >= 0` | `ddgi_sample_irradiance(...)`，**即使 GI 已应用也调用**，因为要拿 `dominant_lightdir` | `:169-175` |

**三条施工规则从这段代码里读出来**：
1. **漫反射 GI 是互斥的（第一个生效者赢），镜面 GI 是叠加的（按 alpha 混合）**。
2. 屏幕空间 GI 用**像素坐标索引**（`[surface.pixel]`），世界空间 GI 用**位置+法线采样**（`SampleSurfelGI(P,N)`）——两者取用方式不同，不能混用同一采样函数。
3. DDGI 的采样**无条件下进行**，因为它顺带产出主光方向；这意味着 DDGI 一旦接入，就会影响所有着色，包括已被别的 GI 覆盖的像素。

## §5 采样／降噪／上采样三段结构对照（施工选型用）

| 技术 | 每像素采样 | 空间降噪 | 时间降噪 | 需要 velocity | 需要历史缓冲 | 分辨率 |
|---|---|---|---|---|---|---|
| SSR | 1 条 Hi-Z | ✓ 方差+双边 | ✓ 双候选重投影 | ✓ | ✓ 2 张 | 1/2 或 1/4（`wiRenderer.h:484`） |
| SSGI | 0（多尺度 gather） | ✓ 联合双边 | ✗（靠 TAA） | ✗ | ✗（仅 TAA） | 1/2，4 mip |
| RTAO | 1 条 | ✓ DNSR filter | ✓ DNSR temporal | ✓（DNSR 内） | ✓ 2 张 moments | 1/2 |
| RTReflection | 1 条 GGX | ✓ 复用 SSR | ✓ 复用 SSR | ✓ | ✓ 复用 SSR | 1/2 或 1/4 |
| RTDiffuse | 2 条余弦 | ✓ | ✓ | ✓ | ✓ 2 张 | 1/2 或 1/4 |
| RTShadow | 16 条（每光源 1） | ✓ 前 4 光源 | ✓ 前 4 光源 + 其余简单混合 | ✓ | ✓ 2 张 | 1/2 |
| ScreenSpaceShadow | 扫描线 | ✗ | ✗ | ✗ | ✗ | 1/2 |

**结论（施工可当定理用）**：**凡是「每像素 1~2 条随机方向光线」的技术，采样数都不足以直接出图**，必须配「空间 + 时间 + 上采样」三段，且时间解算必须吃 velocity。这是 GI 与普通后处理（bloom/tonemap）的根本区别。
