## §3 逐项详解

### A3-01 全屏三角 VS〔必需〕

**功能**：所有「画全屏」的 PS 类后处理（Outline、Upsample_Bilateral、DownsampleDepthBuffer、体积云上采样）共用这一个 VS，避免为全屏四边形建顶点/索引缓冲。
**结构**：`postprocessVS.hlsl:10-16` 只以 `SV_VERTEXID` 走 `vertexID_create_fullscreen_triangle`，输出 `SV_Position` + `TEXCOORD`；UV 故意溢出到 [0,2]/[0,-1] 以覆盖整个 [-1,1] NDC [实测]。PSO 侧在 `wiRenderer.cpp:1558/1568/1578/1588` 被四处复用 [实测]。
**对本项目的取舍**：**必需**。TooiyumeRender 已有 `Engine/Shader/02_Deferred/FullScreenVS.hlsl`（在 `Engine/CMakeLists.txt:55-61` 的编译列表里），语义等价，可直接复用，不必新写。

### A3-02 Tonemap 8 步流水〔必需〕

**功能**：把 HDR 线性色压到显示参考的 LDR 范围，并在**同一次 dispatch** 内完成曝光、泛光叠加、曲线、色彩分级、抖动、对比度/亮度/饱和度。处于链的第 20 位，是整条管线唯一的 HDR→LDR 分界。
**结构（逐行实测 `tonemapCS.hlsl:95-193`）**：

| 步 | 内容 | 行号 |
|---|---|---|
| 1 | `uv = (DTid.xy+0.5)*resolution_rcp`，再按相机 scissor 提前 return（支持 FSR2 上采样分辨率） | `:97-100` |
| 2 | `unpack_half4` 取出 exposure/brightness/contrast/saturation；`flags` 取低 16 位、`hdr_calibration` 取高 16 位 | `:102-108` |
| 3 | 两张可选畸变图分别加性扰动 UV | `:110-120` |
| 4 | 采样 input（HDR 场景色） | `:124-128` |
| 5 | **曝光**：有 luminance 缓冲时先乘自适应系数，再 `result.rgb *= exposure`（HDR 域） | `:130-136` |
| 6 | **泛光**：采 bloom 的 mip 1.5/3.5/4.5 求平均后相加（仍在 HDR 域） | `:138-147` |
| 7 | **曲线 + OETF**：SRGB 分支内按 ACES / Uchimura / 内建 tonemap 三选一，再 `ApplySRGBCurve_Fast` | `:149-169` |
| 8 | **3D LUT 分级 → 抖动(/64) → contrast/brightness → saturation 矩阵 → 写 UAV** | `:171-193` |

**域划分结论（施工必须遵守）**：曝光与泛光在**曲线之前**（HDR 域）；contrast/brightness/saturation 在**曲线之后**（LDR 域）；dither 夹在 colorgrading 与 contrast 之间 [实测 `:181-185`]。顺序搞反会得到「高光先被压平再叠泛光」的错色。
**结构补充**：Push常量结构 `PushConstantsTonemap` 共 12 个 32-bit（`ShaderInterop_Postprocess.h:136-150`），由 `wiRenderer.cpp:17377-17408` 组装；ACES 用 BakingLab 输入/输出矩阵（`tonemapCS.hlsl:8-45`），Uchimura 用 GT7 分段曲线（`:47-92`）。
**对本项目的取舍**：**必需**。项目 tonemap Pass 是空壳（`Engine/04_Renderer/Renderer/Deferred/DeferredRenderer.cpp:427-431` 只有 PIX 事件），且无 HDR RT、无 sRGB 编码。移植时入参可复用已有 32-bit 根常量，不必新建 CB。

### A3-03 眼适应直方图〔可选〕

**功能**：给 tonemap 提供随时间平滑的曝光系数，模拟人眼明暗适应。
**结构**：Pass1（`luminancePass1CS.hlsl:16-41`）以 32x32 线程块、每块 1024 个 groupshared 桶做对数亮度直方图，`InterlockedAdd` 到全局缓冲的 histogram 区 [实测 `:14-39`]；Pass2（`luminancePass2CS.hlsl:11-41`）用 1024 线程做树形归约，`groupIndex==0` 时算出加权平均并做 `1-exp(-dt*adaptionrate)` 时间插值，写回 luminance/exposure 两项并清空直方图 [实测 `:30-40`]。缓冲布局是 `1 exposure + 1 luminance + 1024 bins`（`wiRenderer.cpp:11340-11347`，偏移常量见 `ShaderInterop_Postprocess.h:19-21`）。
**对本项目的取舍**：**可选**。没有 HDR 自动曝光需求时可先用固定 exposure；但实现代价低（一个 4KB RAW 缓冲 + 两次 dispatch），且 tonemap 的 `buffer_input_luminance` 分支已经预留（`tonemapCS.hlsl:130-134`）。归 **WP8**。

### A3-04 Bloom 分离〔必需〕

**功能**：把 HDR 里的高亮部分单独抽出并降采样，供 tonemap 叠加。
**结构**：目标纹理是 **1/4 分辨率** R11G11B10_FLOAT、mip 数 = `min(5, log2(max(w,h)))`（`wiRenderer.cpp:11418-11423`）[实测]。分离 CS（`bloomseparateCS.hlsl:7-36`）取 4 个对角 tap 平均、乘 exposure（可选乘 luminance 曝光）、`min(color,10)` 上限保护、再减 threshold 并 clamp 到 0 [实测 `:15-33`]。随后 `GenerateMipChain(..., MIPGENFILTER_GAUSSIAN, ...)` 用 wide 高斯生成 mip 链（`wiRenderer.cpp:11510-11513`）。
**对本项目的取舍**：**必需**。tonemap 里已经硬编码了「采 bloom mip 1.5/3.5/4.5 平均」的消费方式（`tonemapCS.hlsl:142-145`），所以 bloom 的**格式与 mip 布局必须与之一致**，否则叠出来偏色。归 **WP8**。

### A3-05 可分离高斯 + mip 链〔必需〕

**功能**：AO 去噪、GUI 背景、bloom mip 链共用的一套横/纵两遍可分离高斯。
**结构**：一个 256 线程（`POSTPROCESS_BLOCKSIZE`=8 但此处 `POSTPROCESS_BLUR_GAUSSIAN_THREADCOUNT`=256，见 `ShaderInterop_Postprocess.h:7`）的一维 tile，`groupshared` 缓存 `CACHE_SIZE = GAUSS_KERNEL/2 + 256 + GAUSS_KERNEL/2`，即宽核 288、普通核 264 个槽（`blur_gaussian_float4CS.hlsl:113-115`）；`params0.xy` 是方向向量，`y==0` 判为横向（`:124`）[实测部分]。C++ 侧横向+纵向各 dispatch 一次，第二遍读 temp 写 output（`wiRenderer.cpp:12703-12711`），`mip_dst < 0` 时先 ClearUAV 那张 temp（`:12639-12643`）[实测]。两档核由宏切换：宽核 `GAUSS_KERNEL = 33`（`:16`，权重表 `:17-51`、偏移 `:52-86`），普通核 `GAUSS_KERNEL = 9`（`:88`，权重 `:89-99`、偏移 `:100-110`，中心权重 0.29118）[实测]；`blur_gaussian_wide_float4CS.hlsl` 全文就是 `#define BLUR_WIDE` + include（2 行）[实测]。
**对本项目的取舍**：**必需**。这是 AO 与 GUI 的基础件，且 `MIPGEN_OPTIONS`（`wiRenderer.h:1147-1153`）里的 `gaussian_temp` 是高斯 mip 链的**必需**输入（`wiRenderer.cpp:10454` 有 `assert(gaussian_temp != nullptr)`），mip 链是逐级 `i → i+1` 调 `Postprocess_Blur_Gaussian`（`:10456-10459`）——即每一级都重跑横+纵两遍，不是简单降采样。归 **WP8**。

### A3-06 双边模糊（深度加权）〔必需〕

**功能**：在高斯基础上乘深度相似度，避免 AO 跨物体边缘渗色。
**结构**：`blur_bilateral_float4CS.hlsl` 全文只有两行——`#define BILATERAL` 后直接 include 高斯体 [实测 `:1-2`]，即**同一份算法、多一个 `groupshared depth_cache`**（`blur_gaussian_float4CS.hlsl:118-120`）；权重阈值由 `depth_threshold` 传入（`wiRenderer.h:575-583`）。SSAO 之后固定以 `depth_threshold=1.2, wide=true` 调一次（`wiRenderer.cpp:12911`）[实测]。
**对本项目的取舍**：**必需**。若 AO 走单通道 R8，用 `_float1` 变体即可；注意 in-place 不安全（SSAO 的调用是 `Postprocess_Blur_Bilateral(output, res.temp, output, ...)`，input 与 output 同一张，靠 temp 中转）[实测]。归 **WP8**。

### A3-07 TAA〔必需〕

**功能**：用历史帧累积亚像素采样，把 jitter 换成抗锯齿并抑制闪烁。
**结构（逐行实测 `temporalaaCS.hlsl:24-120`）**：① 半分辨率无关的 8x8 tile + 1px 边界，把 R/G/B 与线性深度 `pack_half4` 进 `groupshared` [`:27-43`]；② 3x3 邻域求 min/max 作为钳制范围，同时取**最小深度**的偏移量用来选速度 [`:53-76`]；③ `prevUV = clamp_uv_to_scissor(uv + velocity)` [`:78`]；④ 去遮挡fallback：速度>0.01 且前后线性深度差>1 时直接输出当前色 [`:81-90`]；⑤ 历史做 `clamp(history, nMin, nMax)` [`:96`]；⑥ 亚像素修正 `frac(max(|vx|*W,|vy|*H))*0.5` → `blendfactor = saturate(lerp(0.05,0.8,subpixel))`，`prevUV` 出屏则取 1.0 [`:99-105`]；⑦ HDR_CORRECTION 下先 tonemap 再 lerp 再 inverse_tonemap [`:107-117`]。
**数据来源**：`texture_velocity` 与 `texture_depth_history` 都是 bindless 宏（`globals.hlsli:787/789`），指向相机 CB 里的索引；jitter 由 `wiRenderPath3D.cpp:426-430` 取 Halton 序列（`GetFrameCount()%256`）并除以内部分辨率生成，同时懒创建 TAA 资源（`:431-435`）[实测]。
**双缓冲在资源包里**：`TemporalAAResources` 持 `texture_temporal[2]`，`GetCurrent()`/`GetHistory()` 按 `frame%2` 轮转（`wiRenderer.h:888-897`），C++ 每帧 `res.frame++`（`wiRenderer.cpp:17181-17182`），首帧把 input 同时当历史（`:17204-17211`）[实测]。这是 WE 后处理里**唯一改签名之外的隐式状态**。
**对本项目的取舍**：**必需**。项目 `Engine/Shader/04_PostProcess/TAACS.hlsl`（92 行）算法已写好但**不在 CMake 编译列表**（`Engine/CMakeLists.txt` 全文无 TAACS，实测 grep 无命中），且用 `space1`/`b2` 根签名，与单一 `g_CommonRS` 不匹配（`TAACS.hlsl:7-13`）。另外项目虽然创建了 `VelocityBuffer`（`DeferredRenderer.cpp:540`、格式 `RendererConfig.h:19`），但**没有任何着色器写它** [实测：`Engine/Shader` 下只有 TAACS 读 `gVelocity`]，所以 TAA 前必须先补速度写入，否则重投影恒为 0。归 **WP8**（速度写入归 **WP5/WP6**）。

### A3-08 FXAA〔可选〕

**结构**：`fxaaCS.hlsl:6-12` 以 `FXAA_PC=1 / FXAA_HLSL_4 / FXAA_GREEN_AS_LUMA` 引入 `fxaa.hlsli`，质量档 `PRESET 39` [实测]；参数在 `:14-16` 固化为 subpix=0.75、edgeThreshold=0.166、edgeThresholdMin=0.0833；主函数只做一次 `FxaaPixelShader` 调用（`:29`）。
**对本项目的取舍**：**可选**。项目没有 `fxaaPS.hlsl`，实际文件名是 `fxaaCS.hlsl` [实测文件夹，与任务清单里的猜测不符]。若 TAA 落地，FXAA 优先级可降到最低。归 **WP8**。

### A3-09 锐化〔可选〕

**功能**：上采样后补偿细节损失。
**结构**：`sharpenCS.hlsl:15-21` 取 center 与上下左右 5 个 tap，输出 `center + (4*center - top - bottom - left - right) * params0.x` [实测]，**没有**对比度自适应或 clamp，是纯 USM。C++ 侧只传一个 amount（`wiRenderer.cpp:17267`）。

### A3-10 FSR1 EASU/RCAS〔规模不匹配〕

**功能**：AMD FidelityFX Super Resolution 1 的上采样（EASU）+ 锐化（RCAS），用于低分辨率渲染到高分辨率输出。
**结构**：`fsr_upscalingCS.hlsl:14-16` 用 `GatherRed/Green/Blue` 三通道分别供 `FsrEasuF`，常量来自 `fsr.Const0..3`（`:24`）；线程布局是 64 线程、`ARmp8x8` 重映射后一次处理 4 个像素（`:30-41`）[实测]。`fsr_sharpenCS.hlsl:15-25` 同理封装 `FsrRcasF` [实测]。两者都 `#include ffx-fsr/ffx_fsr1.h`。
**对本项目的取舍**：**规模不匹配**。完整 EASU 需要 ffx_fsr1.h（约 700 行内联）与 4 个 32-bit 常量打包，属于「能抄但维护成本高」的档；在 WP8 阶段用双边上采样 + 简单锐化即可达到同样目的。归 **WP8**（仅记录，不施工）。

### A3-11 FSR2 上采样〔规模不匹配〕

**功能**：自带完整 TAA 的上采样器，开启时**顶替** A3-07，并且链首位置也变（`wiRenderPath3D.cpp:2350-2376` 的 if/else 二选一）[实测]。
**结构**：调用方要准备 32 个资源位——`r_input_color_jittered / r_motion_vectors / r_depth / r_exposure / r_reactive_mask / r_reconstructed_previous_nearest_depth / r_dilated_motion_vectors / r_lock_status / r_depth_clip / r_luma_history / r_rcas_input / r_lanczos_lut / r_imgMips …`（`ffx-fsr2/ffx_fsr2_callbacks_hlsl.h:237-263`）[实测节选]。资源包里 `adjusted_color`（R16G16B16A16_UNORM，渲染分辨率）、`exposure`（1x1 R32G32）、`luminance_current`（半分辨率 + 完整 mip 链、逐 mip 建 UAV）、`previous_depth`（R32_UINT）等（`wiRenderer.cpp:17609-17660`）[实测]。
**对本项目的取舍**：**规模不匹配**。引入 FSR2 等于引入第三方 SDK + 32 个回调 + 独立根签名，在架构迁移完成前不明智。归 **WP8**（仅在 RT 语义表里预留「上采样器可替换」的接口位）。

### A3-12 运动模糊 tile 统计〔可选〕

**功能**：先算每个 tile 的速度极值，再按「有无运动/是否一致/是否剧烈」三分类，把主模糊的负载交给 GPU 间接调度。
**结构**：横向 pass（`motionblur_tileMaxVelocity_horizontalCS.hlsl:9-39`）对每个输出像素扫 `MOTIONBLUR_TILESIZE.x`=32 个像素（常量见 `ShaderInterop_Postprocess.h:122`），同时记 max/min 的速度向量 [实测 `:18-35`]；纵向 pass 同理；邻域 pass（`motionblur_neighborhoodMaxVelocityCS.hlsl:15-70`）做 3x3 合并后 `InterlockedAdd` 到 `PostprocessTileStatistics` 的三个 `IndirectDispatchArgs` 计数，并把 tile 索引压进三个 StructuredBuffer [实测 `:50-69`]。C++ 侧该缓冲以 `BUFFER_STRUCTURED | INDIRECT_ARGS` 创建（`wiRenderer.cpp:16496-16500`）。
**对本项目的取舍**：**可选**。GPU 间接调度（`DispatchIndirect`）是这套方案的核心，项目 RHI 已有 `ComputeContext::DispatchIndirect`（`Engine/02_RHI/Command/CommandContext.h:326`）[实测]，技术上可行；但运动模糊本身优先级低于 TAA/AO，建议 WP8 只落地基础版（全屏单核）。归 **WP8**。

### A3-13 运动模糊主 CS 三分支〔可选〕

**功能**：按 tile 分类走三种成本的重建核，避免全屏都付最贵代价。
**结构**：`motionblurCS.hlsl:13-19` 用 `MOTIONBLUR_EARLYEXIT / _CHEAP` 条件编译决定从 t2/t3/t4 读哪个 tile 列表 [实测]；`DepthCmp`/`SpreadCmp`/`SampleWeight` 三个 inline（`:23-42`）实现 Jimenez 2014 的深度+扩散双比较 [实测]；主函数从 tile 反解像素坐标（`:47-54`）、按 scissor 提前退出（`:56-57`），earlyexit 分支直接 `color = input[pixel]`（`:61-62`）[实测]。**采样核**：±7.5 的固定 `range`、步长 2、每轮取两点共 16 次 tap（`:85-122`），采样方向由 `neighborhood_velocity`（带 16px dither 抑制 tile 块状，`:68`）乘 `blue_noise(pixel).x` 决定，cheap 分支则改用 `center_velocity`（`:79-83`）[实测]。最后 `sum /= numSampling` 再 `color.rgb = sum.rgb + (1-sum.w)*center`——**用权重和做能量守恒补偿**（`:123-126`），这是廉价实现里很关键的一步。
**对本项目的取舍**：**可选**。三个变体意味着三份 PSO 与三份常量，迁移时先做 expensive 一版即可。归 **WP8**。

### A3-14 ~ A3-18 景深五段（tile / 邻域 / prepass / main / postfilter / upsample）〔可选〕

**功能**：CoD:AW 式（Jimenez 2014）半分辨率散射景深，支持大小可变的 bokeh 半径。
**结构（管道共 6 段，全部实测行号）**：① tile maxCoC 横/纵两遍（`depthoffield_tileMaxCOC_horizontalCS.hlsl:9`、`_verticalCS.hlsl`）；② 3x3 邻域合并并按 CoC 分派（`depthoffield_neighborhoodMaxCOCCS.hlsl:15-63`，判据 `max_coc<1` → earlyexit、`|max-min|<1` → cheap）[实测 `:47-61`]；③ prepass 在**半分辨率**上算 CoC（`depthoffield_prepassCS.hlsl:33-42`），并在 `backgroundFactor<1` 时做 `ringSampleCount` 次环形预过滤（`:47-61`）[实测]；④ 主模糊按 `maxCoC` 决定 `ringCount = clamp(ceil(sqrt(maxcoc)*DOF_RING_COUNT),1,DOF_RING_COUNT)`（`depthoffield_mainCS.hlsl:50-52`）[实测]；⑤ 9 点中值后滤波（`depthoffield_postfilterCS.hlsl:67-93`，在 `circleOffsets[0..8]` 上先三组 `sort3`，再 `max3/min3` 夹逼后 `sort3` 取 `p[4]`；注释 `:67` 标 [Smith1996]）[实测]；⑥ 合成（`depthoffield_upsampleCS.hlsl:25-34` 用 `backgroundFactor/foregroundFactor/depthDelta` 混回全分辨率）[实测]。
**分辨率**：主链全部在 `/2`（`depthoffield_mainCS.hlsl:33` 的 `tile * DEPTHOFFIELD_TILESIZE / 2`），前置 tile 图是 32px tile（常量 `ShaderInterop_Postprocess.h:125`）。
**对本项目的取舍**：**可选**。六段 + 三变体 + 间接调度，工作量约为 SSAO 的 3 倍；建议 WP8 之后单独立项。归 **WP8**（排期靠后）。

### A3-19 SSAO〔必需〕

**功能**：屏幕空间环境光遮蔽，为间接光提供遮挡系数。
**结构（逐行实测 `ssaoCS.hlsl:16-122`）**：① 8x8 线程 + 1px 边界，把视空间 xy 与 z 分两个 `groupshared` 缓存（`:11-28`）；② 从深度重建**平面法线**：取中心+四邻域共 5 个深度，选「横向/纵向跳变最小」的一对做叉乘（带 6 组 if 分支，`:64-78`）——这是为了解决深度不连续处法线插值错的问题 [实测 `:31-36` 的注释也说明了取舍]；③ 用 `RNG` 生成随机向量投影到切空间构造 TBN（`:82-88`）；④ 半球 Hammersley 采样 `ssao_samplecount` 次，每次把采样点投影回屏幕、比线性深度，并乘 `depth_fix = 1-saturate(|Δd|*0.2)` 抑制远处误判（`:91-118`）；⑤ 输出 `pow(saturate(1-ao), ssao_power)`（`:121`）。
**分辨率与格式**：dispatch 目标是**全分辨率** R8_UNORM（由 output 描述决定，`wiRenderer.cpp:12866-12896`）；资源包里只有一张**半分辨率** R8_UNORM 的 `temp` 供双边模糊中转（`:12841-12851`）[实测]。之后固定调 `Postprocess_Blur_Bilateral(..., 1.2f, wide=true)`（`:12911`）。
**对本项目的取舍**：**必需**。项目 GBuffer 有 Normal（`RendererConfig.h:11` R16G16_FLOAT），意味着可以**跳过深度重建法线**直接读 GBuffer，比 WE 更省；但要注意 WE 这条路是「只有深度也能跑」，可作为禁用 GBuffer 时的后备。归 **WP8**。

### A3-20 HBAO〔可选〕

**功能**：水平角基环境光遮蔽，比半球采样噪声更低。
**结构**：`hbaoCS.hlsl:6-26` 定义 `STEP_SIZE=4 / NUM_STEPS=16 / KERNEL_FALLOFF=2 / TAN_ANGLE_BIAS=0.1 / DEPTH_FIX=0.4`，并据 320 线程（`POSTPROCESS_HBAO_THREADCOUNT`，`ShaderInterop_Postprocess.h:69`）算 `CACHE_SIZE` [实测]；主函数按 `hbao_direction` 是横还是纵决定扫掠方向（`:74-85`），把线性深度反算成视空间 (x,z) 存 `groupshared float2`（`:88-95`），再逐样本累积 `sinS-sinH` 的地平线遮蔽（`:60-67`）[实测]。C++ 侧是**两遍**：横向 pass 把 `t0` 绑成 `getWhite()`（`:12959`）写 `res.temp`（dispatch 为 `(W+319)/320, H`，`:12977-12982`），纵向 pass 再读 `res.temp` 写 `output`（dispatch 为 `W, (H+319)/320`，`:13006-13011`）[实测]——所以着色器里那张 `texture_horizontalpass` 在第一遍是白色，即「单方向累积」的入口约定。最后的双边模糊被**注释掉**（`:13022`）[实测]。
**对本项目的取舍**：**可选**。注意 `:13022` 表明 WE 自己关掉了 HBAO 的模糊，正文的解释应考虑「HBAO 输出本身足够平滑」；迁移时不要照抄一个被注释的调用。归 **WP8**。

### A3-21 MSAO〔规模不匹配〕

**功能**：把 AO 分 4 个相位交错算，再用 4 级深度金字塔逐级 blur+upsample，用较低的每像素采样数换质量。
**结构（六段，实测行号）**：① `msao_preparedepthbuffers1CS.hlsl:1-45` 建 `/2` 与 `/4` 深度图 + `/8`、`/16` 的 16 层 Texture2DArray 交错图（资源见 `wiRenderer.cpp:13050-13060` 的 `array_size=16`）；② `msao_preparedepthbuffers2CS.hlsl:1-35` 继续到 `/8`、`/16`；③ `msaoCS.hlsl:15-27` 用 32x32 或 16x16 的 groupshared 深度缓存（`TILE_DIM`），`:82-145` 主函数做球体侵入判定 `disocclusion = depth*invRange - frontDepth`（`:29-44`）；④ `msao_interleaveCS.hlsl:1-2` 只有一行 `#define INTERLEAVE_RESULT` 后 include 同一份 `msaoCS`，靠 `DTid.xy<<2 | (z&3, z>>2)` 写回交错位置（`msaoCS.hlsl:140-144`）[实测]；⑤ 四次 blur&upsample（`msao_blurupsampleCS.hlsl:156-203`，9x9 patch / 半径 2，注释在 `:164`）；⑥ 通过 `BLEND_WITH_HIGHER_RESOLUTION / COMBINE_LOWER_RESOLUTIONS` 变体逐级合并（C++ 分支 `wiRenderer.cpp:13459-13474`）[实测]。
**对本项目的取舍**：**规模不匹配**。这是 MiniEngine 改写版（`msaoCS.hlsl:1` 明确注明），涉及 16 层数组纹理、6 段管线、4 个变体；在 1080p 上收益不如直接 SSAO+双边。归 **WP8**（仅记录）。

### A3-22 4x4 box 降采样〔必需〕

**功能**：把全分辨率图降到 1/4，是 GUI 背景、太阳径向模糊、SSR 前置的共同基础。

### A3-23 双边上采样〔必需〕

**功能**：把半分辨率效果（体积光、AO、SSGI 等）按深度权重升回全分辨率，避免物体边界糊掉。
**结构**：`upsample_bilateral_float4CS.hlsl:10-19` 声明高低分辨率两张深度图 + 4 个 ±0.5 texel 偏移 [实测]；`:23-36` 用 `USE_PIXELSHADER` 宏同时支持 PS 与 CS 两种形态（PS 入口是 `:25`）[实测]；核心循环 `:50-72` 每轮 `GatherRed` 取 4 个深度、算 `wwww = max(0.001, 1-saturate(|z-z_high|*threshold))`、对 4 个通道分别 `bilinear` 加权，最后 `color /= sum` [实测]。`:60` 有 `1/512` 的 Gather 坐标精度校正（引用 reedbeta 的博客）。
**对本项目的取舍**：**必需**。项目 RHI 的 `ColorBuffer` 支持建 mip（`Engine/04_Renderer/BufferManager.h:27-32` 的 `mipCount`），但**深度缓冲不支持 mip**（`DepthBuffer::Create` 无 mip 参数，`Engine/02_RHI/Resource/DepthBuffer.h:55-58`）[实测]，所以低分辨率深度图得另外建一张 R32_FLOAT，这是移植时必须先解决的资源问题。归 **WP8**（深度 mip 归 **WP4**）。

### A3-24 光束/径向模糊〔可选〕

**功能**：从太阳屏幕位置向外做径向衰减采样，制造体积光/镜头光束。
**结构**：`lightShaftsCS.hlsl:10` 固定 `NUM_SAMPLES=64`；`:15-31` 沿 `uv-lightPos` 方向每次步进 `density/64`，样本乘递减的 `illuminationDecay`（衰减因子 0.945），最后整体乘 `params0.w`（strength）[实测]。参数在 C++ 里硬编码 density=0.65、weight=0.25、decay=0.945（`wiRenderer.cpp:16012-16015`）[实测]。调用前先 `Postprocess_Downsample4x` 降一次（`wiRenderPath3D.cpp:2014`）。
**对本项目的取舍**：**可选**。64 次采样的代价在小分辨率上可接受；真正的问题是它需要「太阳屏幕位置」，这属于 A2 卷的天气/太阳模块。归 **WP8**（依赖 **WP5** 提供 sun 数据）。

### A3-25 色差〔可选〕

### A3-26 CRT 扫描线〔可选〕

### A3-27 描边〔可选〕

**功能**：给选中物体或特定 layer 画轮廓。
**结构**：`outlinePS.hlsl:8-68` 是**像素着色器**，读一张单通道 RT，取 3x3 邻域后套 Sobel 核（K00..K22 在 `:34-42`，中心权重 0.01 在 `:28`），梯度模超 `threshold*middle` 则输出 `outlineColor` [实测 `:63-67`]。C++ 侧走 `PSO_outline` + `device->Draw(3,0,cmd)`（`wiRenderer.cpp:16470-16500`）[实测]，是后处理中**唯一用 PS 而非 CS** 的效果（A3-01 的 VS 在这里被真正使用）。
**对本项目的取舍**：**可选**。若项目已有 GBuffer 的 PrimitiveID/Stencil，用模板或 ID 差异描边比 Sobel 更稳。归 **WP8**。

### A3-28 水下效果〔可选〕

**功能**：相机进入水面以下时，整屏叠加折射扭曲、水体吸收/内散射与 godray。
**结构**：`underwaterCS.hlsl:7-9` 开启 `INTERSECTION_DISTORT/LENS_DISTORT`；`brownConradyDistortion`（`:20-33`）用 K1=0.25、K2=-0.34 的径向畸变；`GodRays`（`:36-…`）以 `atan2` 角度做频率 48/32/20 的多层条纹；尾部（`:184-192`）先乘 `transmittance`、再按 `fogAmount` lerp 到 `fogColor`，最后用 `smoothstep(0,0.025, world_pos.y - ocean_pos.y - 0.01)` 在水面线附近平滑过渡 [实测]。
**对本项目的取舍**：**可选**。强依赖 A5 卷的 OceanComponent 与 A2 卷的雾/散射模型，单独迁移没有意义；但这套「按世界高度做效果淡入」的写法可作为任何「体积边界效果」的模板。归 **WP8**（依赖 **WP6** 的天气数据）。

### A3-29 线性深度（5 级同时写）〔必需〕

**功能**：把硬件深度换成 [0,1] 归一化的线性距离，供 DoF/雾/AO 使用。
**结构**：**一次 dispatch 写 5 张图**：`lineardepthCS.hlsl:16-18` 算 `compute_lineardepth(depth)*z_far_rcp` 写 mip0，随后按 `GTid.x%2/%4/%8/%16` 条件写 mip1..mip4（`:19-34`）[实测]——即 4 级「稀疏写」金字塔，不是逐级过滤，因此低 mip 是**点采样**而非 min/average。C++ 侧对同一张纹理绑 5 个 UAV（`wiRenderer.cpp:18406-18410`）[实测]。消费端通过 `LinearDepthTextureEmulator`（`globals.hlsli:1447-1458`）伪装成普通纹理，可指定 mip 采样（如 `ssaoCS.hlsl:24` 用 `SampleLevel(...,1)`）。
**对本项目的取舍**：**必需**。项目的 `SceneDepthBuffer` 是 D32_FLOAT、无 mip（`RendererConfig.h:18`、`DepthBuffer.h:55-58`），必须另建一张 `R32_FLOAT` 多 mip 颜色目标来承载线性深度；这是 TAA/AO/DoF 的共同前置。归 **WP8**。

### A3-30 深度转法线〔必需〕

**功能**：在没有 GBuffer 法线时（如移动端或纯前向），从深度重建世界空间平面法线。
**结构**：`normalsfromdepthCS.hlsl:13-33` 与 SSAO 同构——8x8+1px 边界、`groupshared tile_XY/tile_Z`、`reconstruct_position` 反投影 [实测]；`:35-39` 的注释完整说明了「为什么选 3 tap 而非 ddx/ddy」；支持读指定 mip（`params0.x` 是 `depth_mip`，`:21`）[实测]；输出是 [0,1] 范围的无符号 float3（`:4-5` 注释）。
**对本项目的取舍**：**必需**（作为无 GBuffer 路径的后备）。但**项目已有 Normal GBuffer**（`RendererConfig.h:11`），主路径应直接读 GBuffer，本项只在 Forward 路径或 GBuffer 不可用时启用。另注意 `reconstruct_position(uv, depth)` 的 3 参重载默认用当前相机投影，若要物体空间法线需显式传矩阵（`ssaoCS.hlsl:25` 就是这么做的）[实测]。归 **WP8**。

### A3-31 Min 深度金字塔 + 重投影深度〔必需〕

**功能**：为 SSR/SSGI/运动模糊提供「按屏幕区域快速求最小深度」的结构，以及「上一帧深度对齐到本帧」的能力。
**结构 A（min 金字塔）**：`depth_pyramidCS.hlsl:14-61`，64 线程/组，`remap_lane_8x8` 后 `GatherRed` 取 4 tap 最小值写 mip0（`:21-23`）；用 `QuadReadAcrossX/Y` 做 2x2 归约写 mip1（`:25-33`）；再用 `groupshared float shared_depths[8][8]` 二次归约写 mip2（`:36-47`），最后由 `groupIndex==0` 合并 4 个角写 mip3（`:51-60`）[实测]。**全部是 min，不插值**。
**结构 B（重投影）**：`depth_reprojectCS.hlsl:12-50`，先用速度求 `uv_prev`（`:19-20`），`GatherRed` 取 4 邻域最小值（`:25-26`），再用**上帧的 inverse_view_projection** 反投影、用**本帧的 view_projection** 正投影回去（`:28-35`），最后 `QuadReadAcross` 归约写 mip1（`:44-49`）[实测]。C++ 入口 `wiRenderer.cpp:19071 ComputeReprojectedDepthPyramid`，`depth_pyramid` 的绑定在 `:19135`。
**对本项目的取舍**：**必需**。这是 A3-22/23 之外第三块「基础 RT」。注意 `ComputeReprojectedDepthPyramid` 需要 `camera.previous_inverse_view_projection`（`depth_reprojectCS.hlsl:28`）——项目相机必须保存上帧矩阵，实测在 `Engine/` 全仓 grep `previous_inverse_view_projection|prev_inverse|previous_.*view` **零命中** [实测]，即上帧矩阵尚未保存，A3-31 与 TAA 的重投影都缺这个输入。归 **WP8**（上帧矩阵归 **WP6**）。

### A3-32 VRS 着色率分类〔规模不匹配〕

**功能**：按速度大小给每个 VRS tile 降着色率，属于性能优化而非画质。
**结构**：`shadingrateclassificationCS.hlsl:16-100`，64 线程/组，`groupshared uint tile_rate` 初值 0xFF（`:19-23`），按 `|velocity|` 的最大分量在 tile 内取最差（`:32-40`）[实测节选]；C++ 侧用 `WriteShadingRateValue` 把枚举转成硬件码并写入 `ShadingRateClassification` 结构（`wiRenderer.cpp:11530-11545`）[实测]。调用点在 `wiRenderPath3D.cpp:1093-1100`，且要求 `VARIABLE_RATE_SHADING_TIER2` 能力 [实测]。
**对本项目的取舍**：**规模不匹配**。项目 RHI **完全没有** VRS 相关封装（`Engine/` 全仓 grep `variable.?rate|shading.?rate|VRS` 零命中；现有的能力查询只有 `D3D12_OPTIONS5` 的 `RaytracingTier`，`GraphicsCore.cpp:174-190`）[实测]，且 TIER2 有硬件门槛。归 **WP8**（仅记录，不施工）。

### A3-33 大气透视后处理〔可选〕

**功能**：在不透明几何之后，按逐像素深度叠加空气透视（远处发灰/偏蓝）。
**结构**：`aerialPerspectiveCS.hlsl` 有**两个 `main`**，由 `AERIALPERSPECTIVE_CAPTURE` 宏切换 [实测 `:93` 与 `:137`]：
- **采集分支**（`:95-136`）：目标是 `RWTexture2DArray`，`uv` 经 `uv_to_cubemap(uv, DTid.z)` 变成方向 N，按 cube slice 取对应相机（`GetCameraIndexed(DTid.z)`，`:123`），结果**合成到已有内容上**：`composite.rgb*(1-a) + result.rgb`（`:135`）——用于给反射相机/立方体贴图预先烘焙大气。
- **屏幕分支**（`:139-170`）：读 `texture_depth[DTid.xy]`，跳过天空盒（`depth==0` 时写 0 并 return，`:146-150`），用 `inverse_view_projection` 还原方向（`:152-160`），最终只写 `float4(luminance, transmittance)`（`:166-169`）——**它输出的是「雾层本身」而不是合成后的图**，由后续 pass 叠加。
两条路都调同一个 `RenderAerialPerspective(...)`（`:130`/`:164`），最后一个 bool 参数区分是否采集模式。调用点在 `wiRenderPath3D.cpp:1644`（主相机）与 `:1237`（反射相机），两者都在 `QUEUE_COMPUTE` 上异步执行（`:1605-1649`）[实测]。
**对本项目的取舍**：**可选**。它属于 A2 卷大气模型的「应用端」，若 A2 未落地则无意义。归 **WP8**（依赖 **WP6/WP7** 的天空数据）。

### A3-34 自定义后处理钩子〔可选〕

**功能**：让宿主在 tonemap 前/后插入任意 CS（用户外挂 shader）。
**结构**：`wiRenderer.cpp:18706-18760`——`BindCommonResources(cmd)` 后按 output 尺寸算 dispatch，参数只有 `params0/params1` 两个 float4，输入固定 t0、输出固定 u0 [实测]。调用侧遍历 `custom_post_processes`，按 `Stage::BeforeTonemap / AfterTonemap` 分流（`wiRenderPath3D.cpp:2398-2415` 与 `:2498-2514`）[实测]。
**对本项目的取舍**：**可选**。这是 WE 里唯一「不写死效果」的扩展点，适合作为 WP8 的接口雏形——但注意它**没有版本/校验**，迁进静态注册表时要补。归 **WP1/WP8**。

### A3-35 GUI 背景模糊链〔必需〕

**功能**：给 GUI 背板提供「磨砂玻璃」底图。
**结构**：`wiRenderPath3D.cpp:2546-2556` 三行——`Downsample4x(rt_read → rtGUIBlurredBackground[0], hdrToSRGB)`、`Downsample4x([0] → [2])`、`Blur_Gaussian([2] → [1], temp=[2], wide=true)` [实测]。**这是 R3 特例**：高斯调用里 input 与 output 同为 `[2]`，靠 `[1]` 作 temp 实现逻辑 in-place（因为高斯是横纵两遍、第二遍读 temp 写 output）。
**对本项目的取舍**：**必需**（若要做 GUI 毛玻璃）。注意 `hdrToSRGB` 的 /9 校正（见 A3-22）在这里被使用，迁移时要一并决定「GUI 底图取 HDR 还是 LDR」。归 **WP8**。

## §5 ping-pong 规则（三条）

| # | 规则 | 证据 |
|---|---|---|
| R1 | 每个效果显式收 `src` 与 `dst`，由调用方 `std::swap(rt_read, rt_write)` | `wiRenderPath3D.cpp:2342-2343` 初始化、每个效果块末尾 swap（如 `:2520`、`:2527`） |
| R2 | 有旁路产物（GUI 背景、FSR 中间图、太阳径向模糊）的效果**不参与** ping-pong，直接写自己的目标 | `:2551-2553`、`:2014-2018`、`:2560` |
| R3 | 效果级 in-place **不安全**（CS 读邻居是算法竞态，barrier 救不了）；唯一允许的是 GUI 高斯靠 temp 中转的「逻辑 in-place」 | `:2553`（input==output==[2]、temp=[1]）；对照 SSAO 的 `Postprocess_Blur_Bilateral(output, res.temp, output, ...)`（`wiRenderer.cpp:12911`） |

补充（实测）：链首还有一次 **aliasing barrier**（`wiRenderPath3D.cpp:2346` 把 rtPrimitiveID 与 rtPostprocess 别名化），说明 rtPostprocess 是复用其他 RT 的显存，不是独立分配。

**对本项目的含义**：后处理框架必须在**接口层**强制 `src != dst`（编译期/断言均可），in-place 只能作为显式标注的特例。归 **WP8**。

## §6 检索提示

- 「本项目加后处理第一步做什么」→ 先看 §8 的 G1–G3，再看 §4 表的前 3 行。
- 「某个效果的参数语义」→ 读 `wiRenderer.h` 里 `Postprocess_*` 的声明，参数顺序即语义顺序（如 `wiRenderer.h:575-583` 的 bilateral 参数）。
- 「某个效果是否 temporal」→ 看签名有没有 velocity/prev 帧，或资源包里有没有双缓冲（唯一特例是 `TemporalAAResources`，`wiRenderer.h:888-897`）。
- 「某个效果跑在什么分辨率」→ 看 `Create*Resources` 里的 `resolution.x / N`（如 bloom 是 `/4`、SSAO temp 是 `/2`、DoF 是 `/2`）。
- 「某个效果用什么格式」→ 看 `Create*Resources` 的 `desc.format`（这张表比着色器里的声明可靠，因为着色器用 bindless）。
